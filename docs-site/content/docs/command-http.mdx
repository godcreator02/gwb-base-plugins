# gwb-command-http

> **搁置（2026-09-14）**：这个入口的班由 [gwb-mcp](/docs/mcp) 复位接回——default home
> 已卸载本插件，代码留仓、registry 留 0.2.2 当**逃生门**（MCP 门坏到没救时手工装回，就
> 有一条无会话的 curl 道）。判据见轨迹卡「MCP 复位」。以下为在职期间的现状记录，钉码
> 随源码保留。

把 [`ctx.gwbCommands`](/docs/commands) 那份命令注册表开成一个**本机无状态 JSON 接口**。
2026-09-13 接 mcp 插件的班（mcp 搁置、default 卸载，判据见轨迹卡「HTTP 门接班」）——端口
策略与 runtime.json 那一项两样纪律原样继承，信道从会话态的 MCP 换成无会话的裸 HTTP；
token 鉴权没跟过来（0.2 摘除，判据见下文「不设鉴权」）。同日正名：`http` 是拿协议当名字，
按 node-cli / py-cli 那条「对象-载体」语法改成**命令的 HTTP 口**（更名卡见轨迹区）。

包名 `@godcreator02/gwb-command-http`，无界面、**零运行时依赖**（mcp 那串 SDK 解包
4.3MB，随 mcp 搁置退役）。`inject: ['gwbCommands', 'gwbSettings']`——settings 是硬依赖，
端口从它来；data 件 0.2 起退役（token 落盘是它唯一的用途）。

## 怎么连

起来之后日志里有一行：

```
[I] gwb-command-http 命令 HTTP 口就绪（default home）：http://127.0.0.1:2870——无鉴权，绑 127.0.0.1 本机自用
```

另一条出口是命令 `command-http.info`——url + 两条 curl 例句一起回。日常就两条路：

```
curl -s http://127.0.0.1:2870/surface
curl -s -X POST http://127.0.0.1:2870/run -d '{"command":"skill.list"}'
```

台没起时 curl 直接 connection refused，一眼见骨——把台起起来再调，没有重连这个概念。

## 不设鉴权

mcp 时代那层 Bearer token（0.1）随门换代摘除。判据三条：**口只绑 127.0.0.1**、服务本机，
本机进程本就同权，token 挡不住任何本机上的东西；**token 跟着内核重启换新**，agent 侧的
配置变成一桩要反复伺候的差事——换了门当天就两次逼着人翻日志捞 token；`command-http.info`
与日志里也不再示 token。旧 home 数据目录里遗留的 `token.json` 不再读、不再写，留着无害。

## 两条路由

{/* ref file="../plugins/command-http/src/index.ts" lines="201-233" */}

**GET /surface 现拼**：命令注册表 + 说明书清单 + 自报 home 名 + instructions（入口上的
纪律）一条回执全带——它是 agent 的发现面，热挂上来的插件下一次 GET 就在。**POST /run
按名调**：body `{"command": 名字, "args": {...}}`，参数形状在命令描述里、命令自己校验；
命令自身失败回 `{"ok":false,…}`、HTTP 仍是 200——那是业务回执，不是入口的错误。

## 全量太贵，于是有过滤

全量回执实测约八千 token（72 条命令占七成），且随插件数线性涨。四个查询参数，全部
服务端筛、生效条件在回执 `filter` 那格自证：

| 参数 | 筛什么 | 例 |
| --- | --- | --- |
| `?plugin=<插件名>` | 只留那个插件登记的（commands 与 skills 一起筛） | `?plugin=gwb-plugin-manager`（13 条，约 800 tok） |
| `?prefix=<前缀>` | 命令名前缀 | `?prefix=skill.` |
| `?q=<词>` | 名字或描述里找子串，不分大小写 | `?q=install` |
| `?slim=true` | 只回 名字+插件 的索引行 | 72 条约五百 tok |

用法节奏写进了 instructions：**陌生 home 全量一次就够，此后定向取，反复全量是坏味道**。
分页（page/size）刻意不做——这个量级按组筛比翻页好用。

## 没有会话

每个请求自包含。本插件热重挂（比如 update-all 升到自己）或工作台重启，在途那一发会断，
**下一个请求自动就好**——重发即可。这正是接班的理由：mcp 那条会话态信道断一次要人敲
`/mcp`，而这台工作台的插件以分钟级热重挂为节拍，会话的寿命跟不上插件的节拍。

门上只剩方法不对 405 一道拦法，方法与路径的判断在各路由手里——就是上面那段 `handle`；
401 / 503 两段守卫是 token 时代的，随鉴权一起摘了。

## default 的端口是契约，不是首选

{/* ref file="../plugins/command-http/src/endpoint.ts" lines="52-66" */}

**`default` 认死 2870，被占就不开这个入口。** 日常车道认死这个基址，退让就是把它送给先
起来占住 2870 的那台测试 home——那台会老老实实收下请求，命令面、数据、说明书全是另一
套，两头都不报错。其它 home 缺省系统随机端口（多 home 同开是常态，没有哪个串是它的
契约），显式给了端口、被占才退让。

## 绑成那一刻补 runtime.json 的 `command-http` 项

{/* ref file="../plugins/command-http/src/runtime.ts" lines="39-64" */}

内核开机整份重写 `pid` / `startedAt` / `appDir` / `cdp` 四项，本插件绑成之后**读改写**
补自己那一项。项名随插件短名走：mcp 那项叫 `mcp`，这个插件叫 `command-http`；旧项
（`mcp`、一天的 `http`）属于「认不得的字段」，原样保留不碰。没绑成不写（写一项假的比
不写坏得多）、写失败不影响这个入口、进程退了不删——验活是读的人的事（核 pid 还在、
且那个 pid 真持着那个端口）。

## instructions：入口的纪律随 /surface 发

{/* ref file="../plugins/command-http/instructions.md" */}

mcp 那份 instructions（怎么干活 + agent 自改的规矩：哪些改动不用问、哪些先问人）由本插件
接着养。差别只在送法：MCP 是 initialize 时白送进上下文，这边是 `/surface` 回执里带
一份——agent 的第一份 GET 就是它的「连上先读」，而 GET 是现拼的，改一个字发一版就跟着
走，没有「清单是连接时快照」那回事。

## 说明书清单在这，正文走 /run

清单进 `/surface` 的 `skills` 项；正文不另开路由——`POST /run` 调
`skill.list` / `skill.read`（skills 插件登记的命令，参数形状看它自己的描述）。skills 插件
不在时入口照开，清单那一项是空表。命令名跟注册表一致（点分风格）——MCP 桥当年把
`skill.read` 改写成下划线工具名，那层改写随 mcp 一起退场了。
