# gwb-commands

**没有这个件，界面调不到任何 node 侧的能力**——内核一条命令名都不认识，`gwb:command`
收到什么就原样派给 `ctx.gwbCommands`；没装这个件就是一句「认不出」。

包名 `@godcreator02/gwb-commands`，服务 `ctx.gwbCommands`。产物 4 个文件、零运行时依赖。

## 怎么用

**登记一条命令**（在你的件里）：

```ts
export const inject = ['gwbCommands']

export function apply(ctx: GwbContext) {
  ctx.effect(() =>
    ctx.gwbCommands.register(
      { name: 'mine.hello', description: '回一句话', plugin: 'mine' },
      (args) => ({ got: args }),
    ),
  )
}
```

`register` 回的是注销函数，**用 `ctx.effect` 包着**——本件卸载时注册自动回收。

`plugin` 这个字段由注册方自带，不从 `ctx.name` 读：那是 cordis 的追踪属性，没 `inject`
就读会抛。

**从界面调**（在你的 client 束里）：

```js
args.host.call('mine.hello', { n: 7 }).then((res) => {
  // { ok: true, data: { got: { n: 7 } } }
})
```

整条链路是：界面 → IPC（`gwb:command`）→ 主进程里的 `ctx.gwbCommands` → 你的 handler
→ 原路回。件与桥同一个进程，中间没有第三跳。

## 回执的形状

handler **自己判过成败就原样透传**，没判的一律算成了：

- 回 `{ ok: false, error: '...' }` → 原样交给调用方
- 回 `42` → 包成 `{ ok: true, data: 42 }`
- 抛异常 → `{ ok: false, error: '<异常文本>' }`，不炸到调用方
- 命令没注册 → `{ ok: false, error: '没有这条命令：xxx' }`

## 描述里必须写参数形状

`description` 不是给人看的简介，是**agent 只看它就得知道参数怎么给**的那一行。经
[gwb-mcp](/docs/mcp) 出去的每条命令，agent 手上除了名字就只有这一句——参数形状不在
这儿，它就只能猜，猜错了回的是一句跟形状无关的报错。

所以写法定死：带参数的把形状写出来（`{ entryId }`、`{ pkg, spec? }`、
`{ args?: string[], cwd?: string }` 这种），无参数的写「无参数」。

## 标顶层：登记时就定了

登记时多标一个 `top: true`，这条命令就会被 [gwb-mcp](/docs/mcp) 渲染成顶层工具——agent
一连上就在工具清单里看得见的那种。总线对这个字段只做一件事：原样带进 `list()`，缺省
`false`；桥看到 `true` 就渲染，**没有运行时名单、没有「批准」这一步**。

{/* ref file="../plugins/commands/src/registry.ts" lines="9-13" */}

**顶层是开发时定的，不是装进软件之后批的。** 顶层工具清单在 agent 连着的时候是一份快照，
而且每枚工具的 schema 都只是 `args: unknown`，比 `gwb_command_run` 只多一个名字——顶层是
稀缺位，只留给「连上第一件就要看」的命令（说明书那两条）。于是「同意」只剩一条纪律：
**agent 写件时给命令标 `top: true` 之前，先停下来问人**——这句写进了 mcp 的
instructions，每个连上来的 agent 都会读到。

## 三条判据

写进测试的那三条，各自的理由见[撞过的墙](/docs/walls)：

1. **撞名后来者赢，但要告警** —— 静默改派的话两边谁都不报错
2. **注销只收自己那份** —— 撞名后先卸的不该带走接手的
3. **handler 抛出来不炸调用方** —— 它可能是界面上的一次点击
