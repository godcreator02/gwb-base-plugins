**本页回答**：数据插件有哪些功能；插件和插件管理经哪些接口用它，各属于哪条接缝；它依赖什么、缺了会怎样；哪些事常被以为归它、其实不归它。包名 `@godcreator/gwb-data`，源码目录 `plugins/data/src`，入口文件 `index.ts`。

插件要在磁盘上存自己的东西（JSON 文档、图片、日志），把 `gwbData` 写进 `inject`，拿到一个只属于自己那条条目的目录，不用自己拼路径、不用自己写原子写入。数据插件没有命令、没有说明书。

<Diagram name="data-layout" title="数据插件按条目 id 给每条条目一个数据目录">
- 同一个包 `@scope/gwb-notes` 在 `cordis.yml` 里有两条条目 `home:notes` 与 `home:notes-work`，各得一个目录 `<home>/data/notes/`、`<home>/data/notes-work/`
- 插件经服务 `ctx.gwbData` 的 `dir`、`readDoc(doc)`、`writeDoc(doc, value)` 读写；数据插件从调用方条目算出目录，先核对 `.owner.json` 里记的包名再读写
- 每份文档是目录里的 `<文档名>.json`；`writeDoc` 先写同目录的临时文件再改名覆盖，`readDoc` 没有这份或解析不了都回 `undefined`
</Diagram>

## 功能

- **每条条目一个数据目录**：`<home>/data/<条目 id 的末段>/`；同一个包在 `cordis.yml` 里配两条条目，各有一个目录
- **认得出调用方**：插件不用报自己是谁，服务从调用方的上下文里认出条目；插件没法读写别的条目的目录
- **按名字整份读写 JSON 文档**：一份文档是目录里的 `<文档名>.json`；没有这份文档、或文件解析不了，读出来都是 `undefined`，解析不了时另写一条 warn
- **写入是原子的**：先写同目录的临时文件（文件名带随机后缀），再改名覆盖目标；同一份文档的多次写入按发起顺序一次一个，后发起的那次留在文件里；写失败时删掉临时文件、写一条 error 日志，异常照样抛给调用方
- **目录记着归哪个包**：目录第一次被访问时写下 `.owner.json`，之后包名对不上的一律拒绝；插件管理经 `owners`、`transferOwner` 列出和改写归属
- **条目没写 id 时提醒**：条目 id 是 loader 生成的 8 位随机十六进制时，写一条 warn（这种 id 每次启动都变，数据每次启动都会新建一份），每条条目只写一次
- **名字写错当场报错**：文档名与条目 id 的每一段都必须是 kebab-case，条目 id 超过两段抛错

## 接口

每条接缝上交换什么、各方保证什么，写在接缝页；本节只列数据插件提供了哪些接口、定义在哪里。

| 接口 | 做什么 | 接缝 |
| --- | --- | --- |
| 服务 `ctx.gwbData` 的 `dir`、`readDoc(doc)`、`writeDoc(doc, value)` | 调用方条目的数据目录；按文档名读、整份替换写；类型 `GwbDataApi` 由本包导出 | [6 数据](/docs/seams/data) |
| 服务 `ctx.gwbData` 的 `owners()`、`transferOwner(id, pkg)` | 列出各数据目录归哪个包；把一个目录改归另一个包（包改了名、要接着用旧数据时） | [7 数据归属](/docs/seams/owners) |
| 目录 `<home>/data/<条目 id 的末段>/` | 目录名由调用方的条目 id 算出：取末段，`home:hello` 得 `hello` | [8 条目身份](/docs/seams/entry-identity) |
| 文件 `<数据目录>/.owner.json` | `{ "pkg": "<包名>" }`，记这个目录归哪个包 | [7 数据归属](/docs/seams/owners) |
| 文件 `<数据目录>/<文档名>.json` | 一份文档，两格缩进的 JSON | [6 数据](/docs/seams/data) |

用它的插件写 `export const inject = ['gwbData']`，之后：

```ts
const layout = await ctx.gwbData.readDoc('layout') // 第一次运行时是 undefined，调用方自己给默认值
await ctx.gwbData.writeDoc('layout', layout ?? { panes: [] })
```

**`dir` 是同步的 getter**：插件拿到路径就可能自己往里写，所以归属检查在取 `dir` 时同步做完；检查过的目录记在内存里，不重复读磁盘。

**同一个条目 id、不同的包**：目录名只取条目 id 的末段，而插件管理生成默认 id 时去掉了 scope，`@a/gwb-foo` 与 `@b/foo` 都叫 `foo`。条目删掉后数据留在磁盘上，下一个拿到这个 id 的包读到的会是前一个包的数据，所以目录里记着包名，对不上就拒绝，错误里写明两种处理办法：给条目换个 id，或确认是同一个插件改了包名、走 `plugin-manager.transfer-owner`。`.owner.json` 认不出来时抛错，不当成没有归属。

## 依赖

| 依赖 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- |
| 内核服务 `gwbKernel` 的 `dataDir`（内核仓 gwb-kernel；不写进 `inject`，经 `src/vocab.ts` 里的 `requireKernel` 取） | 算出 `<home>/data` | 构造时抛错「ctx.gwbKernel 不在」，插件加载失败 |
| cordis 的 `Service`（peer，`^4.0.0-rc.10`） | 提供服务；方法里的 `this.ctx` 是调用方的上下文 | 无法加载；必须和内核用同一份 cordis，两份的 `instanceof` 对不上 |
| loader 在调用方上下文上加的 `fiber.entry`（`id`、`options.name`） | 认出调用方的条目 id 与包名 | 不是经 `cordis.yml` 加载的插件调用时抛错「取不到调用方的身份」 |
| 词汇表包 `@godcreator/gwb-plugin-api`（dev，`^0.4.1`） | `GwbContext`、`GwbKernelApi` 的类型 | 只在编译时用 |
| 内核包 `@godcreator/gwb-kernel-desktop`（peer，`^0.4.1`） | — | — |
| 文件系统 | 建目录、读写文档与 `.owner.json` | 读失败当作没有这份文档；写失败把异常抛给调用方 |

数据插件和[设置插件](/docs/settings)用同一个办法从条目 id 算名字：两边各有一份十几行的算法（`entryDirName` 与 `entrySection`），必须给出同一个答案，改一处就要改另一处。

## 不做的事

- **不管目录里的其他文件**：`dir` 交出去后，插件在里面存什么都行，数据插件不检查
- **不是安全边界**：插件和数据插件在同一个进程里，有完整的 Node 权限，能写任何路径；名字校验只防写错
- **不做局部更新与事务**：`writeDoc` 整份替换；同一份文档同时写两次，后发起的那次覆盖先发起的，不会合并
- **不删数据**：条目删掉后目录留在磁盘上，谁来清理不归数据插件
- **没有命令**：页面与 agent 看不到数据目录；要给外面看，由插件自己登记命令
- **不管设置**：设置项在 [gwb-settings](/docs/settings)，写在 `<home>/settings.json`，不在数据目录里
- **不按包名分目录**：同一个包的两条条目是两份独立的实例，按包名分会共用一个目录、互相覆盖
