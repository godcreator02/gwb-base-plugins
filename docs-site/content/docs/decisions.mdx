# 定过的事

按 `gwb-decide` 的规矩：选型推完交人拍板，拍板之后记进这页。只记关系**件**的选型；
关系**规则**的（命名、依赖判据、内核该不该做某事）归内核仓的站。

## 2026-09-08：状态格机制整个下架，件各画各的窗格

**定**：`gwb-status` 与整条状态格机制（`registerCell` / `mountCell` / `status.cells` /
`gwb-status:cells` 事件）删除——**要给人看的件，自己画自己的窗格**。

**经过**（三步都没离开当天的工作区，前两步的判词各留一句）：先走声明式（0.0.1——格子
内容由消费件报数据+档位、渲染器只有状态件一份，理由是数据起源于 node 半、渲染统一不靠
自觉、headless 件不必背浏览器构建线）；压测旧侧栏那张复杂状态卡后改判自绘（0.0.4——
卡框归状态件、身体由消费件 `mountCell` 自绘，判词「通用格式的设计越来越复杂」）；随后
整个下架。

**下架的依据**：格子的价值本在「多个件的健康一屏看全」，可这条线至今只有两三个件、
且各有各的窗格——聚合的需求从没真到过（准入第二关）。而每颗格子要 node 半注册 +
client 半自绘 + 一套取数轮询，比一扇窗格多一层服务、一层事件、一条软契约
（`mountCell` 的形状）。件各画各的窗格之后这套全没了；哪天真要「一屏看全」，再做一个
聚合窗格的件也不迟——加回来永远比拿掉容易。

**收尾**：registry 上的 0.0.1–0.0.4 佚版留档不撤（照 `gwb-market` 先例）；hello 去格发
0.0.20（`hello.probe` / `hello.bump` 两条命令保留——探针数据口与格子无关）；devkit 的
「插件源」格改开一扇普通窗格；gwb-windows-backup 撤格留窗格。

## 2026-09-08：市场并入插件管理，`gwb-market` 下架

**定**：装机面只剩一个窗格——`gwb-plugins` 的「插件」格分**「已装」与「可装」两段**；
`gwb-market` 整个删除（0.0.1 佚版留在 registry 上，不做 unpublish），白名单清单
（`catalog.ts`）跟着界面搬进 gwb-plugins。顺手补上查新版本：`plugins.outdated`（跑
`pnpm outdated --json`，退出码 1 是「有过期」不是失败）与 `plugins.update`
（`pnpm add <pkg>@latest`，**不建条目**——升级与装第二条条目是两回事），界面上
「有新版」徽标 + 「更新」按钮。

**依据**：市场件本身只有一格窗格、一条命令都没有，装的动作本来就走 `plugins.install`
——「发现」与「管理」拆成两个件，人却要在两格里来回跳才能「看一眼装了什么、有什么可装」。
合并后少维护一个件、少一条软契约，边界并不因此变糊：清单是数据、管理是服务，本就同属
「装机」这一件事。

**记两笔边界**：
- **显示有新版 ≠ 自动升级**。内核那边「不做自动升级」钉的是「装过了就不再动它」；这儿
  升级的每一下都是人点的按钮，判据不受触动
- 「可装」的白名单判据原样保留（registry 搜索接口是个坟场，判据见 `catalog.ts` 头注）；
  将来推荐清单若从 gwb-catalog 来，换的只是清单的数据来源，不是这一段的结构

## 2026-09-08 多桌面：试了一版保活，同日撤回，先做布局保存

**定**：多桌面（类 Windows 虚拟桌面）第一波**不做**——做到 0.0.14（一张桌面一口井、
井常驻保活、切走不拆）后撤回，改为先把「布局落盘」做小做稳：一口井自动存档，人可起名
存布局、点开哪套铺哪套。母仓「工作区 tab」草案的「切换即销毁重建」也**一并搁置**——
两种切换语义都没进第一波。

**为什么撤**：实机切桌面出了「无响应 / 疑似后面的桌面覆盖前面的」的现场（用户亲历）；
受控复测（DOM 打标记、切走再切回）状态是保留的、复现不出，根因没钉死。连同「步子迈得
太大」一起，拍板人叫停。

**留下的**：gwbData 注入、`shell.layout.get/save` 两条命令、400ms 防抖整档保存、
「布局没存上」告警、dispose 前 flush——这些本来就是路线图第四刀「布局落盘」的东西，
不是多桌面的，0.0.15 起它们继续活着。

**重做的门槛**：先把那桩切换悬案钉死（保活还是销毁重建、井间状态与 `pane.instance`
的唯一性范围），再动手。多桌面时代的 v1 档按「认不出」整档当没有，不用清退。

## 2026-09-08（同日再改判）：「可装」的白名单退场，改 registry 检索

**改判**：上一条里「白名单判据原样保留」作废。可装段不再认手工清单，改为
`plugins.search` 查 **npm registry 标准检索协议**（`/-/v1/search`），列出
`@godcreator02` scope 下 `gwb-` 前缀的全部。拍板人的原话：「不要主动注册了，直接找
以 gwb- 开头的插件都列进来就行了」「market 就是去 npm 找 @godcreator02，应该做到
解耦，Verdaccio 是接管了这个而已」。

**解耦那条是钉死的**：代码里不出现任何具体源的名字与地址——基址从 pnpm 配置解析
（`@godcreator02:registry`，退 `registry`，再退 npm 官方），装从哪来、搜就到哪去。
白名单那条「坟场」判据（registry 上混着一整条废弃线）因此转成**已接受的后果**：
废弃线的 `gwb-api`/`gwb-cli`/`gwb-build`/`gwb-home` 等与共享包、词汇表包会一并列在
可装段里。判据没有消失，是换了个形态——从「清单拦着」变成「行上摆着 description，
装错了一眼能看出来」。

**实现落点**：检索住在 gwb-plugins 的 node 半（宿主进程 fetch，10 秒超时，不抛）；
基址解析一次缓存到底；registry 上这条线就几十个包，检索一把抓全量、搜索框纯本地筛。
