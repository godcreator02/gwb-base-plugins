**本页回答**：这个仓怎么构建；`pnpm check` 查什么、什么时候它的构建产物检查才真的运行；只有 node 部分的插件怎么不启动工作台验证；发版时八个包按什么顺序给。

## 构建

在仓根：

```powershell
pnpm install
pnpm build
```

`pnpm build` 是 `pnpm -r build`，每个插件输出到自己的 `dist/`：七个插件用 `tsc -p tsconfig.json`，MCP 插件先用 `build.ts`（esbuild）打包出 `dist/index.js`，再用 `tsc --emitDeclarationOnly` 输出类型声明。pnpm 工作区是 `plugins/*`、`packages/*` 与 `docs-site`；`packages/` 下的 `shared-react`、`tokens` 只剩旧的构建产物、没有 `package.json`，不是在用的包。

## 提交前的检查

```powershell
pnpm check
```

依次是类型检查（仓根 `tsc --noEmit`，再对每个包 `pnpm -r typecheck`）、`oxlint`（带类型信息，警告也算失败）、`vitest`（`plugins/*/tests` 与 `packages/*/tests`）。测试有两类：

- **单元测试**：纯逻辑，比如命令表、路径与名字规则、MCP 的 `index`/`search` 返回、设置的解析顺序
- **构建产物检查**（`tests/artifact.test.ts`）：相对 import 带 `.js`、包名 import 只有 node 内置模块与 `cordis`（MCP 插件只有 node 内置模块）。没构建时整组跳过，所以改了代码要 `pnpm build` 之后再跑一次 `pnpm check`，这组才真的检查了

文档检查 `pnpm doc`、`pnpm doc:confirm <页…>` 的脚本写在仓根，不在 `docs-site`。

## 不启动工作台验证

只有 node 部分的插件可以不启动工作台，直接在 home 里用 node 建一个 cordis 上下文验证，注意事项见[遇到过的问题](/docs/pitfalls)。

## 发版时包的顺序

`devkit.release` 的 `packages` 被依赖的在前。本仓插件之间的依赖是：说明书、设置、日志、两个命令行运行插件用命令总线，设置与两个命令行运行插件用说明书，MCP 插件用命令总线、设置、说明书与 node 命令行运行插件。八个一起发时这样给：

```
devkit.release {"dir":"<仓根绝对路径>","packages":["plugins/commands","plugins/skills","plugins/settings","plugins/data","plugins/logger","plugins/node-cli","plugins/py-cli","plugins/mcp"]}
```
