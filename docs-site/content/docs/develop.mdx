## 构建

在仓根：

```powershell
pnpm install
pnpm build
```

`pnpm build` 是 `pnpm -r build`，每个插件输出到自己的 `dist/`，构建前先清空它：`files` 白名单整个带上 `dist/`，删掉或改了名的源文件，上一次构建留下的产物不清掉就跟着发出去。七个插件先用 `node -e` 删掉 `dist/`、再用 `tsc -p tsconfig.json`，MCP 插件的 `build.ts` 先删掉 `dist/`、再用 esbuild 打包出 `dist/index.js`，之后用 `tsc --emitDeclarationOnly` 输出类型声明。每个包的 `prepublishOnly` 都是 `pnpm build`：`pnpm check` 不构建，少了这一步会把上一版的 `dist` 原样发出去。

pnpm 工作区是 `plugins/*` 与 `docs-site`。仓根 `packages/` 下如果还有 `shared-react`、`tokens`，是旧构建留下的未跟踪文件、没有 `package.json`，不在工作区里。

## 提交前的检查

```powershell
pnpm check
```

依次是类型检查（仓根 `tsc --noEmit` 检查各插件的 `tests/` 与 `build.ts`，再对每个包 `pnpm -r typecheck`）、`oxlint`（带类型信息，警告也算失败）、`vitest`（`plugins/*/tests` 与 `packages/*/tests`）。

各插件的**构建产物检查**（`tests/artifact.test.ts`）查相对 import 带 `.js`、包名 import 只有 node 内置模块与 `cordis`（MCP 插件只有 node 内置模块，且只有一个打包好的 `index.js`）。没构建时整组跳过，所以改了代码要 `pnpm build` 之后再跑一次 `pnpm check`，这组才真的检查了。

文档检查 `pnpm doc`、`pnpm doc:confirm <页…>` 的脚本写在仓根，不在 `docs-site`；确认只点名自己改的页。

## 发版

**包的顺序**：`devkit.release` 的 `packages` 被依赖的在前。本仓插件之间的依赖是：说明书、设置、日志、两个命令行运行插件用命令总线，设置与两个命令行运行插件用说明书，MCP 插件用命令总线、设置、说明书与 node 命令行运行插件（逐条见[插件之间怎么连](/docs/wiring)）。八个一起发时这样给：

```
devkit.release {"dir":"<仓根绝对路径>","packages":["plugins/commands","plugins/skills","plugins/settings","plugins/data","plugins/logger","plugins/node-cli","plugins/py-cli","plugins/mcp"]}
```

**各包清单此刻的样子**：`devkit.release` 按每个包 `package.json` 的 `publishConfig.registry` 决定发到哪、没写就拒发，并要求 peer 里内核包的范围包含运行中的内核。八个包都写了团队源的 `publishConfig.registry`，peer 里内核包都是 `^0.7.0`；用到的本仓插件也写在 peer（`workspace:^`，发版时换成 `^<版本号>`）：
