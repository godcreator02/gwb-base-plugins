**本页回答**：基础插件仓是什么；八个插件怎样互相连接，每两个模块之间靠哪条接缝相连、接口是什么、细节在哪一页；每个插件讲什么、在哪一页；带着不同的目的来，接着读哪几页。

## 是什么

god 工作台的无界面基础插件：命令总线、MCP 入口、说明书、设置、数据、日志、node 与 python 命令行工具。它们都是 home 里 `cordis.yml` 点名的普通插件，只依赖内核词汇表包的类型，不依赖任何界面包；界面在界面插件仓，插件管理（装插件、找插件、配包源）在 devkit 仓，内核在内核仓。为什么这么切见[关键设计](/docs/design)，怎么改、怎么发版见[开发](/docs/develop)。

- 本仓八个插件：MCP 入口 `gwb-mcp`、日志 `gwb-logger`、命令总线 `gwb-commands`、node 命令行工具 `gwb-node-cli`、说明书 `gwb-skills`、python 命令行工具 `gwb-py-cli`、设置 `gwb-settings`、数据 `gwb-data`
- 仓外：MCP 客户端（agent）；内核（把页面发来的命令交给命令总线、日志流）；别的插件（外壳、插件管理、应用插件等，用本仓提供的服务）；插件管理（devkit 仓）；cordis loader；子进程（Electron 以 node 模式运行、uv）
- 各插件都经接缝 1 登记自己的命令；图上只画命令总线到别的插件那一条
- 实线接缝有代码接口；点线接缝 8 只靠约定

## 十条接缝

| # | 接缝 | 连接的模块 | 接口 | 细节在 |
| --- | --- | --- | --- | --- |
| 1 | 命令总线 | 命令总线 ↔ 各插件 | `gwbCommands` 的 `register`、`run`、`list` 与回执；命令行工具镜像成的命令也走这里 | [命令总线](/docs/seams/bus) |
| 2 | MCP 协议 | MCP 入口 ↔ MCP 客户端 | HTTP `/mcp`、`index` / `search` / `run` 三个工具、Bearer token、端口、`runtime.json` 的 `mcp` 项 | [MCP 协议](/docs/seams/mcp-protocol) |
| 3 | 命令表开给 agent | MCP 入口 ↔ 命令总线、说明书 | `list` / `run`、`gwbSkills.list`；回执怎么翻译 | [命令表开给 agent](/docs/seams/agent-surface) |
| 4 | 说明书 | 说明书 ↔ 带说明书的插件 | `gwbSkills.register(dir)`、`SKILL.md` 的格式、`skill.list` / `skill.read` | [说明书](/docs/seams/skills) |
| 5 | 设置 | 设置 ↔ 各插件与界面 | `gwbSettings` 的方法、`settings.*` 四条命令 | [设置](/docs/seams/settings) |
| 6 | 数据 | 数据 ↔ 各插件 | `gwbData` 的 `dir`、`readDoc`、`writeDoc` | [数据](/docs/seams/data) |
| 7 | 数据归属 | 数据、设置 ↔ 插件管理 | `owners()`、`transferOwner(id, pkg)` | [数据归属](/docs/seams/owners) |
| 8 | 条目身份（约定） | 数据、设置、说明书、命令、两个命令行工具插件 ↔ cordis loader | 调用方的条目 id 与包名；条目 id 转目录名、分区名的算法 | [条目身份](/docs/seams/entry-identity) |
| 9 | 命令行工具 | node / python 命令行工具插件 ↔ 调用它们的插件、子进程 | `gwbNodeCli` / `gwbPyCli` 的 `register`、`run` | [命令行工具](/docs/seams/cli) |
| 10 | 日志 | 日志 ↔ 内核日志流、日志窗格 | cordis 日志的 exporter 与缓冲、推给页面的事件、`logger.backlog` / `logger.where` | [日志](/docs/seams/log) |

## 怎么读这张图

- 图上只画模块与模块之间的接缝；每个插件有哪些功能、提供什么接口，看各插件自己的页
- 一条接缝连接的两个模块可以各自替换：只要接口不变，换掉其中一个，另一个不用改
- 每条接缝由什么测试保护，写在「细节在」那一列的页里；左栏接缝页标题前的数字就是图上的编号
- 内核那边的接缝（插件加载、内核服务 `gwbKernel`、IPC 通道、日志）在内核仓的文档站
