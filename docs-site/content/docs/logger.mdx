**本页回答**：日志插件 `@godcreator/gwb-logger` 管什么、刻意不知道什么；一条日志是什么形状；它提供哪些接口、依赖哪些接口；不启动工作台怎么测它；代码从哪读起。日志窗格怎么拿历史与实时日志、来源名单靠什么约定，写在接缝页[日志](/docs/seams/log)。

## 管什么

**三个来源的日志本来就汇在一条流上。** 插件与 loader 的日志、内核自己的日志、页面 console（内核把它转成名为 `renderer` 的 cordis 日志）都经 cordis 的 `ctx.logger`；内核在这条流上注册了第一个 exporter，写 stderr 与 `<home>/gwb.log`。日志插件注册第二个，级别设为 3（`debug` 也收），每收到一条就编号、分来源、存进缓冲、经 `gwbKernel.emit` 推给页面：

{/* ref file="../plugins/logger/src/index.ts" lines="100-125" */}

**插件加载之前的日志从 cordis 自带的缓冲补进来。** `ctx.logger.buffer` 是 cordis 注册的第一个 exporter，留 info 及以上；先补这一段再注册自己的 exporter，两段不重叠。

**分来源、定级别。** logger 名是 `renderer` 的算页面，是 `kernel`、`loader` 的算内核，其余算插件；cordis 的 `success` 等级别一律算 `info`：

**保留最近两千条**，超出时从最早的开始丢；每条带从 1 起递增的 `seq`，窗格按它合并历史与实时日志、去重。

**exporter 不抛错。** 格式化失败时退回把参数逐个转成文本——exporter 抛错会打断别人写日志的那次调用：

## 不知道什么

**不写日志文件、不写 stderr。** `<home>/gwb.log` 与 stderr 由内核的 exporter 写，日志插件不在时人照样看得到日志；更早的日志去 `gwb.log` 找。

**不画窗格。** 日志窗格在界面插件仓 gwb-ui-plugins，筛选、搜索、清屏都是窗格的事；日志插件的 `package.json` 里没有任何界面包。

**不过滤、不改级别。** `debug` 也进缓冲；日志插件只收，不管别的插件怎么写日志。

**来源名单是抄来的。** `kernel`、`renderer` 两个名字由内核定，`loader` 是 cordis loader 自己的 logger 名，日志插件在 `KERNEL_LOGGER_NAMES` 里另写一份。内核改名或新增名字，这边会把它算成插件，不报错（见[日志](/docs/seams/log)的「靠约定」）。

**服务上不放方法。** 取数据走命令、推送走内核事件；出现第二个绕不开服务的使用方之前不加：

## 提供的接口

| 接口 | 做什么 | 契约在 |
| --- | --- | --- |
| 命令 `logger.backlog` | 无参数，返回最近两千条日志的数组 | [10 日志](/docs/seams/log) |
| 命令 `logger.where` | 无参数，返回 `{ home, logFile }`，`logFile` 是内核写的 `<home>/gwb.log` | [10 日志](/docs/seams/log) |
| 页面事件 `{ t: 'gwb-logger', line }` | 每条新日志经 `gwbKernel.emit` 推给页面，页面用 `window.gwb.on` 收 | [10 日志](/docs/seams/log) |
| 服务 `ctx.gwbLogger` | 没有方法；出现就说明日志插件已加载、`logger.backlog` 可以调了 | [10 日志](/docs/seams/log) |
| 导出的类型 `LogEntry`、`LogSource`、`LogLevel`，常量 `EVENT`、`BACKLOG_COMMAND`、`WHERE_COMMAND`，函数 `sourceOf` | 给同在 node 侧的使用方与测试用；日志窗格在浏览器里，不 import 它们 | [10 日志](/docs/seams/log) |

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |

## 怎么单独测

三个测试文件，都在 `plugins/logger/tests/`：

**`source.test.ts`** 测 `sourceOf`：`renderer` 是页面，`kernel`、`loader` 是内核，其余都算插件。

**`apply.test.ts` 装上整个插件测**：真 cordis 根上下文，内核与命令总线用替身，内核替身把 `emit` 的载荷收进数组：

{/* ref file="../plugins/logger/tests/apply.test.ts" lines="28-40" */}

证明的是：提供服务 `gwbLogger`；两条命令登记在本包包名下、卸载时注销；每条新日志推一次 `{ t: 'gwb-logger', line }` 并进 backlog；来源与级别的分类；装上之前的日志从 cordis 缓冲补进来，`seq` 从 1 起连续；就绪时写一条 info；backlog 最多两千条、返回副本。

**`artifact.test.ts`** 查构建产物：相对 import 带 `.js`，包名 import 只有 node 内置模块与 `cordis`。

窗格按 `seq` 拼接历史与实时日志，只能在隔离 home 里验证：日志插件加载后自己写的那条 info 出现在窗格里，来源是插件、名字是 `gwb-logger`。
