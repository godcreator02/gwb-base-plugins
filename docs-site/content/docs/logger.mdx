**本页回答**：日志插件有哪些功能；日志窗格和 agent 经哪些接口用它，各属于哪条接缝；它依赖什么、缺了会怎样；哪些事常被以为归它、其实归内核或界面插件。包名 `@godcreator/gwb-logger`，源码目录 `plugins/logger/src`，入口文件 `index.ts`。

日志插件没有界面，也不收日志：日志由内核写进 `<home>/gwb.log`，日志插件只在有人调 `logger.query` 时读这份文件。人在界面上看日志用的日志窗格在界面插件仓 gwb-ui-plugins 里，它经这条命令取数据。

<Diagram name="log-flow" title="内核写两份日志文件，logger.query 怎么读（分步）">
- 插件、内核、页面 console 的日志都由内核写成 `<home>/gwb.log` 里的一行 JSON `{ ts, level, source, name, msg }`；写满 128 MB 改名成 `gwb.log.1`，只留这一份旧的
- 不给 `after`：从 `gwb.log` 末尾按块往前读、逐行筛，凑够 `limit` 条就停，不够再接着读 `gwb.log.1`
- 给 `after`：`gwb.log` 不比 `after` 小，只读 `after` 到末尾；比 `after` 小说明轮转过，先读 `gwb.log.1` 从 `after` 到末尾，再读新 `gwb.log` 全部
- 不是 JSON、五个键的顺序或类型不对的行直接报错，写明文件与行首
</Diagram>

## 功能

- **按条件查日志文件**：`logger.query` 读内核写的 `gwb.log` 与轮转出的 `gwb.log.1`，按级别（这一级及以上）、logger 名（精确匹配）、子串（在 `name` 与 `msg` 里找，不分大小写）筛，回筛完之后最近的 `limit` 条，默认 2000
- **只读新写的**：回执里的 `cursor` 是读完时 `gwb.log` 的字节长度，下一次作 `after` 传回来，就只读那之后新写的；中间轮转过也接得上
- **倒着按块读**：从文件末尾往前一次读 64 KB，凑够条数就停，不把整份文件读进内存；按字节找换行再解码，块边界切在多字节字符中间也不会解错
- **坏行、坏参数直接报错**：一行不是 JSON、五个键的顺序或类型对不上，报错写明是哪份文件、那一行开头几十个字符，不跳过；参数里有认不出的键、类型不对，也直接报错
- 命令标 `effect: 'read'`，插件卸载时注销

## 接口

每条接缝上交换什么、各方保证什么，写在接缝页；本节只列日志插件提供了哪些接口。

| 接口 | 做什么 | 接缝 |
| --- | --- | --- |
| 命令 `logger.query` | 参数 `{ limit?, minLevel?, name?, text?, after? }` 都可省：`limit` 是正整数，默认 2000；`minLevel` 是 `debug` / `info` / `warn` / `error`；`name` 精确匹配；`text` 是非空字符串；`after` 是非负整数，取上一次回执里的 `cursor`。回 `{ file, cursor, entries }`：`file` 是 `gwb.log` 的绝对路径，`cursor` 是读完时它的字节长度，`entries` 是文件里原样的对象，从旧到新 | [10 日志](/docs/seams/log) |
| 一条日志 `LogEntry` | `ts`（ISO 时间字符串）、`level`、`source`（`kernel` / `plugin` / `renderer`）、`name`、`msg`，就是 `gwb.log` 一行的五个键，顺序由内核定；类型由本包导出，回执类型 `LogQueryResult` 也是 | [10 日志](/docs/seams/log) |

## 依赖

注入了哪些服务、peer 怎么写、缺了会怎样，以及用了哪些约定通道（写死的 `gwb.log` 文件名与 `.1` 后缀、一行的五个键），见[插件之间怎么连](/docs/wiring#godcreatorgwb-logger)。

## 不做的事

- **不写日志、不收日志**：`gwb.log` 与 stderr 由内核写；日志插件不在 cordis 的日志流上注册任何东西，它不在时日志照样写进文件（轨迹卡[日志插件只读内核写的文件](/trajectory/2026-09-27-logger-reads-kernel-file)）
- **不在内存里留日志、不推给页面**：每次调用都现读文件；日志窗格要新日志，就带 `after` 再调一次
- **不分来源**：`source` 由内核写进每一行，日志插件原样交出
- **不画窗格**：日志窗格在界面插件仓 gwb-ui-plugins，怎么显示、怎么筛是窗格的事
- **不提供服务**：只有一条命令，别的插件、页面、agent 都经命令总线调
