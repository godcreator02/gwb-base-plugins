**本页回答**：日志插件有哪些功能；页面、agent 和日志窗格经哪些接口用它，各属于哪条接缝；它依赖什么、缺了会怎样；哪些事常被以为归它、其实归内核或界面插件。包名 `@godcreator/gwb-logger`，源码目录 `plugins/logger/src`，入口文件 `index.ts`。

日志插件没有界面。人在界面上看日志用的日志窗格在界面插件仓 gwb-ui-plugins 里，它从这个插件取数据。

- 插件（`ctx.logger('<名字>')`）、内核（`kernel`、`loader`）、页面 console（内核转成 `renderer`）的日志都经 cordis 的 `ctx.logger` 汇成一条流
- 流上有三个接收方：内核的 exporter 写 stderr 与 `<home>/gwb.log`；cordis 自带的缓冲 `ctx.logger.buffer` 留 info 及以上；日志插件的 exporter 收全部（debug 也收）
- 日志插件加载时先从 `ctx.logger.buffer` 补历史，再注册自己的 exporter
- 每条新日志编 `seq`、分来源，存进 2000 条的缓冲，经 `gwbKernel.emit` 推 `{ t: 'gwb-logger', line }` 给页面
- 界面插件仓的日志窗格先用 `window.gwb.on` 订阅，再调 `logger.backlog` 取历史，两段按 `seq` 合并

## 功能

- **把三个来源的日志收到一处**：插件与 loader 的日志、内核自己的日志、页面 console（内核把它转成名为 `renderer` 的 cordis 日志），都经 cordis 的日志流来，插件在流上注册一个 exporter（级别设为 3，`debug` 也收）就全部收到；它是流上的第三个 exporter，前两个是 cordis 自带的缓冲和内核写 stderr 与 `gwb.log` 的那个
- **给每条日志分来源、定级别**：logger 名是 `renderer` 的算页面，是 `kernel`、`loader` 的算内核，其余算插件；cordis 的 `success` 等级别算 `info`
- **保留最近两千条**：足够查看启动以来的日志，又不至于占太多内存；插件加载之前已经产生的日志，从 cordis 自带的缓冲里补进来，先补再注册 exporter，两段不重叠；每条带从 1 起递增的序号 `seq`
- **实时推给页面**：每收到一条，经内核的事件通道推给页面
- **不打断别人写日志**：格式化失败时退回把参数逐个转成文本——exporter 抛错会打断写这条日志的那次调用
- **两条命令**：`logger.backlog` 取最近两千条，`logger.where` 报 home 目录与日志文件的路径；插件卸载时注销
- **提供一个没有方法的服务 `gwbLogger`**：日志窗格按服务名等它出现，服务上刻意不放任何方法；`apply` 里先提供这个服务再做别的
- **就绪时写一行 info**：写明补进了多少条历史；装了日志窗格的话，这一行会出现在窗格里，可以用来确认整条链路是通的

## 接口

每条接缝上交换什么、各方保证什么，写在接缝页；本节只列日志插件提供了哪些接口。

| 接口 | 做什么 | 接缝 |
| --- | --- | --- |
| 命令 `logger.backlog` | 无参数，返回最近两千条日志的数组（副本） | [10 日志](/docs/seams/log) |
| 命令 `logger.where` | 无参数，返回 `{ home, logFile }`，`logFile` 是内核写的 `<home>/gwb.log` | [10 日志](/docs/seams/log) |
| 页面事件 `{ t: 'gwb-logger', line }` | 每条新日志经 `gwbKernel.emit` 推给页面，页面用 `window.gwb.on` 收，靠 `t` 认出 | [10 日志](/docs/seams/log) |
| 一条日志 `LogEntry` | `seq`、`ts`、`source`（`plugin` / `kernel` / `renderer`）、`level`（`error` / `warn` / `info` / `debug`）、`name`、`msg`；类型由本包导出 | [10 日志](/docs/seams/log) |
| 服务 `ctx.gwbLogger` | 没有方法；日志窗格写 `inject: ['gwbLogger']` 只为等日志插件加载 | [10 日志](/docs/seams/log) |

**日志窗格怎么取**：先用 `window.gwb.on` 订阅实时事件，再调 `logger.backlog` 取历史，两段按 `seq` 拼接、去重。反过来先取历史再订阅，中间那一刻产生的日志会漏掉；按 `ts`、`name`、`msg` 拼字符串去重会把同一毫秒里两条一样的日志丢掉一条，所以用 `seq`。

## 依赖

注入了哪些服务、peer 怎么写、缺了会怎样，以及用了哪些约定通道（cordis 日志流上的第三个 exporter、推给页面的内核事件、写死的 `gwb.log` 文件名与 `kernel` / `loader` / `renderer` 三个来源名），见[插件之间怎么连](/docs/wiring#godcreatorgwb-logger)。

## 不做的事

- **不写日志文件**：`<home>/gwb.log` 与 stderr 由内核写，日志插件不在时人照样看得到日志
- **不画窗格**：日志窗格在界面插件仓 gwb-ui-plugins，筛选、搜索、清屏都是窗格的事
- **不保存缓冲**：两千条只在内存里，重启就清空；更早的日志去 `gwb.log` 找
- **不改日志级别、不过滤**：`debug` 也进缓冲；日志插件只收，不管别的插件怎么写日志
- **服务 `gwbLogger` 上不放方法**：取数据走命令，推送走内核事件
