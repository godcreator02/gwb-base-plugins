# gwb-logger

包名 `@godcreator02/gwb-logger`，**没有服务**。它只做一件事：把内核汇好的那条流水画成一格窗格。

两半都做完了，实机验通：内核那半（四路汇总、缓冲、`gwb.logs` 两条口、文件轮转）与这个件。

## 先看分工：日志的活几乎全不在这个件里

四路日志——件与 loader 的 cordis 日志、宿主自己的话（`[host]` / `[install]` / `[stdin]`）、
主进程自己的话、渲染层的 console——**汇总、缓冲、落盘、轮转全在内核**。

| | 谁收 | 这个件做什么 |
| --- | --- | --- |
| 件与 loader 的 cordis 日志 | 宿主自己挂的全量 exporter，经 fd3 上行 | 不做 |
| 宿主自己的话 | 同上（那几处裸 `console.error` 改走 `ctx.logger`） | 不做 |
| 主进程自己的话 | 主进程自己 | 不做 |
| 渲染层 console | 主进程收 `console-message` | 不做 |
| 历史段与实时 | 主进程的环形缓冲 + preload 两条口 | **取，画** |
| 落盘与轮转 | 主进程，`<home>/logs/` | 不做 |

判据一句话：**位置由「谁够得着」决定。** 主进程够得着三路，件跑在宿主子进程里，主进程与
渲染层那两路一个字都看不见。而且**件挂不上的时候它自己也不在场**——那恰恰是最该看日志的
时候。完整判据在**内核仓的站**上（`26090705ymz/gwb-kernel` 的「定过的事」，日志那六条）。

**这条改判过**：路线页原先写着「node 半不要，cordis 的出口归官方 `plugin-logger-console`」
——那句成立的前提是「只收 cordis 日志」。要「一切」之后前提没了，官方那个件也撤了。

## 窗格里有什么

**版式的正本就是这一段。** 2026-09-08 视觉精修过一轮：先在一份独立的效果图工程里定稿，
再落进件。（那份工程 `design/` 2026-09-09 随选择器 scope 那条构建线一起删了——画的东西
已经在件里，留着就是第二份真相。所以**效果图不再存在，别去找**。）行为语义没动，动的
是观感：日志行改 grid 定宽列齐头（时间戳/级别/路标/来源名/消息，消息列不再被不定宽的
来源名推得参差）；级别从徽标改成**无框字母加整行色调**（error/warn 行淡色底加左缘色条，
info/debug 保持素底）；来源名从亮白降到中间档，消息是行里唯一全亮的。

**三个筛选维度，两个是新加的**（母仓那份只有级别与一个平的来源下拉）：

| 维度 | 形态 | 为什么 |
| --- | --- | --- |
| 级别 | 分段控件一排四个，**门限**语义（点 Warn 是「Warn 及以上」），选中挡实心、更严重侧半亮——把显示范围画出来 | 日志里 error 少 info 多，实际操作永远是把噪声压下去，而「只看 info 不看 error」这个场景不成立 |
| 路 | 胶囊一排四个，**多选**，各带色点与条数；关掉整颗降透明（不再是删除线） | 「把渲染层的噪声关掉」是最常见的一步，单选下拉做不到；色点与流水行路标同色，筛选与行用同一个颜色锚 |
| 来源名 | Select，**按路分组** | 名字是开集、路是闭集，两个维度性质不同，揉进一个控件就筛不干净 |
| 搜索 | 子串、不区分大小写、同时匹配 `name` 与 `msg` | 四路合流之后噪声大一个量级，两个维度筛不到「那句话」 |

来源名的值要用 `source|name` 这样的**复合键**——不同路的同名（比如宿主和某个件都叫
`install`）不能撞在一起。

**各自的代价**：门限筛掉了「只看某一级」（要那个靠搜索）；两个来源维度是「与」关系，人能
把自己筛成空表——所以空态文案必须分得清**「一条都没有」和「被筛掉了」**，后者带一颗「清筛选」。

**搜索明确不做正则**：写错的表达式静默匹配不到任何东西，人只会以为没日志。也不做防抖——
2000 条上做一次 `includes` 是微秒级的，防抖只会让输入手感发黏。

**从母仓继承、这次改了形态的**：

- **吸附底部**（离底 24px 之内就跟着走）保留；「已暂停吸附」从脚注文本挪成**右下角的
  浮胶囊**，点它回底——吸附状态是个动作入口，不是一句话。浮胶囊挂在窗格根，不进滚动
  容器（absolute+bottom 相对滚动内容的话，内容一长就漂出视口）
- **时间戳带毫秒**（`HH:mm:ss.SSS`）保留——四路合流之后「谁先谁后」是最常问的问题
- **「清空」改叫「清屏」**保留——它只清这一份视图，不动缓冲也不动文件；而且**清完不会
  自己回来**（backlog 只在挂载时取一次），重开窗格才会。这两句写在按钮的 `title` 上
- 每行的**三字路标**（`件`/`宿主`/`主`/`渲`）保留，前面加一颗小色点，四路各一色——
  用点不用第二个徽标，一行里颜色太多就没有重点了

**上限 2000 条**，超了从头切。这个数是**渲染成本**定的（一行一个 div，没有虚拟滚动），不是
缓冲大小——所以 `backlog()` 回来的比它多时窗格侧切尾，翻更早的去日志文件，**路径印在脚注上**。
虚拟滚动明确不做：真遇到需求才加。

## 它从哪儿拿日志

**不从 `args` 拿。** `mountPane` 给的是 `{ host, shell, pane }`，日志走的是页面的公共面：

```js
const off = window.gwb.logs.on((batch) => { /* 一批一批地追上去 */ })
const history = await window.gwb.logs.backlog()
```

**先订阅实时，再取历史。** 缓冲里是开机以来的整段，窗格挂载那一刻之前推的全在里面，两段
按 `seq` 接上，交叠的那一瞬靠去重挡住。反过来的话中间那一瞬会漏。

**去重与排序都用 `seq`**——母仓那份拿 `ts|name|msg` 拼字符串，同一毫秒里两句一模一样的话
会被静默吃掉一句，四路合流之后那不是假想。母仓还写着 `logBacklog?.()` 的可选链兼容老
preload，这条线只有一版，去掉。

**为什么不经外壳转发**：外壳凭什么认识「日志」。`window.gwb` 是**页面的公共面**（谁在这页上
跑都够得着），`args` 是**外壳给窗格的额外便利**，两者不是替代关系。这条与「不走命令通道」的
判据都在内核仓的站上。

`host` 只用在一处：调 `kernel.info` 取 home 与日志目录，画在脚注上。所以这个件**一条命令都
不注册**，也就不 `inject` `gwbCommands`、不依赖 commands 件。

## 条目按形状收，不引类型包

```ts
{ seq, ts, source, level, name, msg }
```

`source` 是 `plugin` / `host` / `main` / `renderer` 四路之一，`level` 四路给的都是真级别。
判形函数认不出的条目**丢掉，不崩**。

跟 `hello` 的 client 同一个规矩：浏览器半不牵 node 那边的类型包。代价是形状变了没有编译期
守卫——判形函数就是那道运行期守卫，而正本钉在内核仓的契约页上。

## 这一格开几份

**2026-09-11 起不由注册说了算**：`duplicable` 那个布尔删掉了，一格开几份取决于它装着几份
不同的内容（件调 `openPane` 时给的 `key`）。所以这个件注册时什么都不必声明——它将来真要
「一份钉在 Error、一份跟着某个件的流水」，办法是拿这两个筛选条件当 `key` 各开一份。判据见
[定过的事](/docs/decisions)。

真开出两份时的代价没变：两份各订阅一次、各持 2000 条，内存与渲染都是双份，而且两份会各自
调一次 `backlog()`。筛选状态本来就是组件本地的 state，两份天然互不干扰。

**`pane.instance` 这一版用不上**：两份的隔离是 React 树天然的。它真正到期是在「筛选条件落盘」
那天——那时键必须带 instance，否则两份互相覆盖。

## 三个已知的坑（还没撞，撞了搬进「撞过的墙」）

**一、日志回环。** 渲染层的 console 是四路之一：窗格自己 `console.error` 一句 → 主进程收走 →
进缓冲 → 推回窗格 → 那条路上如果又打了一句，就是一变二、二变四，**界面当场冻死**。所以
**窗格在收日志的路径上一个 console 都不许打**；取表失败那种非循环路径上的可以留。

**二、Radix 的门户会逃出 scope 围栏——这条随围栏换代整个消失了，留着是记它的下场。**
0.1 时件的样式表整张 scope 在 `[data-gwb-plugin=…]` 之下，而 Select 的弹层默认挂在 `body`
下，挂出去就一条规则都匹配不上，**症状是「下拉打开是一片没样式的白板」**。这个件是**第一个
用门户组件的件**（`hello` 只有 Button，外壳那张 dockview 表本来就不 scope），所以第一个撞上。

当时的走法：`src/client/portal.tsx` 供一个 `PortalContainer` context，窗格在顶层把 `mountPane`
给的容器放进去（它身上正好带着 `data-gwb-plugin`），改过的 `select.tsx` 自己去读——做成
context 而不是让调用方逐个传，因为传漏了同样是静默白板。

**0.2.0 换成 Tailwind 前缀围栏之后这套全拆了**：类名从源头带 `logger:`，规则全页有效、
跟 DOM 祖先无关，弹层挂到 `body` 上照样有样式。`portal.tsx` 删除，`select.tsx` 重拉成
**官方原样**，一个补丁都不打。实机量过：Select 的弹层挂在 `body` 下、底色等于 `--popover`。
**这一整条现在只对 scope 方案成立，而 scope 方案已经没有了**——写在这儿是为了以后有人
提出「让组件知道自己该挂哪个容器」时，能一眼认出那是在往回走。判据见
[定过的事](/docs/decisions)。

**三、`icon` 名要查一眼。** `scroll-text` 是确定有的；`logs` 这个名字是 lucide 较新加的，用之前
先确认在不在。图标这一版注册了也只是原样收着——真画是外壳导航的事。

## 依赖为什么这么写

三条 peer 各是[三档判据](/docs/overview)里的不同一档，值得单看一眼：

- **契约包 `gwb-plugin-api`**：只 `import type`，但 `apply(ctx: GwbContext)` 让它进了
  `dist/index.d.ts`——**出现在导出的类型面上**，就是中间那一档
- **`gwb-shell` 件**：一行值都没 import（只 `import type {}` 激活它的 `declare module`），
  类型也不在导出面上，按字面像 dev。但 **`inject: ['gwbShell']` 是运行期硬依赖**——home 里
  没有它，这个件永远挂不上。peer 的语义正是「宿主环境得提供这个」。**凡是 `inject` 的服务
  提供方，一律 peer。** 版本写 `>=`，钉的是「这个面得在」而不是某一版
- **两个共享包**（`gwb-shared-react` / `gwb-tokens`）：浏览器半靠 home 里有它们才跑得起来
  ——react 系经页面 importmap、令牌表经 `gwb://`

`radix-ui` / `class-variance-authority` / `cn` / `lucide-react` 是 **dev**：它们是 shadcn 组件的
运行时依赖，但**打进本束**——不在 importmap 里，外置成裸名就是运行期一句
`Failed to resolve module specifier`。产物守卫钉着这条（`client.js` 里除那四个共享名之外
不许有裸名，而且 `select-trigger` 得真在束里）。

`cordis` 一个字都没 import（node 半不 `extends Service`、只写 `apply`），本件不写，
由契约包的 peer 带进来——对照 `gwb-shell`，那边 `extends Service` 是运行时真 import，写的是 peer。

**组件是从 shadcn 官方拉的四个**（button / badge / input / select），照仓里的规矩各拉各的，
**四个都是官方原样**——0.2.0 迁前缀围栏时 `select.tsx` 那处 Portal container 的手改连同
`src/client/portal.tsx` 一起删了。`components.json` 的 `tailwind.prefix` 填着 `logger`，
CLI 拉下来的类名自带前缀，不用回头手改。

peer 范围一律写 `>=` 不写 `^`：caret 在 `0.0.x` 上锁死 patch（`^0.0.1` 只匹配 `0.0.1`），
共享包一升版消费方就不匹配了。
