# gwb-logger

包名 `@godcreator02/gwb-logger`，0.3 起是**无头 core 件**：挂第二个 cordis exporter 收全量、
自己缓冲、开 `logger.backlog` / `logger.where` 两条命令、实时经内核事件口推给页面；外加一格
面刻意留空的薄服务 `gwbLogger`（0.3.1 补挂——gwb-baseui 的日志窗格按服务名嵌套注入，没有
它那格永远 PENDING）。**窗格不住这儿**，住 `@godcreator02/gwb-baseui`，装它找回。

## 先看分工：管道整块在这个件里，窗格不在

三路日志——件与 loader 的 cordis 日志、内核自己的话、渲染层的 console（内核把它转进了
`ctx.logger('renderer')`，所以一个 exporter 收齐）——**汇总与缓冲在这个件**：挂第二个
exporter 收全量、自己缓冲两千条、历史段从 cordis 自带的那圈 buffer 补、实时经内核事件口
（`gwbKernel.emit`）推给页面。内核只做一件事：cordis 的日志全量进 stderr 与 `<home>/gwb.log`，
人不靠任何件也看得见。

**窗格不住这个件**：0.3 劈 core 后它住 `@godcreator02/gwb-baseui`。

判据一句话：**位置由「谁够得着」决定。** 这条是老内核时代定下的——那时件跑在宿主子进程
里，四路里两路一个字都看不见，汇总全在内核；单进程内核之后管道整块搬进了这个件，而
「**件挂不上的时候它自己也不在场**——那恰恰是最该看日志的时候」仍然成立，所以 stderr 与
`gwb.log` 那条兜底留在内核。

**这条改判过**：路线页原先写着「node 半不要，cordis 的出口归官方 `plugin-logger-console`」
——那句成立的前提是「只收 cordis 日志」。要「一切」之后前提没了，官方那个件也撤了。

## 窗格里有什么

**这格窗格 0.3 劈 core 后住 `@godcreator02/gwb-baseui`**——版式与交互的代码随浏览器半搬了
过去；这一节留着的是定稿时的判据（为什么门限、为什么多选、为什么复合键），判据不随代码
搬家作废。

版式 2026-09-08 视觉精修过一轮：先在一份独立的效果图工程里定稿，再落进件。（那份工程
`design/` 2026-09-09 随选择器 scope 那条构建线一起删了——画的东西先落在件里、三仓拆分时
随窗格搬去了 gwb-baseui，留着就是第二份真相。所以**效果图不再存在，别去找**。）行为语义
没动，动的是观感：日志行改 grid 定宽列齐头（时间戳/级别/路标/来源名/消息，消息列不再被
不定宽的来源名推得参差）；级别从徽标改成**无框字母加整行色调**（error/warn 行淡色底加
左缘色条，info/debug 保持素底）；来源名从亮白降到中间档，消息是行里唯一全亮的。

**三个筛选维度，两个是新加的**（母仓那份只有级别与一个平的来源下拉）：

| 维度 | 形态 | 为什么 |
| --- | --- | --- |
| 级别 | 分段控件一排四个，**门限**语义（点 Warn 是「Warn 及以上」），选中挡实心、更严重侧半亮——把显示范围画出来 | 日志里 error 少 info 多，实际操作永远是把噪声压下去，而「只看 info 不看 error」这个场景不成立 |
| 路 | 胶囊一排四个，**多选**，各带色点与条数；关掉整颗降透明（不再是删除线） | 「把渲染层的噪声关掉」是最常见的一步，单选下拉做不到；色点与流水行路标同色，筛选与行用同一个颜色锚 |
| 来源名 | Select，**按路分组** | 名字是开集、路是闭集，两个维度性质不同，揉进一个控件就筛不干净 |
| 搜索 | 子串、不区分大小写、同时匹配 `name` 与 `msg` | 四路合流之后噪声大一个量级，两个维度筛不到「那句话」 |

来源名的值要用 `source|name` 这样的**复合键**——不同路的同名（比如宿主和某个件都叫
`install`）不能撞在一起。

**各自的代价**：门限筛掉了「只看某一级」（要那个靠搜索）；两个来源维度是「与」关系，人能
把自己筛成空表——所以空态文案必须分得清**「一条都没有」和「被筛掉了」**，后者带一颗「清筛选」。

**搜索明确不做正则**：写错的表达式静默匹配不到任何东西，人只会以为没日志。也不做防抖——
2000 条上做一次 `includes` 是微秒级的，防抖只会让输入手感发黏。

**从母仓继承、这次改了形态的**：

- **吸附底部**（离底 24px 之内就跟着走）保留；「已暂停吸附」从脚注文本挪成**右下角的
  浮胶囊**，点它回底——吸附状态是个动作入口，不是一句话。浮胶囊挂在窗格根，不进滚动
  容器（absolute+bottom 相对滚动内容的话，内容一长就漂出视口）
- **时间戳带毫秒**（`HH:mm:ss.SSS`）保留——四路合流之后「谁先谁后」是最常问的问题
- **「清空」改叫「清屏」**保留——它只清这一份视图，不动缓冲也不动文件；而且**清完不会
  自己回来**（backlog 只在挂载时取一次），重开窗格才会。这两句写在按钮的 `title` 上
- 每行的**三字路标**（`件`/`宿主`/`主`/`渲`）保留，前面加一颗小色点，四路各一色——
  用点不用第二个徽标，一行里颜色太多就没有重点了

**上限 2000 条**，超了从头切——这个数如今钉在件的环形缓冲上（`CAP`），`logger.backlog` 回的
就是最近这两千条；它最早是窗格侧的渲染成本上限（一行一个 div、没有虚拟滚动），劈 core 后
缓冲与显示合成一个数。翻更早的去日志文件，路径 `logger.where` 报、窗格印在脚注上。
虚拟滚动明确不做：真遇到需求才加。

## 窗格从哪儿拿日志

窗格那半（住 gwb-baseui）**先订实时、再取历史**：实时经内核事件口到页面的公共面
`window.gwb.on`（认 `{ t: 'gwb-logger', line }` 那个记号），历史走 `logger.backlog`（开机
到此刻，最近两千条）。缓冲里是开机以来的整段，窗格挂载那一刻之前推的全在里面，两段按
`seq` 接上，交叠的那一瞬靠去重挡住。反过来的话中间那一瞬会漏。

**去重与排序都用 `seq`**——母仓那份拿 `ts|name|msg` 拼字符串，同一毫秒里两句一模一样的话
会被静默吃掉一句，三路合流之后那不是假想。母仓还写着 `logBacklog?.()` 的可选链兼容老
preload，这条线只有一版，去掉。

**为什么不经外壳转发**：外壳凭什么认识「日志」。`window.gwb` 是**页面的公共面**（谁在这页上
跑都够得着），窗格的挂载参数是**外壳给窗格的额外便利**，两者不是替代关系。

home 与日志目录不劳窗格自己去摸：这个件开 `logger.where`，回 `{ home, logFile }`——窗格
脚注直接用。所以它 `inject` 的只有 `gwbCommands`（没有总线历史段出不去、命令注册不上），
commands 是 peer。

## 条目按形状收，不引类型包

```ts
{ seq, ts, source, level, name, msg }
```

`source` 是 `plugin` / `host` / `main` / `renderer` 四路之一，`level` 四路给的都是真级别。
判形函数认不出的条目**丢掉，不崩**。

跟窗格那半（住 gwb-baseui）同一个规矩：浏览器半不牵 node 那边的类型包。代价是形状变了
没有编译期守卫——判形函数（随窗格住 gwb-baseui）就是那道运行期守卫，形状的正本是上面
钉的那段 `LogEntry`。

## 这一格开几份

**2026-09-11 起不由注册说了算**：`duplicable` 那个布尔删掉了，一格开几份取决于它装着几份
不同的内容（开窗格时给的 `key`）。所以窗格那侧（住 gwb-baseui）什么都不必声明——真要
「一份钉在 Error、一份跟着某个件的流水」，办法是拿这两个筛选条件当 `key` 各开一份。判据见
[定过的事](/docs/decisions)。

真开出两份时的代价没变：两份各订阅一次、各持 2000 条，内存与渲染都是双份，而且两份会各自
调一次 `backlog()`。筛选状态本来就是组件本地的 state，两份天然互不干扰。

**`pane.instance` 这一版用不上**：两份的隔离是 React 树天然的。它真正到期是在「筛选条件落盘」
那天——那时键必须带 instance，否则两份互相覆盖。

## 三个已知的坑（还没撞，撞了搬进「撞过的墙」）

**一、日志回环。** 渲染层的 console 是三路之一：窗格自己 `console.error` 一句 → 内核收走
（转进 `ctx.logger('renderer')`）→ 进缓冲 → 推回窗格 → 那条路上如果又打了一句，就是一变二、
二变四，**界面当场冻死**。所以
**窗格在收日志的路径上一个 console 都不许打**；取表失败那种非循环路径上的可以留。

**二、Radix 的门户会逃出 scope 围栏——这条随围栏换代整个消失了，留着是记它的下场。**
0.1 时件的样式表整张 scope 在 `[data-gwb-plugin=…]` 之下，而 Select 的弹层默认挂在 `body`
下，挂出去就一条规则都匹配不上，**症状是「下拉打开是一片没样式的白板」**。这个件是**第一个
用门户组件的件**（`hello` 只有 Button，外壳那张 dockview 表本来就不 scope），所以第一个撞上。

当时的走法：`src/client/portal.tsx` 供一个 `PortalContainer` context，窗格在顶层把 `mountPane`
给的容器放进去（它身上正好带着 `data-gwb-plugin`），改过的 `select.tsx` 自己去读——做成
context 而不是让调用方逐个传，因为传漏了同样是静默白板。

**0.2.0 换成 Tailwind 前缀围栏之后这套全拆了**：类名从源头带 `logger:`，规则全页有效、
跟 DOM 祖先无关，弹层挂到 `body` 上照样有样式。`portal.tsx` 删除，`select.tsx` 重拉成
**官方原样**，一个补丁都不打。实机量过：Select 的弹层挂在 `body` 下、底色等于 `--popover`。
**这一整条现在只对 scope 方案成立，而 scope 方案已经没有了**——写在这儿是为了以后有人
提出「让组件知道自己该挂哪个容器」时，能一眼认出那是在往回走。判据见
[定过的事](/docs/decisions)。

**三、`icon` 名要查一眼。** `scroll-text` 是确定有的；`logs` 这个名字是 lucide 较新加的，用之前
先确认在不在。图标注册随窗格那半住 gwb-baseui——真画是外壳导航的事。

## 依赖为什么这么写

劈 core 之后 peers 剩三条，各是[三档判据](/docs/overview)里的不同一档：

- **契约包 `gwb-plugin-api`**：`requireKernel` 是运行时真 import——第一档，peer
- **`gwb-commands` 件**：一行值都没 import（只 `import type {}` 激活它的 `declare module`），
  但 **`inject: ['gwbCommands']` 是运行期硬依赖**——home 里没有它，这个件永远挂不上（没有
  总线，历史段出不去、命令注册不上）。peer 的语义正是「宿主环境得提供这个」。**凡是
  `inject` 的服务提供方，一律 peer。** 版本写 `>=`，钉的是「这个面得在」而不是某一版
- **`cordis`**：0.3.1 起薄服务 `extends Service`，且必须是宿主那一份——运行时真 import，
  peer。（0.3 之前 cordis 一个字都没 import、由契约包的 peer 带进来，薄服务落地后升了档。）

原先那三条 UI 侧的 peer——`gwb-shell`、`gwb-shared-react` / `gwb-tokens`——与 shadcn 那套
dev 依赖（radix / cva / cn / lucide、`components.json` 的 `logger` 前缀）全随浏览器半搬去了
`@godcreator02/gwb-baseui`：窗格侧的依赖故事在那边讲，Tailwind 前缀围栏、Select 浮层户口
那些也随之过去了。

peer 范围一律写 `>=` 不写 `^`：caret 在 `0.0.x` 上锁死 patch（`^0.0.1` 只匹配 `0.0.1`），
共享包一升版消费方就不匹配了。
