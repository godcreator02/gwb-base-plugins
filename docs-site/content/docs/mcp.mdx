# gwb-mcp

把 [`ctx.gwbCommands`](/docs/commands) 那份命令注册表开给任意外部 agent。方向**永远**是
agent → 工作台。

包名 `@godcreator02/gwb-mcp`，无界面。`inject: ['gwbCommands', 'gwbData']`。

## 怎么连

起来之后日志里有两行：

```
[I] gwb-mcp MCP 端点就绪：http://127.0.0.1:2870/mcp
[I] gwb-mcp token（仅本机使用，勿外传）：<43 个字符>
```

**这一版没有界面，日志就是 token 唯一的示人出口**（另一条是命令 `mcp.info`，
但那得先有办法调命令）。

token 落在 `<home>/data/@godcreator02/gwb-mcp/token.json`，形状 `{ token, createdAt }`。
重启沿用，不会每次换一个。

## `mcp.info` 回的是一段能照抄的配置

{/* ref file="../plugins/mcp/src/endpoint.ts" lines="72-80" */}

除了 `url` / `port` / `token` 三样散件，`mcp.info` 还回一个 `mcpServers`——形状就是
Claude Code 那份 `.mcp.json` 里的一条 http server，**原样贴进客户端配置就能连**。

给散件也给拼好的那一份，是因为**拼装那一步本来是每个客户端各拼一遍的**：scheme 写成
`sse`、header 漏了 `Bearer ` 前缀、url 少了 `/mcp` 一段——三种都拼得出来，而症状全是
「连不上」，从客户端那头看不出为什么。拼好的这份把那些机会一次收掉。

{/* ref file="../plugins/mcp/src/index.ts" lines="349-369" */}

命令自己的顺序是**端口先答**：这道口没开成时回 `ok: false` 说清楚原因，而不是回一个
连不上的 url。下一节就是它最常见的那一种。

## default 的口是契约，不是首选

{/* ref file="../plugins/mcp/src/endpoint.ts" lines="50-58" */}

**`default` 这个 home 认死 2870，被占就不开这道口。**

原来的写法是「首选 2870，被占退让到系统随机口」，退让本身看着很合理——多 home 同开
是常态。危险的是这条时间线：**一台测试 home 先起来占住 2870，随后起的 default 退让到
随机口**。连工作台的 agent 会话手上那份 `.mcp.json` 早就写死了 2870，于是它连上的是
**那台测试 home**——命令面、数据、说明书全是另一套，而两头都不报错。

所以 default 那一支的 `fallback` 是 `false`，接线照着它走：

{/* ref file="../plugins/mcp/src/index.ts" lines="306-321" */}

**不开比开在别处强**——开在别处是静默连错，不开是当场看得见（一行 `log.error`，
外加 `mcp.info` 回 `ok: false`）。本件其它部分照常挂着，只是这道口这次没开。

其它 home 不吃这条：默认要系统随机口（没有哪个串是它的契约），显式给了 `config.port`
才试那个口、被占照旧退让并 warn。home 名从 `gwbKernel.dataDir` 的末段认——那个目录就是
home 目录，件不必另有一条「你是谁」的入口。

## 工具面只有两件

{/* ref file="../plugins/mcp/src/index.ts" lines="179-254" */}

**没有逐条门牌**：命令注册表随装了哪些件而变，没有一张固定清单，所以给的是
「看清单」加「按名字调」这一对。旧线做过五件精选直通，后来发现它们不比
`gwb_cli_run` 多任何能力，只是多了几条要维护的常驻描述。

业务失败（命令不存在、参数不对）回的是 `isError` 的文本，**不是协议错误**——
agent 读得到原因、连接不断。抛出去只会让对面看见一条 JSON-RPC 错误，
分不清是自己叫错了还是这台工作台坏了。

## 为什么自己起 `node:http`

三条路都看过：

- **`@cordisjs/plugin-http`** —— 它是 **HTTP 客户端**（`ctx.http`，axios 风格），
  收不了请求。内核仓 roadmap 那条「装官方的 plugin-http/plugin-server」把两者混为一谈了
- **`@cordisjs/plugin-server`** —— 能用，`ctx.server` 拿得到原始 `req._req` / `res._res`。
  但它最后一次发布早于 cordis `4.0.0-rc.9` 两个半月，属于「semver 说行、作者没验过」
- **拆一个 `gwb-http` 件出来**（旧线的做法）—— 一个宿主一个 server、谁要挂路由谁来注册。
  职责分得正，但**这个 server 上眼下就只有本件一个客户**

于是自己起，就在 `apply` 里。真出现第二个要开口的件，那时再拆——那一刀只动本件内部，
不动任何跨件契约。

## 无状态：每请求一对

{/* ref file="../plugins/mcp/src/index.ts" lines="256-267" */}

`new StreamableHTTPServerTransport({})` 里那个空对象就是无状态：不给
`sessionIdGenerator`，每个请求现造一台 `McpServer` 加一条 transport，随响应关闭。

好处是工具面永远是**此刻**的——热挂上来的件当场就在清单里。
代价是**发不出 list_changed 那类通知**：正连着的 agent 要等下一次重连才知道多了什么。
认下这个代价，为一条通知改成有状态不划算。

## instructions：每个 agent 连上来都要读的那段

固定那半是包根一份真的 markdown，模块加载时读一次；动态那半（此刻挂着的 skill 清单）
才由 `skills.ts` 现拼。**它是每会话的固定成本**——skill 一多、话一长，这段就变成一页
白占上下文的废话，所以两半都按「少一句就漏事、多一句就是废话」裁。

{/* ref file="../plugins/mcp/instructions.md" */}

固定那半里有一条不写就会出事的：**这道口是无状态的，agent 自己新装的件不会长出新的
顶层工具**（上一节那个代价）。不说明白，它装完件就会在工具清单里干等，而清单永远
不会变——写清楚了它才知道该走 `gwb_command_list` / `gwb_command_run`，或者重连。

后半段是**这台工作台准许 agent 改自己到哪儿**：修 bug、补 `SKILL.md`、加命令加件不用
问；改内核、改那七件被别人 `inject` 的契约面或依赖先问人。判据是**改动的爆炸半径**——
前一类错了只波及它自己，后一类错了是整台工作台起不来或者别的件静默失灵，而 agent
在自己的会话里看不见那个半径。

{/* ref file="../plugins/mcp/src/skills.ts" lines="56-77" */}

「说明书在 `skill://gwb/<名>/SKILL.md` 里，动手前先读对得上的那份」这句在**动态那半**，
不在固定那半：这个 home 一份 skill 都没挂时，那句话读了也无处可去。

## 一道门，不是两道

{/* ref file="../plugins/mcp/src/index.ts" lines="130-152" */}

token 拿不到 503、鉴权不过 401、不是 POST 405，三段之后才轮到正事。

**「没给 token」与「给错 token」的响应逐字相同**——拒绝面一旦有差别，就是在给外面
一个试探面。实机两发对比过。503 的 body 也不带原因（未鉴权的请求不该从错误文本里
读出这台机器的情况），真原因走 `mcp.info` 与日志——问那条命令的人本来就在本机。

比较本身走 `timingSafeEqual`，而且**长度先判**：不让时序侧信道透出前缀。

## 取令牌存的是 promise，不是值

{/* ref file="../plugins/mcp/src/index.ts" lines="109-123" */}

首启那次要异步落一份盘，而路由一挂上去随时可能进请求。存值的话，两个并发请求会各
生成一个 token 互相盖掉；存 promise，先到的请求等的就是同一次首启。

失败之后把它置空,下一次请求重来一遍——盘一时写不进去不该把这条口永久钉死在 503 上。

## 依赖那 4.3MB

官方 SDK 的 `dependencies` 拖着 express@5、hono、cors、jose、ajv、eventsource、
express-rate-limit 一串，解包 4.3MB、693 个文件，跟着这个件全装进 home。

摆上桌算过：换成自写一份最小 JSON-RPC（只做 initialize / tools/list / tools/call）
是百来行、零依赖，但协议细节（版本协商、Accept 校验、错误码）得自己跟，
而客户端的实际行为是唯一裁判。第一版求的是**能连通**，所以用 SDK。

写成 `dependencies` 而不是 `peer`：这个件没有导出面（不 provide 服务、没人 import 它的
类型），没有「消费方必须解析得到」这回事。

## 安全边界

**持 token 就拿到写面**：`gwb_cli_run` 能调的是完整的命令注册表，包括往 home 里装件。
这个系统的信任模型是两层——**装件 = 授权**（件在宿主进程里有完整 Node 权限，无沙箱），
**token 给谁 = 授权**（持 token 的 agent 等同一个远程的你）。

绑 `127.0.0.1`，不对外。命令级的拒绝名单这一版不做。
