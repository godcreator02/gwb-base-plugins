# gwb-mcp

把 [`ctx.gwbCommands`](/docs/commands) 那份命令注册表开给任意外部 agent。方向**永远**是
agent → 工作台。

包名 `@godcreator/gwb-mcp`，无界面。`inject: ['gwbCommands', 'gwbSettings']`
——settings 是硬依赖，端口从它来。

> 时间线：2026-09-13 搁置（「HTTP 门接班」），同日复位成唯一的门（「MCP 复位」），
> 工具面当日从两枚重设计为三枚（「三枚面」）。command-http 2026-09-17 退役（「command-http
> 退役」），不再有第二个入口；门出问题时怎么走写在随包 SKILL.md 的「门出问题时」一节。

## 怎么连

起来之后日志里有一行：

```
[I] gwb-mcp MCP 门就绪（default home）：http://127.0.0.1:2870/mcp——无鉴权，绑 127.0.0.1 本机自用
```

另一条出口是命令 `mcp.info`——url 加一段可照抄进客户端配置的 `mcpServers` 片段：

{/* ref file="../plugins/mcp/src/index.ts" lines="344-369" */}

无鉴权：口只绑 127.0.0.1、服务本机，本机进程本就同权——command-http 0.2 摘
token 时验过的判据，复位时原样继承。

## 工具面封顶三枚

{/* ref file="../plugins/mcp/src/index.ts" lines="93-149" */}

**`index`**（地图：全部命令与全部说明书，各带一句话）、**`search`**（按址取详情与兜底
搜索，命中行带 usage；裸调＝全貌全用法）、**`run`**（按名调一切命令）。写死在
`registerTools` 里，没有运行时名单，登记方也没有申报顶层的字段——top 随 commands 0.3
退役。其余命令（包括 `skill.list` / `skill.read`）一律经 `run` 按名调。

为什么封顶：MCP 的工具清单是**连接时的快照**，而这台工作台的件以分钟级热重挂为节拍
——任何「件登记、门渲染成顶层工具」的通道都会把快照变成重连债。封顶之后快照里没有
会变的东西：命令面的多变全在 `run` 的参数里，每次调用现打总线，与件的热重挂同一个
新鲜度。

**封顶的粒度**：加一枚工具是 **major** 级协议变更；给现有枚加可选参数是 **minor**
（老调用方不受伤）；**改回执形状或参数语义是 major**。守卫是测试——内存信道连一对
真的 server/client 按协议往返，`tools/list` 恰好这三枚，多一枚 CI 就红。

## 渐进式：索引 → 按址取件，搜索是兜底

{/* ref file="../plugins/mcp/src/inventory.ts" */}

| 要什么 | 调什么 | 成本 |
| --- | --- | --- |
| 地图（每会话第一调） | `index` 裸调 | 约两千 token |
| 全貌全用法（陌生 home 深度进场一次） | `search` 裸调 | 约八千 token |
| 一角带用法（干活途中 / 忘了名字） | `search` 带 `plugin` / `prefix` / `q` | 数百 token |
| 执行 / 读手册正文 | `run` | 视命令 |

四条硬规矩长在纯函数里：**两表同形**（index 的命令行与手册行都是 名字+插件+一句话，
`description` 与 skill 的 description 同义——导航触发文本，不是参数文档）；**命中行恒带
usage**（行形状不随条件变——这是对旧 surface「一 tool 多模式」的根治）；**裸调＝不过滤**
（语义自洽：不带条件就是全量，代价提示写死在工具描述里）；**谁也不捎全表**（`prefix` 是
命令域意图，此时说明书表只回瘦身行——「一条定向查询捎回 11.6KB 全表」那课的封口）。
`q` 对命令**连 usage 一起搜**——概念常住在用法里（「venv 自愈」在名字里搜不到）。

**files 不投影**：手册的附件地址归 SKILL.md 正文自己管（正文引用 references/ 是
Agent Skills 的惯例），门侧再列一份是第二份真相、会漂。`skill.read {name, file}` 一直
能用，地址从正文来；写手册的纪律因此多一句「附件必须在正文里提到」。

参数形状不在 `run` 的 schema 里，在命令的 **usage** 里——`args` 是 `z.unknown()`，协议层
放行、命令自己校验。有的客户端把嵌套对象序列化成 JSON 字符串才发，门在入口收一道：

{/* ref file="../plugins/mcp/src/tools.ts" lines="23-55" */}

业务失败（命令不存在、参数不对）回 `isError` 的文本，**不是协议错误**——agent 读得到
原因、连接不断。

## 说明书：清单进 index，正文走 run

清单（一句话）进 `index` 的 `skills` 项；正文经 `run` 调 `skill.list` / `skill.read`
（skills 件登记的命令）。skills 件不在时门照开，清单那格是空表。门自己也带一份
SKILL.md（连接片段、封顶判据与粒度、台没起怎么办），经 skills 件挂载。

## default 的端口是契约，不是首选

{/* ref file="../plugins/mcp/src/endpoint.ts" lines="54-67" */}

**`default` 这个 home 认死 2870，被占就不开这道门。**（mcp 时代的契约，随复位收回。）

「首选 2870、被占退让」看着体面——多 home 同开是常态——但危险的时间线是：一台测试
home 先起来占住 2870，随后起的 default 退让到随机端口，而 agent 会话手上那份配置早就
写死了 2870——它连上的是**那台测试 home**，命令面、数据、说明书全是另一套，两头都不
报错。所以 default 那一支 `fallback` 是 `false`：

{/* ref file="../plugins/mcp/src/index.ts" lines="305-314" */}

**不开比开在别处强**——开在别处是静默连错，不开是当场看得见：

{/* ref file="../plugins/mcp/src/index.ts" lines="332-342" */}

其它 home 不吃这条：缺省系统随机口（没有哪个串是它的契约），显式给了端口才试那个、
被占照旧退让并 warn。home 名从 `gwbKernel.dataDir` 的末段认。

## 端口是一项设置，不是 `cordis.yml` 的 config

**插件的配置一律走 `gwbSettings.define`**，这个插件不收 `apply` 的 `config` 形参：

{/* ref file="../plugins/mcp/src/index.ts" lines="158-176" */}

`port` 的缺省按 home 名给，跟 `choosePort` 不给值时的答案一致——界面上看到的缺省就是
真会用的端口。设置插件不做运行时校验，`choosePort` 收 `unknown`：不是整数、出了范围
一律当没给。改了要重启这个 home 才生效——门是 `apply` 时开的。

## 绑成那一刻补 runtime.json 的 `mcp` 项

{/* ref file="../plugins/mcp/src/runtime.ts" */}

内核开机整份重写 `pid` / `startedAt` / `appDir` / `cdp` 四项，本插件绑成之后**读改写**
补自己那一项。三条边界：**没绑成不写**、**写失败不影响这道门**、**进程退了不删**
——验活是读的人的事（核 pid 还在、且那个 pid 真持着那个端口）。

## 无状态：每请求一对

{/* ref file="../plugins/mcp/src/index.ts" lines="260-281" */}

`new StreamableHTTPServerTransport({})` 里那个空对象就是无状态：不给
`sessionIdGenerator`，每个请求现造一台 `McpServer` 加一条 transport，随响应关闭。
发不出 list_changed 那类通知——工具面封顶之后这无所谓：清单里没有会变的东西，客户端
等不到通知也不会错过任何事。（SDK 会把 `listChanged` 能力位广告成 `true`；「可能发通知」
语义上不排斥「永远不发」，不值得为它掏私有格去改。）

## instructions：固定三十行内，每个 agent 连上来都要读

{/* ref file="../plugins/mcp/instructions.md" */}

包根一份真的 markdown，模块加载时读一次，**不随挂着的 skill 变**。它是每会话的固定
成本，测试钉着行数上限。initialize 时白送一份；`index` 的回执再带一份——客户端不透出
initialize 的 instructions 通道时，第一调 index 也读得到纪律。

有两条不写就会出事：**工具面封顶、新装的件不长新工具**（不说明白，agent 装完件就在
工具清单里干等）；**台没起时怎么办**（工具全灰不是协议错误：起台、重连——MCP 没有
「下一发请求自动好」）。后半段是**这台工作台准许 agent 改自己到哪儿**，判据是改动的
爆炸半径；**破封顶先问人**与改内核、动被 inject 的面并列。

## 为什么自己起 `node:http`

- **`@cordisjs/plugin-http`** —— HTTP **客户端**（`ctx.http`），收不了请求
- **`@cordisjs/plugin-server`** —— 能用，但最后一次发布早于 cordis `4.0.0-rc.9`
  两个半月，「semver 说行、作者没验过」
- **拆一个 server 插件**——职责分得正，但这个 server 上只有本件一个客户

于是自己起，就在 `apply` 里。真出现第二个要开口的件，那时再拆。

## 依赖那 4.3MB

官方 SDK 的 `dependencies` 拖着 express@5、hono、cors、jose、ajv 一串，解包 4.3MB、
693 个文件，跟着这个插件装进装它的 home（default 装回是复位装配的一部分；隔离 home
的底座件集里没有门）。换成自写最小 JSON-RPC 是百来行、零依赖，但协议细节（版本协商、
Accept 校验、错误码）得自己跟，而客户端的实际行为是唯一裁判。求的是**能连通**，所以
用 SDK。写成 `dependencies` 而不是 `peer`：这个插件没有导出面。

## 安全边界

**本机的进程就拿到写面**：`run` 能调的是完整的命令注册表，包括往 home 里装插件。
工具面收窄收的是**发现面**，不是权限面。信任模型：**装插件 = 授权**（插件在宿主进程里
有完整 Node 权限，无沙箱），**口不出本机**（绑 127.0.0.1）。命令级的拒绝名单不做；
「用户同意」只能是纪律——写进 instructions，不做成机制。
