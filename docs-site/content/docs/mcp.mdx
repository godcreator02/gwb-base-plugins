**本页回答**：MCP 插件 `@godcreator/gwb-mcp` 管什么、刻意不知道什么；它在内存和磁盘上各记着什么；它提供哪些接口、依赖哪些接口；不启动工作台怎么测它；代码从哪读起。HTTP 与鉴权的约定写在接缝页[MCP 协议](/docs/seams/mcp-protocol)，三个工具的内容从哪来、回执怎么翻译写在[命令表开给 agent](/docs/seams/agent-surface)。

## 管什么

**一个只给外部 agent 用的 HTTP 端点。** 页面走内核的 IPC，要真的 HTTP 的只有外部 agent，所以这个插件不提供服务，在 `apply` 里自己用 `node:http` 开端点。`apply` 就是整个插件的装配顺序：取 home 名与端口、取 token、跟踪说明书插件、生成三个工具的处理函数、开 HTTP 服务、登记三条命令、卸载时关服务：

{/* ref file="../plugins/mcp/src/index.ts" lines="421-452" */}

**三个工具，写死在 `registerTools` 里。** `index` 给全部说明书与按包名分组的命令名，`search` 按条件给命令用法，`run` 按名字调任何命令。MCP 的工具清单是连接时的快照，而插件在运行中装上、升级、停用；命令的变化全在 `run` 的参数里，所以工具以后也不增加（轨迹卡[三个工具](/trajectory/2026-09-14-three-tool-face)、[MCP 复位](/trajectory/2026-09-14-mcp-returns)）。处理函数每次调用都从命令总线与说明书插件现取清单：

{/* ref file="../plugins/mcp/src/index.ts" lines="205-228" */}

`run` 的回执要翻译成 MCP 工具结果：命令失败回带 `isError` 的文本，不是协议错误；命令行工具的回执与处理函数自己返回的带 `ok` 的对象原样转成文本。翻译规则在 `src/tools.ts`，逐条写在[命令表开给 agent](/docs/seams/agent-surface)。

**每个请求新建一个 server 与一条 transport，随响应关闭。** 无状态：没有会话，也就发不出清单变更通知。构造 server 时声明 `tools.listChanged: false`，SDK 的 `registerTool` 会把它改成 `true`，客户端在 initialize 里看到的是 `true`，实际从不发通知：

{/* ref file="../plugins/mcp/src/index.ts" lines="230-252" */}

**请求在派发之前过三项检查**：token、Host、Origin，任何一项不过回 401 并写一条 warn。token 每个 home 一份，存在 `<home>/mcp/secret.json`，重启不换；凭据文件取不出来时入口照开、所有请求一律 401，不退回成不检查：

{/* ref file="../plugins/mcp/src/index.ts" lines="254-274" */}

{/* ref file="../plugins/mcp/src/index.ts" lines="162-179" */}

**端口按 home 名定。** 端口是本插件自己声明的设置项 `port`，缺省按 home 名给：default 固定 2870，被占就不开入口、不换端口；其他 home 缺省由系统分配，显式给了端口而被占时改用系统分配的端口：

{/* ref file="../plugins/mcp/src/endpoint.ts" lines="39-47" */}

default 被占时不换端口，是因为连着 default 的 agent 会话把 `http://127.0.0.1:2870/mcp` 写进了自己的配置：一个测试 home 先启动占住 2870、default 换到别的端口的话，会话连上的是那个测试 home，命令、数据、说明书全是另一套，两边都不报错；不开入口的话马上能看出来。

**绑定成功后把端口写进 home 的 `runtime.json`**：读出整份、只改 `mcp` 一项、写回，内核写的其余字段原样保留；写失败只记 warn，入口照常服务：

{/* ref file="../plugins/mcp/src/index.ts" lines="304-315" */}

**三条命令**：`mcp.info` 回连接信息与可以照抄进客户端配置的片段，`mcp.token` 取当前 token 或换一份新的，`mcp.client` 是包里 `bin/client.mjs` 经 node 命令行运行插件登记成的命令。两条凭据命令的回执带明文 token，会进调用方的会话记录，这一点写在 `usage` 里。

**每次 agent 调命令都写一行日志**：命令总线的日志里看不出是 agent 调的，这里补一行，成功写 info，失败写 warn 并带原因：

## 不知道什么

**不 import 别的插件的运行时代码。** 命令总线、设置、说明书、node 命令行运行插件都只 `import type {}`，为的是让 `ctx` 上的服务有类型；构建产物是一个打包好的 `dist/index.js`，里面的包名 import 只有 node 内置模块：

{/* ref file="../plugins/mcp/src/index.ts" lines="11-15" */}

**不认识命令行运行插件的回执类型。** 它按键名认出这种回执，只声明用得到的字段，不依赖 node-cli、py-cli 两个包；那边改了键名，这边的类型检查发现不了（写在[命令表开给 agent](/docs/seams/agent-surface)的「靠约定」里）：

{/* ref file="../plugins/mcp/src/tools.ts" lines="38-53" */}

**不知道谁在调、不分命令权限。** 本机拿到 token 的进程能调全部命令，包括往 home 里装插件；装插件等于授权，插件在主进程里没有沙箱。「哪些事先问人」只写进 `instructions.md`，不做成机制。

**不知道装了哪些插件。** `index` 里只有说明书与命令；装了哪些插件（包括没有命令的界面插件）由插件管理的 `plugin-manager.list` 回答。

**不替客户端写配置、不管客户端的超时。** `mcp.info`、`mcp.token` 只给片段；`run` 一直等到命令返回，超时在客户端配（`mcp.client` 用 `--timeout`）。

**不对本机以外开放。** 只绑 127.0.0.1，不提供 HTTPS：

## 提供的接口

| 接口 | 做什么 | 契约在 |
| --- | --- | --- |
| 端点 `POST http://127.0.0.1:<端口>/mcp` | 无状态 streamable HTTP；请求头 `Authorization: Bearer <token>`，Host、Origin 只认本机回环地址；别的路径 404，非 POST 405 | [2 MCP 协议](/docs/seams/mcp-protocol) |
| initialize 返回的 `instructions` | 包根 `instructions.md` 全文 | [2 MCP 协议](/docs/seams/mcp-protocol) |
| 工具 `index`、`search`、`run` | 说明书与命令名清单；按 `plugin`、`prefix`、`q` 筛选、带用法；按名字调命令 | [3 命令表开给 agent](/docs/seams/agent-surface) |
| 命令 `mcp.info`、`mcp.token` | 连接信息与配置片段；取当前 token 或 `{"rotate":true}` 换一份 | [2 MCP 协议](/docs/seams/mcp-protocol) |
| 命令 `mcp.client` | `bin/client.mjs` 登记成的 node 命令行工具，参数 `{"args":[…]}` | [9 命令行工具](/docs/seams/cli) |
| 文件 `<home>/mcp/secret.json`、`<home>/runtime.json` 的 `mcp` 项 | token；实际端口与地址，别的程序说出 home 名就能找到入口 | [2 MCP 协议](/docs/seams/mcp-protocol) |
| 设置项 `port`（本插件自己的设置分区） | 缺省 default 2870、其他 home 0；改了要重启这个 home 才生效 | [5 设置](/docs/seams/settings) |
| 说明书 `mcp` | 包根 `skills/mcp/`：连接配置、为什么只有三个工具、工作台没启动时怎么办 | [4 说明书](/docs/seams/skills) |

## 怎么单独测

八个测试文件，都在 `plugins/mcp/tests/`，前六个是纯函数：

- `auth.test.ts`：凭据文件生成、坏文件改名另存、换发；`Bearer` 前缀的解析；三项检查各自的放行与拒绝，token 长度不同也不抛；换发之后旧 token 立刻不认
- `endpoint.test.ts`：home 名取末段、端口的决定（default 被占不换、配置写坏当没给、数字串也认）、`mcp.info` 的片段与 `mcp.token` 的逐字一致
- `inventory.test.ts`：`index` 与 `search` 的生成规则，描述超过 200 字才截，`index` 的返回同样输入逐字节一致、现实规模下不超过 18KB
- `tools.test.ts`：参数字符串的解析、三种回执形状的翻译
- `runtime.test.ts`：只改 `mcp` 项、别的字段原样留着、文件坏了从空对象起
- `server.test.ts`：用 SDK 的内存传输连一对真的 server 与 client，`tools/list` 恰好是三个；`instructions.md` 的长度与两句话

**`apply.test.ts` 装上整个插件测**：真 cordis 上下文，内核、命令总线、设置用替身，home 是系统临时目录下的一个目录，用真端口、真 HTTP 请求与 SDK 的客户端：

{/* ref file="../plugins/mcp/tests/apply.test.ts" lines="72-87" */}

证明的是：声明 `port` 设置、登记两条命令；第一次装上生成 token；`runtime.json` 只补 `mcp` 项；三种 401、404、405；经 MCP 协议调 `run` 带着 `{ via: 'mcp' }` 到达命令总线并写日志；换 token 立刻生效；有说明书插件与 node 命令行运行插件时各登记一样；非 default home 的端口被占时换端口；default 的 2870 被占时不开入口、两条命令回失败；卸载时关掉 HTTP 服务。

**`artifact.test.ts` 查构建产物**：只有打包出来的 `index.js`，没有相对 import，包名 import 只有 node 内置模块。

`bin/client.mjs` 没有单元测试；MCP 入口拿到的是运行中真的命令表与说明书清单，这一段只能在隔离 home 里验证。

**先读** `src/index.ts` 末尾的 `apply`：装配顺序一眼看完，再按需要跳到各部分。
