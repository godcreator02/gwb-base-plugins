**本页回答**：MCP 插件有哪些功能；agent、客户端配置和别的程序经哪些接口用它，各属于哪条接缝；它依赖什么、缺了会怎样；哪些事常被以为归它、其实归命令总线或别的插件。包名 `@godcreator/gwb-mcp`，源码目录 `plugins/mcp/src`，入口文件 `index.ts`。

MCP 插件是工作台唯一的对外入口，方向只有 agent 调工作台一种。它不提供服务，自己启动 `node:http`。

## 功能

- **开一个 MCP 入口**：`http://127.0.0.1:<端口>/mcp`，只收 POST，无状态：每个请求新建一个 MCP server 和一条 transport，响应结束就关
- **工具只有三个，以后也不增加**：`index` 给全部说明书与命令名的清单，`search` 按条件取命令用法，`run` 按名字调任何命令；新装的插件不会多出新工具，它的命令经 `run` 调
- **每次调用都现取命令表与说明书**：插件在运行中装上、升级、停用，下一次 `index` 就反映出来
- **要 token**：每个 home 一份，写在磁盘上、重启不换；另外检查 `Host` 与 `Origin`，三项都在处理请求之前检查，不通过就回 401 并写明原因
- **default 固定用 2870 端口**：端口被占就不开入口，不换端口；其他 home 缺省用系统分配的端口
- **把端口写进 home 的 `runtime.json`**：绑定成功后补上 `mcp` 一项，别的程序说出 home 名就能找到入口
- **每次 agent 调命令都写一行日志**：成功写 info，失败写 warn 并带原因
- **连接信息与 token 用命令取**：`mcp.info`、`mcp.token`；另带一个零依赖的命令行客户端，没有 MCP 客户端的环境也能调
- **带一份说明书 `mcp`**：连接配置、为什么只有三个工具、工作台没启动时怎么办

## 接口

每条接缝上交换什么、各方保证什么，写在接缝页；本节只列 MCP 插件提供了哪些接口、定义在哪里。

### MCP 入口

| 接口 | 做什么 | 接缝 |
| --- | --- | --- |
| 端点 `POST http://127.0.0.1:<端口>/mcp` | 无状态 streamable HTTP；别的路径回 404，非 POST 回 405；能力位 `tools.listChanged` 为 `false` | [2 MCP 协议](/docs/seams/mcp-protocol) |
| 请求头 `Authorization: Bearer <token>` | 也认只写 token 本身的写法；缺了或对不上回 401 | [2 MCP 协议](/docs/seams/mcp-protocol) |
| 请求头 `Host`、`Origin` | `Host` 必须是 `127.0.0.1:<端口>` 或 `localhost:<端口>`；带了 `Origin` 就必须是这两个地址的 `http://` 形式，`null` 不认；不带 `Origin` 的非浏览器客户端照常放行 | [2 MCP 协议](/docs/seams/mcp-protocol) |
| initialize 返回的 `instructions` | 包根 `instructions.md` 的全文，加载时读一次 | [2 MCP 协议](/docs/seams/mcp-protocol) |

`instructions.md` 是每个会话的固定开销，测试检查它不超过 2000 字符、41 行（Claude Code 超过 2048 字符会不提示地截断），并且还写着「只有三个工具」与「不带参数就返回全部」这两句。

### 三个工具

| 工具 | 参数 | 返回 | 接缝 |
| --- | --- | --- | --- |
| `index` | 无 | `home`（home 名）、`version`（本插件的版本）、`instructions`、`skills`（每份说明书的名字、所属插件、描述，描述超过 200 字才截断）、`commands`（按插件包名分组、只有命令名）、`hint`（下一步去哪查） | [3 命令表开给 agent](/docs/seams/agent-surface) |
| `search` | `plugin?`（精确包名）、`prefix?`（命令名前缀）、`q?`（在名字、一句话介绍、用法里找子串，不分大小写） | 匹配的命令，每条带 `usage`；匹配的说明书；只给 `prefix` 时说明书只回名字与插件；不带参数就返回全部 | [3 命令表开给 agent](/docs/seams/agent-surface) |
| `run` | `command`、`args?` | 命令的回执转成文本；命令失败（不存在、参数不对）回 `isError` 的文本，不是协议错误 | [3 命令表开给 agent](/docs/seams/agent-surface) |

{/* ref file="../plugins/mcp/src/index.ts" lines="110-166" */}

三个工具写死在 `registerTools` 里，没有运行时名单，登记命令的一方也没有「放成顶层工具」的字段。测试用内存传输连一对真的 server 与 client，`tools/list` 必须恰好是这三个。**变更的级别**：加一个工具是 major 级协议变更，给现有工具加可选参数是 minor，改返回形状或参数语义是 major。

`run` 的参数形状不在工具的 schema 里（`args` 是 `z.unknown()`），在那条命令的 `usage` 里，命令自己校验。有的客户端把对象参数序列化成 JSON 字符串再发，`run` 收到字符串先试着 `JSON.parse`，解析成功用结果，失败原样交给命令。回执的转换：

- 普通回执 `{ ok, data }` 转成 JSON 文本；`ok` 为 `false` 时回 `isError` 的文本 `执行失败：<原因>`
- 回执除了 `ok`、`data`、`error` 还有别的字段（处理函数自己返回的带 `ok` 的对象），原样转成 JSON 文本
- 命令行运行插件的回执只留 `ok`、`exitCode`、`timedOut`、`durationMs`、`stdout`、`stderr` 六项

### 命令

| 命令 | 做什么 | 接缝 |
| --- | --- | --- |
| `mcp.info` | 无参数，返回 `{ url, port, mcpServers, auth }`：`mcpServers` 是可以照抄进客户端配置的片段，含 `type`、`url` 与请求头 `headers: { Authorization: 'Bearer <token>' }`，token 是当前那份，与 `mcp.token` 取的是同一个，只读不换；`auth` 写明 token 存在哪个文件、怎么换。入口没开或凭据文件取不出来时回失败并写明原因。**回执里是明文 token，会进调用方的会话记录** | [1 命令总线](/docs/seams/bus) |
| `mcp.token` | 不给参数返回当前 token；`{"rotate":true}` 换一份新的，新 token 立即生效，旧客户端从此 401。返回 `{ token, file, rotated, mcpServers }`，`mcpServers` 与 `mcp.info` 的片段形状相同。**回执里是明文 token，会进调用方的会话记录** | [1 命令总线](/docs/seams/bus) |
| `mcp.client` | 包里 `bin/client.mjs` 登记成的 node 命令行工具：`{"args":["index"]}`、`["search", "<JSON 条件>"]`、`["run", "<命令名>", "<JSON 参数>"]`。地址取 `--url`、环境变量 `GWB_MCP_URL`，缺省 default 的 2870；token 取 `--token`、环境变量 `GWB_MCP_TOKEN`，缺省读 default home 的 token 文件；失败时退出码 1 | [9 命令行工具](/docs/seams/cli) |

### 写进 home 的文件与设置

| 接口 | 做什么 | 接缝 |
| --- | --- | --- |
| `<home>/mcp/secret.json` | `{ "token": "<32 字节随机数的 base64url>" }`；没有就生成；内容认不出时先改名成 `secret.json.broken-<时间戳>` 留着，再生成新的；取不出来时入口照开，所有请求一律 401 | [2 MCP 协议](/docs/seams/mcp-protocol) |
| `<home>/runtime.json` 的 `mcp` 项 | `{ port, url }`；绑定成功后读出整份、改自己这一项、写回，内核写的其他项原样保留；没绑定成功不写，写失败只记 warn，进程退出不删 | [2 MCP 协议](/docs/seams/mcp-protocol) |
| 设置 `port`（数字） | 缺省按 home 名给：default 是 2870，其他 home 是 0（系统分配）；改了要重启这个 home 才生效，入口在加载时打开 | [5 设置](/docs/seams/settings) |
| 说明书 `mcp` | 包根 `skills/mcp/`，交给说明书插件登记 | [4 说明书](/docs/seams/skills) |

**default 的端口被占时不换端口**：连着 default 的 agent 会话把 `http://127.0.0.1:2870/mcp` 写进了自己的配置。一个测试 home 先启动占住 2870、default 换到别的端口的话，会话连上的是那个测试 home，命令、数据、说明书全是另一套，两边都不报错；不开入口的话，马上能看出来。其他 home 设置里显式给了端口、端口被占时，换成系统分配的端口并写一条 warn。

## 依赖

| 依赖 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- |
| 命令插件的服务 `gwbCommands`（写在 `export const inject` 里，[gwb-commands](/docs/commands)） | `list()` 给 `index`、`search`；`run()` 给 `run`；登记 `mcp.info`、`mcp.token` | 插件一直等待、不加载，没有入口 |
| 设置插件的服务 `gwbSettings`（写在 `export const inject` 里，[gwb-settings](/docs/settings)） | 声明并读取 `port` 设置 | 插件一直等待、不加载，没有入口 |
| 说明书插件的服务 `gwbSkills`（局部注入，[gwb-skills](/docs/skills)） | `index`、`search` 里的说明书；登记自带的说明书 `mcp` | 入口照常开，`index` 与 `search` 里没有说明书 |
| node 命令行运行插件的服务 `gwbNodeCli`（局部注入，[gwb-node-cli](/docs/node-cli)） | 把 `bin/client.mjs` 登记成 `mcp.client` | 入口照常开，没有 `mcp.client` 这条命令 |
| 内核服务 `gwbKernel` 的 `dataDir`（内核仓 gwb-kernel；不写进 `inject`，经 `src/vocab.ts` 里的 `requireKernel` 取） | home 名（目录的最后一段）、token 文件、`runtime.json` 的位置 | 加载时抛错「ctx.gwbKernel 不在」 |
| `@modelcontextprotocol/sdk`（`^1.30.0`）、`zod`（`^4.5.4`），写在 dependencies | MCP 协议、工具参数的 schema | 无法加载；SDK 连同它的依赖解包约 4.3MB，跟着这个插件装进 home |
| 词汇表包 `@godcreator/gwb-plugin-api`（peer） | `GwbContext`、`GwbResult` 的类型 | 只在编译时用 |

`gwb-commands`、`gwb-settings`、`gwb-skills`、`gwb-node-cli` 写在 devDependencies 里：代码只 `import type {}` 它们，为的是让 `ctx` 上的服务有类型，构建产物里没有它们。SDK 与 zod 写在 dependencies 而不是 peer：这个插件不导出任何类型，没有「使用方必须解析得到」的问题。

## 不做的事

- **不加第四个工具**：命令的变化全在 `run` 的参数里；MCP 的工具清单是连接时的快照，插件在运行中重新加载时快照就过时了
- **不分命令权限**：本机拿到 token 的进程能调全部命令，包括往 home 里装插件；装插件等于授权，插件在主进程里没有沙箱。「先问人」只写进 `instructions.md`，不做成机制
- **不对本机以外开放**：只绑 127.0.0.1
- **不推送通知**：无状态，没有会话；三个工具不会变，客户端不需要清单变更通知
- **不列装了哪些插件**：`index` 里只有说明书与命令；装了哪些插件（包括没有命令的界面插件）问插件管理的 `plugin-manager.list`
- **不校验命令参数**：命令自己校验
- **不负责客户端的超时**：`run` 一直等到命令返回；客户端自己的超时在客户端配，`mcp.client` 用 `--timeout`
