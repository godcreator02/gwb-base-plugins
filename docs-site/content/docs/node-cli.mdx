**本页回答**：node 命令行运行插件有哪些功能；插件、页面和 agent 经哪些接口用它，各属于哪条接缝；它依赖什么、缺了会怎样；哪些事常被以为归它、其实不归它。包名 `@godcreator/gwb-node-cli`，源码目录 `plugins/node-cli/src`，入口文件 `index.ts`。

插件要运行一个命令行工具时，启动进程、时限、结束整个进程树、截断输出、编码这几样最容易写错，而且写错了不当场报错。这个插件把它们收在一处；它自己不带要运行的工具，工具是登记它的插件自己编译出来、随包发布的 js。

## 功能

- **登记命令行工具**：插件给一个名字和要运行的 js 的绝对路径，拿回注销函数；插件卸载时自动注销，不用自己包 `ctx.effect`
- **登记时就校验**：名字为空或带空白、js 路径不是绝对路径、时限不是正数或超上限，登记时就抛错——等到运行时才发现的话，报错的地方已经离登记的地方很远
- **登记的工具同时是命令总线上的命令**：命令名就是登记的名字，页面、agent、别的插件照调命令的办法调它；`usage` 没给时补上参数形状那一句，`effect` 照登记时给的写进总线命令。总线命令经调用方的上下文登记，命令总线认出的登记方是调用方；总线拒收（没写 `description`、`plugin` 不是调用方的包名、`effect` 不是 `read` / `write` / `external`）时撤掉表里那条，把错抛给调用方
- **用运行工作台的那个 node 启动**：程序是 `process.execPath`（工作台进程的 electron.exe），带上 `ELECTRON_RUN_AS_NODE=1`；不查 PATH、不读 `bin` 字段、不经过 shell，参数全程是数组，引号、空格、中文原样到达
- **工作目录**：按次给的优先，其次登记时给的，都没给就是那个 js 所在的目录；不用工作台进程自己的工作目录。按次给的必须是存在的目录的绝对路径，不合规时不启动进程，回一句说明要什么的 `{ ok: false, error }`
- **时限**：缺省 60 秒，登记时可以给到 2,147,483,647 毫秒（Node 定时器的上限，轨迹卡[显式超时](/trajectory/2026-09-21-explicit-cli-timeout)）；到时限在 Windows 上用 `taskkill /T /F` 结束整个进程树
- **输出只留尾部 64,000 字节**：超出时把全量写进系统临时目录的一个文件，回执里给路径——出错原因常常在被截掉的那头
- **同名后登记的生效**：写一条 warn；先登记的注销时不删接手的那条
- **启动与结束都写日志**：成功写 info，启动失败写 error，超时或非零退出写 warn 并带上 stderr 的尾部
- **带一份说明书 `gwb-node-cli`**：给 agent 讲怎么传参数、回执怎么读、长输出去哪找

## 接口

每条接缝上交换什么、各方保证什么，写在接缝页；本节只列 node 命令行运行插件提供了哪些接口。

<Diagram name="cli-run" title="node 命令行工具的登记、调用与回执（分步）">
- 登记方插件调 `ctx.gwbNodeCli.register({ name, entry, … })`，`entry` 是它随包发布的 js 的绝对路径；gwbNodeCli 同时用同一个名字调 `gwbCommands.register`，登记成总线命令
- 页面、agent、别的插件经 `gwbCommands.run(name, args)` 调它；按次给的 `cwd` 不合规就不启动进程
- gwbNodeCli 用 `process.execPath` 加 `ELECTRON_RUN_AS_NODE=1` 启动子进程，argv 是 `[entry, ...固定参数, ...追加参数]`，不经 shell
- 缺省 60 秒时限，到时限用 `taskkill /T /F` 结束整个进程树；输出只留尾部 64,000 字节，超出时全量写进系统临时目录
- 回执 `CliRunResult` 带 `ok`，命令总线原样返回给调用方
</Diagram>

| 接口 | 做什么 | 接缝 |
| --- | --- | --- |
| 服务 `ctx.gwbNodeCli` 的 `register(spec)` | `spec`：`name`、`entry`（js 的绝对路径）、`description?`（命令总线要求非空，不给登记会被拒）、`usage?`、`effect?`（总线命令的副作用标记，含义见 [gwb-commands](/docs/commands)，不写 agent 按 `write` 对待）、`args?`（固定参数）、`cwd?`、`env?`、`timeoutMs?`、`plugin?`（缺省是调用方的包名，给了也必须是调用方的包名）；类型 `NodeCliSpec` 由本包导出 | [9 命令行工具](/docs/seams/cli) |

| 登记出来的命令 | 参数给一个数组就是追加参数，给 `{ args?, cwd? }` 也认；回执带 `ok`，命令总线原样返回 | [1 命令总线](/docs/seams/bus) |

| 说明书 `gwb-node-cli` | 包根 `skills/gwb-node-cli/`，交给说明书插件登记 | [4 说明书](/docs/seams/skills) |

插件自己算出 js 的绝对路径再登记：

```ts
export const inject = ['gwbNodeCli']

const CLI_ENTRY = path.join(path.resolve(path.dirname(fileURLToPath(import.meta.url)), '..'), 'dist', 'cli.js')

export function apply(ctx: GwbContext) {
  ctx.gwbNodeCli.register({ name: 'mine.build', description: '运行我的构建工具', effect: 'write', entry: CLI_ENTRY, args: ['--json'] })
}
```

## 依赖

注入了哪些服务、peer 怎么写、缺了会怎样，以及用了哪些约定通道（从调用方上下文取命令总线、electron.exe 以 node 模式运行、`taskkill`、临时目录里的全量输出、和 gwb-py-cli 逐字相同的 `run.ts` 与 `invoke.ts`），见[插件之间怎么连](/docs/wiring#godcreatorgwb-node-cli)。

## 不做的事

- **不找程序**：不读 `bin` 字段、不认 `node_modules/.bin`、不查 PATH；js 的路径由登记方自己算好
- **不运行第三方 npm 包的 `bin`**：只运行登记方随包带的 js
- **不经过 shell**：参数不转义，也不支持管道、重定向；子进程的 stdin 是空的，不支持要交互输入的工具
- **不解释输出**：`stdout` 原样放进回执，结构化内容由调用方自己解析
- **没有自检命令、不带被运行的东西**：它只是运行器，工具对不对由登记它的插件验收
- **不分权限、不限调用方**：登记出来的命令和别的命令一样，谁都能调
- **不保存运行记录**：回执返回之后不留记录，只有超长输出的全量文件留在临时目录
- **不管调用方的超时**：MCP 客户端、HTTP 客户端的超时在调用方配，要比这里的时限长
