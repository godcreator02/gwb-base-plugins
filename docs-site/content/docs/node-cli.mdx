**本页回答**：node 命令行运行插件 `@godcreator/gwb-node-cli` 管什么、刻意不知道什么；登记表与回执是什么形状；它提供哪些接口、依赖哪些接口；不启动工作台怎么测它；代码从哪读起。登记方、子进程各保证什么写在接缝页[命令行工具](/docs/seams/cli)。

## 管什么

插件要运行一个命令行工具时，启动进程、时限、结束整个进程树、截断输出、编码这几样最容易写错，而且写错了不当场报错。这个插件把它们收在一处；它自己不带要运行的工具，工具是登记方自己编译出来、随包发布的 js。

**分为四个文件。** `registry.ts` 是登记表与登记时的校验；`invoke.ts` 解析总线参数、校验按次给的工作目录；`run.ts` 启动一次子进程、收输出、按时限结束；`index.ts` 是继承 cordis `Service` 的服务，认出登记方、转登记成总线命令、把三者接起来。`run.ts` 与 `invoke.ts` 在 [gwb-py-cli](/docs/py-cli) 里各有一份一字不差的副本。

**登记时就校验，同时登记成总线命令。** 名字为空或带空白、js 路径不是绝对路径、时限不是正数或超过 Node 定时器上限，登记时就抛错——拖到运行时才发现的话，报错的地方已经离登记的地方很远：

**用运行工作台的那个 node 启动。** 程序是 `process.execPath`（工作台进程的 electron.exe），带上 `ELECTRON_RUN_AS_NODE=1` 让它以 node 模式运行；argv 是 `[entry, ...固定参数, ...追加参数]`，不查 PATH、不经 shell，引号、空格、中文原样到达；工作目录依次取按次给的、登记时给的、js 所在目录，不用工作台进程自己的：

**按次给的工作目录先校验**：必须是存在的目录的绝对路径；不是字符串、是相对路径、目录不存在，三种各回一句说明要什么的 `{ ok: false, error }`，不启动进程、不抛错。经服务的 `run` 与经命令总线调用走的是同一段：

**时限与输出**：缺省 60 秒，登记时可以给到 2,147,483,647 毫秒（轨迹卡[显式超时](/trajectory/2026-09-21-explicit-cli-timeout)）；到时限在 Windows 上用 `taskkill /T /F` 结束整个进程树。stdout、stderr 各只在内存里留最后 64,000 字节，超出时把全量写进系统临时目录的文件、回执里给路径——出错原因常常在被截掉的那头。

**启动与结束都写日志**：成功写 info，启动失败写 error，超时或非零退出写 warn 并带上 stderr 的尾部：

**一条自己的命令 `node-cli.list`**，列出已登记的工具，登记在运行插件自己的上下文上。**带一份说明书 `gwb-node-cli`**，放在包根 `skills/gwb-node-cli/`，讲怎么传参数、回执怎么读、长输出去哪找。

## 不知道什么

**不找程序。** 不读 `bin` 字段、不认 `node_modules/.bin`、不查 PATH；js 的路径由登记方自己从 `import.meta.url` 算好。第三方 npm 包的 `bin` 不运行。

**不经过 shell。** 参数不转义，也不支持管道、重定向；子进程的 stdin 是空的，不支持要交互输入的工具。

**不解释输出。** `stdout` 原样放进回执，结构化内容由调用方自己解析；子进程不知道自己是被总线、MCP 入口还是别的插件调用的。

**不带任何被运行的东西、没有自检命令。** 它只是运行器，工具对不对由登记它的插件验收；包里只有 `dist`、`skills`、`src`，测试检查这一点：

{/* ref file="../plugins/node-cli/tests/artifact.test.ts" lines="54-62" */}

**不分权限、不保存运行记录。** 登记出来的命令和别的命令一样谁都能调；回执返回之后不留记录，只有超长输出的全量文件留在临时目录。

**不管调用方的超时。** MCP 客户端、HTTP 客户端的超时在调用方配，要比这里的时限长。

| 接口 | 做什么 | 契约在 |

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| 命令总线服务 `gwbCommands` 的 `register`（服务类上的 `static inject`） | 把登记的工具登记成命令；登记 `node-cli.list`；缺了服务 `gwbNodeCli` 不提供 | [gwb-commands](/docs/commands) | 只记登记的替身；另一组用按 `Service` 写的替身记下它认出的登记方，还有一个拒收的替身 |
| 说明书服务 `gwbSkills` 的 `register`（局部注入） | 登记自带的说明书；缺了不登记 | [gwb-skills](/docs/skills) | 不提供 |
| cordis 的 `Service`、`effect`、`get`、`logger` | 提供服务；方法里的 `this.ctx` 是调用方的上下文；经它取总线、登记注销 | 内核带的 cordis（peer `^4.0.0-rc.10`） | dev 里的 `cordis` 4.0.0-rc.10 |

| `process.execPath` 与 `ELECTRON_RUN_AS_NODE` | 当作 node 运行 js；不带这个环境变量 electron 会开一个应用，而不是运行 js | 工作台进程的 electron.exe | 跑测试的那个 node（它忽略这个变量） |

## 怎么单独测

六个测试文件，都在 `plugins/node-cli/tests/`：

- `registry.test.ts`：登记时补缺省值、固定参数拷一份、名字与 `entry` 与时限的拒绝条件、同名后登记的生效并告警、注销只删自己那条
- `invoke.test.ts`：总线参数的两种写法、`cwd` 原样带出不收窄、`checkCwd` 的三种拒绝（磁盘检查可以传入替身，也有一条真的查磁盘）
- `run.test.ts`：跑真的 node 子进程——退出码、参数不经 shell、`cwd` 与 `env`、超时结束进程、可执行文件不在时的回执、超长输出写临时文件
- `service.test.ts`：见下
- `artifact.test.ts`：相对 import 带 `.js`，包名 import 只有 `cordis`；包里只有 `dist`、`skills`、`src`

**`service.test.ts` 测服务这一层**：真 cordis 上下文，命令总线用替身；被运行的 js 是临时目录里一个把自己看到的 argv、工作目录、环境变量写到 stdout 的脚本：
