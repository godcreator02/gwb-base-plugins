# gwb-base-plugins

`gwb-kernel`（最小内核，单元 `26090705ymz`）的基础插件仓。

## 插件

| 插件 | 包名 | 服务 | 干什么 |
| --- | --- | --- | --- |
| commands | `@godcreator/gwb-commands` | `ctx.gwbCommands` | 命令总线 |
| data | `@godcreator/gwb-data` | `ctx.gwbData` | 插件的数据落盘 |
| logger | `@godcreator/gwb-logger` | `ctx.gwbLogger` | 日志管道（core） |
| skills | `@godcreator/gwb-skills` | `ctx.gwbSkills` | 说明书的收集与查询 |
| command-http | `@godcreator/gwb-command-http` | — | 命令的无状态 JSON 口，**搁置**（逃生门；入口由 mcp 复位接回） |
| mcp | `@godcreator/gwb-mcp` | — | MCP 门，**唯一的门**：工具面封顶 surface/run 两枚 |
| node-cli | `@godcreator/gwb-node-cli` | `ctx.gwbNodeCli` | node 那条命令行 |
| py-cli | `@godcreator/gwb-py-cli` | `ctx.gwbPyCli` | python 那条命令行 |
| settings | `@godcreator/gwb-settings` | `ctx.gwbSettings` | 设置 |
| plugin-manager | `@godcreator/gwb-plugin-manager` | `ctx.gwbPluginManager` | 管包与条目 |

三仓拆分后这个仓只剩**无头**插件：外壳与窗格的界面外观住 UI 平台仓
（`26091217uiz\gwb-ui-plugins`：shell、theme、baseui 与两个共享包）。验收位（hello 仓）
2026-09-13 已整体退役：装配态验收改由 devkit 模板现场生成（判据见 devkit 仓轨迹卡
「模板即插件」）。
此刻十个插件在册、九个在役：command-http 搁置（逃生门）、mcp 复位接班（判据见轨迹卡
「MCP 复位」）。

**状态与版本号只在[路线](/future/roadmap)一处**——两处各记一份必然漂移，这张表就漂过一轮。

`gwb-commands` 排第一不是随便定的：**内核的 `dispatch` 收到什么就全走 `ctx.gwbCommands`**，
没有它，界面调不到任何 node 侧的能力。

## 一个插件长什么样

```
plugins/<插件名>/
  package.json      name / exports / gwb 段 / peer 与 dev
  tsconfig.json     extends ../../tsconfig.base.json
  src/index.ts      export const name / apply(ctx)
  tests/            纯逻辑的单测 + 产物守卫
```

构建是 `tsc`，不打包——产物给 node 直接加载。所以有两条硬要求，都配了守卫：
**相对 import 必须带 `.js`**、**产物里不许有裸名 import**。为什么，见[撞过的墙](/docs/walls)。

带界面的插件**不在这个仓**——浏览器半、样式与组件的原理在 UI 平台仓那边。

## 母仓那批是参考，不是模板

废弃的插件仓在 `26090623hyz/gwb-plugins`。去查某个插件当初为什么那么做、踩过什么坑，值得；
**结构、分层、包划分一概不抄**。

它那套有几样这里明确不要：`gwb.minAppVersion` 与精确 peer 号的双份准入、`platform` 分区与
`window.confirm` 拦截、为具体某个插件写的硬编码分支。
