# gwb-base-plugins

`gwb-kernel`（最小内核，单元 `26090705ymz`）的基础件仓。

## 件

| 件 | 包名 | 服务 | 干什么 |
| --- | --- | --- | --- |
| commands | `@godcreator02/gwb-commands` | `ctx.gwbCommands` | 命令总线 |
| data | `@godcreator02/gwb-data` | `ctx.gwbData` | 件的数据落盘 |
| shell | `@godcreator02/gwb-shell` | `ctx.gwbShell` | dockview 外壳 + 窗格注册 |
| hello | `@godcreator02/gwb-hello` | — | 验收件兼样板，两格窗格 |
| logger | `@godcreator02/gwb-logger` | — | 日志窗格 |
| skills | `@godcreator02/gwb-skills` | `ctx.gwbSkills` | 说明书的收集与查询 |
| mcp | `@godcreator02/gwb-mcp` | — | 开一个 MCP 口给 agent 连 |
| node-cli | `@godcreator02/gwb-node-cli` | `ctx.gwbNodeCli` | node 那条命令行 |
| py-cli | `@godcreator02/gwb-py-cli` | `ctx.gwbPyCli` | python 那条命令行 |
| settings | `@godcreator02/gwb-settings` | `ctx.gwbSettings` | 设置 |

**状态与版本号只在[路线](/docs/roadmap)一处**——两处各记一份必然漂移，而这张表已经漂过
一轮（`cli` 停在 0.0.3、`shell` 还写着「待做」，实际那时它已经发到 0.0.4 了）。

`gwb-commands` 排第一不是随便定的：**内核的 `dispatch` 除两条自省命令外全走 `ctx.gwbCommands`**，
没有它，界面调不到任何 node 侧的能力。

## 两条命名规矩

**包名 `@godcreator02/gwb-<件名>`。** 加 `gwb-` 前缀跟已废弃的那批错开——
`@godcreator02/cli`、`/shell`、`/logger`、`/settings` 被那批占着。

**服务名一律 `gwb` 开头小驼峰**，默认跟件名对应（`gwb-commands` → `ctx.gwbCommands`）。cordis 官方件
的服务照它自己的（`timer`、`loader`），那不是这个生态的东西。

判据与理由在**内核仓的文档站**（`26090705ymz/gwb-kernel/docs-site`）——规则住那边，
这个站只记件自己的事。

## 内核给的面就这么大

- **`ctx.gwbKernel`**（永不撤销，用 `requireKernel(ctx)` 取，**不写进 `inject`**）：
  `dataDir` / `appVersion` / `install(specs)` / `emit(payload)`
- **`ctx.loader`**：条目树。改条目就是热挂卸——`create` / `remove` / `update` / `store`。
  自己所在的那棵树是 `ctx.fiber.entry?.parent?.tree`
- **两条内核命令**：`kernel.info`（自省）、`kernel.install`（装机）
- **`gwb://asset/plugins/<包名>/client.js`**：界面那半由这条 URL 交给页面

契约包 `@godcreator02/gwb-plugin-api` 只有五个名字（`GwbContext` / `GwbKernelApi` /
`GwbResult` / `requireKernel` / `isRecord`）。**内核的面本来就这么小**，别指望有更多。

## 一个件长什么样

```
plugins/<件名>/
  package.json      name / exports / gwb 段 / peer 与 dev
  tsconfig.json     extends ../../tsconfig.base.json
  src/index.ts      export const name / apply(ctx)
  tests/            纯逻辑的单测 + 产物守卫
```

构建是 `tsc`，不打包——产物给 node 直接加载。所以有两条硬要求，都配了守卫：
**相对 import 必须带 `.js`**、**产物里不许有裸名 import**。为什么，见[撞过的墙](/docs/walls)。

## 母仓那批是参考，不是模板

废弃的件仓在 `26090623hyz/gwb-plugins`。去查某个件当初为什么那么做、踩过什么坑，值得；
**结构、分层、包划分一概不抄**。

它那套有几样这里明确不要：`gwb.minAppVersion` 与精确 peer 号的双份准入、`platform` 分区与
`window.confirm` 拦截、为具体某个件写的硬编码分支。
