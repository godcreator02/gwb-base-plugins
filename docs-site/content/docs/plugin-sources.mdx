**本页回答**：插件来源插件有哪些功能；页面、agent 经哪些接口用它，各属于哪条接缝；它依赖什么、缺了会怎样；哪些事常被以为归它、其实归插件管理。包名 `@godcreator/gwb-plugin-sources`，源码目录 `plugins/plugin-sources/src`，入口文件 `index.ts`。

它回答两件事：配好的源上有哪些插件可装，从哪些源装。安装、卸载、升级与条目管理在插件管理 `@godcreator/gwb-plugin-manager`（devkit 仓 gwb-devkit），两个插件之间没有代码依赖：这里查到包名，交给 `plugin-manager.install` 去装。它不提供服务，只有四条命令。

## 功能

- **搜索可装的插件**：不给 scope 就查全部配好的源，两份 npmrc 里出现过的每个 scope 各查一次，并发进行；`@godcreator` 永远排第一，其余按名字排
- **一条源失败不影响别的**：查成的合并进结果，没查成的在 `note` 里写明是哪条源、为什么；全部失败才算失败
- **「是不是插件」只看包自己的 `keywords` 里有没有 `gwb-plugin`**：包名前缀不参与判断
- **从哪装就在哪搜**：registry 地址按 scope 从两份 npmrc 里找，和 pnpm 安装读的是同一批配置行，先找 `@scope:registry=`，再找 `registry=`，home 级优先于机器级，都没写就是 npm 官方源
- **往机器级 `~/.npmrc` 加一条包源**：同 scope 已有就原地替换；`registry` 直接给地址，或给 `owner` 按 gitea 的格式拼地址，并从设置的 `gitea` 分区取 token
- **删一条包源**：没有别的 scope 再指向同一个源时，那个源的 token 行一起删
- **列出包源**：两份 npmrc 合起来，逐条标出处，token 只说有没有
- **`@godcreator` 不许改、不许删**：本机所有 home 与源码仓的安装、发版都靠它
- **凭据不出去**：回执里的 token 一律写成 `_authToken=***`，日志里也不写
- **写完核对**：重读文件确认写进去的行在；home 级有同名 scope 指向别处时，`note` 里写明 pnpm 用的是 home 级那条
- **带一份说明书 `gwb-plugin-sources`**：给 agent 讲搜索回执怎么读、两种加源的写法、token 怎么配

## 接口

每条接缝上交换什么、各方保证什么，写在接缝页；本节只列插件来源插件提供了哪些接口、定义在哪里。

| 接口 | 做什么 | 接缝 |
| --- | --- | --- |
| 命令 `plugin-sources.search` | 参数 `{ scope? }`；返回 `{ ok, packages, note? }`，每行带 `pkg`、`version`、`description`、`keywords`；用 npm registry 的标准检索接口 `/-/v1/search`，每条源 10 秒超时，配了 token 就带上 | [1 命令总线](/docs/seams/bus)、[11 包源与检索](/docs/seams/sources) |
| 命令 `plugin-sources.add` | 参数 `{ scope, registry?, owner?, token? }`，`registry` 与 `owner` 恰好给一个；返回 `{ ok, scope, registry, tokenWritten, replaced, lines?, note? }` | [1 命令总线](/docs/seams/bus)、[11 包源与检索](/docs/seams/sources) |
| 命令 `plugin-sources.list` | 无参数；返回 `{ user, home, sources }`，每条源带 `scope`、`registry`、`file`（`user` 或 `home`）、`token`（布尔） | [1 命令总线](/docs/seams/bus)、[11 包源与检索](/docs/seams/sources) |
| 命令 `plugin-sources.remove` | 参数 `{ scope }`；返回 `{ ok, scope, registry? }`；机器级没有这条时写明原因，包括「它在 home 级，要手工删」 | [1 命令总线](/docs/seams/bus)、[11 包源与检索](/docs/seams/sources) |
| 文件 `~/.npmrc`（机器级） | `add`、`remove` 改的就是它：`@scope:registry=<地址>` 一行，有 token 时再加 `//<地址去掉协议>:_authToken=<token>` 一行；token 行按源地址配对，不按 scope；写入是原子的 | [11 包源与检索](/docs/seams/sources) |
| 文件 `<home>/.npmrc`（home 级） | 只读：搜索、列表、找地址时和机器级合起来看，同名行优先 | [11 包源与检索](/docs/seams/sources) |
| 说明书 `gwb-plugin-sources` | 包根 `skills/gwb-plugin-sources/`，交给说明书插件登记 | [4 说明书](/docs/seams/skills) |

**`owner` 的写法**：源地址拼成 `<gitea 地址>/api/packages/<owner>/npm/`，gitea 地址取设置 `gitea.base-url`，没配时用代码里写的默认 gitea 实例（与 gwb-gitea 插件那项设置的默认值相同），`note` 里写明。token 没显式给时取设置 `gitea.token`，取不到就回失败：私有源没有凭据装不了。读别的插件分区的设置只能走 `settings.get` **命令**，服务 `ctx.gwbSettings` 只读得到调用方自己的分区。

**为什么写机器级**：`@godcreator` 的路由本来就写在 `~/.npmrc`，本机每个 home 的安装、每个源码仓的安装与发版都读它，包源是整台机器共用的配置。

## 依赖

| 依赖 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- |
| 命令插件的服务 `gwbCommands`（写在 `export const inject` 里，[gwb-commands](/docs/commands)） | 登记四条命令；调 `settings.get` | 插件一直等待、不加载 |
| 设置插件的命令 `settings.get`（[gwb-settings](/docs/settings)），读 `gitea` 分区的 `base-url` 与 `token` | `owner` 写法拼地址、取 token | 用默认 gitea 实例拼地址；没显式给 token 时 `add` 回失败 |
| 说明书插件的服务 `gwbSkills`（局部注入，[gwb-skills](/docs/skills)） | 登记自带的说明书 | 不登记说明书，插件照常工作 |
| 内核服务 `gwbKernel` 的 `dataDir`（内核仓 gwb-kernel） | 算出 `<home>/.npmrc` | 加载时抛错 |
| 网络与各条 npm 源 | 搜索 | 这条源记进 `note`；全部失败时 `search` 回失败 |
| 文件系统：`~/.npmrc`、`<home>/.npmrc` | 读写包源 | 读不到当作空文件；写失败异常抛给调用方，成为失败回执 |

`@godcreator/gwb-commands`、`@godcreator/gwb-skills`、`@godcreator/gwb-plugin-api` 都写在 devDependencies 里，代码只 `import type` 它们。

## 不做的事

- **不装、不卸、不升插件，不改条目**：这些在插件管理 `@godcreator/gwb-plugin-manager`
- **不写 home 级 `.npmrc`**：那里只放手工加的行，`list` 显示、`add` 与 `remove` 不改
- **不改、不删 `@godcreator`**
- **不调用 pnpm**：用环境变量或 pnpm 全局配置指定的源，这里看不到，搜索可能和安装查的不是同一个源；本机的配置都写在 `~/.npmrc`
- **不按包名判断插件**：只看 `keywords`
- **token 不进回执、不进日志**
