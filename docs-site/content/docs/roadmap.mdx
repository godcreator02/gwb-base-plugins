## 共享包（`packages/`，不是件）

准入判据第二关。件的 `build` 脚本直接调它。

## 组件：各拉各的

**这个仓里没有组件库，也没有 registry。** 每个件自己放一份 `components.json`，要什么组件就
`pnpm dlx shadcn@latest add <名>` 从 shadcn 官方拉。件之间的组件不需要一致——统一风格由令牌
保证，不由组件源码一致保证。

`plugins/hello` 是第一份样板：`components.json` + 两份 tsconfig 的 `paths` + `build.ts` 的
esbuild `alias`，三处的 `@/` 都指 `src/client`。新件照抄即可。

## 下一个：`gwb-shell`

分量最大的一个。母仓那个件 1351 行，探查过一遍，**能直接搬的和不能搬的界限很清楚**。

**能原样搬（约 400 行源码 + 426 行测试，零 DOM/React/import，node 里直接跑）**：

`mount-handle`（mount 契约收窄）、`bus`（格间总线，分桶 + 引用计数 + 听众异常隔离）、
`panels`、`liveness`（一格背后的件是 live/idle/gone）、`openable`（条目 × panes → 可开
窗格表）。这是母仓那个件里质量最高的部分。

**该抄思路的 dockview 工程细节**（都是踩出来的）：

- 面板组件表必须是**模块级常量**——换引用会让 dockview 重建全部格
- 导航定宽用 `constraints`（不进 `toJSON`，每轮布局变化要重钉），**必须去重**，
  否则 `setConstraints` 自己触发 `onDidLayoutChange` 无限递归、占死主线程
- 默认布局里 `setSize` 必须等第二格落位后才调
- 首帧门：布局与条目表都到手前根本不渲染 dockview
- 布局落盘 400ms 防抖（用 `ctx.setTimeout`，件卸载时自动收）
- `PluginPane` 那条 effect：注样式 → **await 它真到位** → 动态 import → 调 `mount` →
  存 `unmount`；拿不到 `unmount` 就报契约不符而不是装作成功

**明确不抄**：老布局兼容（约 60 行 + 5 个双分支）、母仓插件名硬编码（`console` 特判、
六个图标名的花名册）、CDP 探针驱动面、状态栏里的母仓品牌、`void host` 那个半吊子契约
（参数里给了 host bridge 却改吃 `window.gwb`）。

**前置全部清空了**，三条当初挡在前面的都已落地：

1. **窗格清单：运行时注册**（不是静态 `gwb.panes`）。母仓那条「外壳排表时 client 束还没
   加载」的理由在 cordis 下不成立——件挂上时它的 node 半就在跑了，注册发生在 `apply` 里，
   而 `client.js` 仍然点了才动态 import。判据见内核仓 decisions
2. **dockview 的基础表与皮肤住 shell 自己的束**。内核零 UI 知识，样式经 `gwb://` 走件的
   `exports`
3. **React 与样式那条链路已经通了**：内核拼注 importmap、`gwb://` 交任意子路径、令牌包
   共享一份。`plugins/hello` 是跑通的样板

所以 shell 开工时**照 hello 抄那套接线**（`components.json` + 别名三处 + 样式先注后渲染），
省下来的力气全花在 dockview 上。

**落盘那条已经解决了**：`gwb-data` 件先做出来了，shell 写 `inject: ['gwbData']` 就能
`ctx.gwbData.writeDoc('layout', …)`，不用自己拼路径、也不用碰 `fs`。原子落盘在那边兜着——
布局写到一半崩了不会毁掉上一份。

## 之后

**`gwb-logger`**：母仓那 205 行 client 是干净的，可以搬（订阅实时 + 取历史段 + 按 `ts`
归并去重 + 级别筛选）。它的 node 半**不要**——cordis logger 的出口归官方
`plugin-logger-console`，落盘归内核。重做时去掉 `logBacklog?.()` 的可选链（新内核只有
一版 preload）。

需要内核先补**日志环形缓冲与 `logBacklog` 通道**——那条正在等这个件出现。

**`gwb-settings`**：范围要重新划。母仓那 981 行里，「插件启停/卸载」那半建立在 config 件
的 `host.config.*` 之上，而**新内核有 loader**，直接用 `ctx.loader` 的
`create`/`remove`/`update` 就行，**热挂卸是白得的、不用重启**。

**明确不抄**：`platform` 分区 + `window.confirm` 拦截（那个布尔不带任何特权，弹窗文案里的
「兜底页」是母仓概念）、`settings.data.list` 那个目录统计器（跟「设置」没必然关系）。

**要修的名不副实**：母仓那颗「卸载」按钮只摘 yml 条目、不碰 `node_modules`。要么接上真的
卸包，要么改叫「移出插件树」。
