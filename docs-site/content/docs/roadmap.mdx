## 共享包（`packages/`，不是件）

它们不挂在 cordis 上，是**件的依赖**，跟件平级装进 home。件写 `peerDependencies` 依赖它们。

| **tokens** | `@godcreator02/gwb-tokens`：令牌的声明面（页面加载）+ 映射面（件构建期引），亮暗两套值 | **已发 0.0.2** |

准入判据第二关。件的 `build` 脚本直接调它。

## 组件：各拉各的

**这个仓里没有组件库，也没有 registry。** 每个件自己放一份 `components.json`，要什么组件就
`pnpm dlx shadcn@latest add <名>` 从 shadcn 官方拉。件之间的组件不需要一致——统一风格由令牌
保证，不由组件源码一致保证。

`plugins/hello` 是第一份样板：`components.json` + 两份 tsconfig 的 `paths` + `build.ts` 的
esbuild `alias`，三处的 `@/` 都指 `src/client`。新件照抄即可。

## 在做：`gwb-shell`

分量最大的一个。母仓那个件 1351 行，切成四刀：

| **一** | 搬纯逻辑：`bus` / `liveness` / `mount-handle` / `panels` | **完成**，41 条测试全绿 |
| **二** | `ctx.gwbShell` 窗格注册服务；`openable` 这时才搬 | **完成**，实机验通 |
| **三** | dockview 骨架 + 开一格插件窗格 | **完成**，实机验通 |
| **三半** | 一个件多格、同一格开多份、`args.shell` 落地 | **完成**，实机验通 |
| **四·状态栏** | ＋列表 / home / 亮暗，外加外壳身份改运行时 | **完成**，实机验通 |

**各刀交出的面与判据见[它自己那页](/docs/shell)。**

- **一**：搬进来的四个模块全是纯逻辑，`openable` 特意推迟到第二刀
- **二**：`openable` 是**重写不是搬**——母仓那份吃的是「条目表 × 包声明的 `gwb.panes`」，
  运行时注册下 join、过滤、老格兼容三样一起消掉了。`mount-handle` 也跟着契约改名改了
- **三**：`hello` 这一刀起降级成**窗格件**（导出 `mountPane`、`gwb.shell` 摘掉），
  外壳的位置归 shell。两个 `shell: true` 会让渲染层不挑，所以这两条必须同一次换过来
- **三半**（不在原来的四刀里）：窗格的**定义**与**实例**分家。它插在三与四之间，因为
  **第四刀的导航要靠这一刀定下来的形状**——点一下是聚焦还是新开、右键给不给「新开一份」、
  导航列件名从哪来。顺带清掉两笔账：`gwb.title` 这个死字段（四个包声明、零读点、
  两仓文档站一句没提），以及 `bus.ts` 那个「搬进来三刀、有测试、零消费方」的模块
- **四·状态栏**：井外面那条。**＋列表顶掉了导航的主要用途**（母仓导航干的主要就是这件事），
  所以导航从「第四刀的一部分」降级成「真需要常驻侧边栏时再说」。顺带把外壳身份也搬去
  运行时了——包清单里如今只剩 `gwb.shared`，而那个是**硬的**（共享包不是件、没有运行时）

## 剩下那部分要用的东西

**母仓那几条 dockview 工程细节，用掉两条，剩三条**：

| 细节 | 状态 | 为什么 |
| --- | --- | --- |
| 面板组件表必须是**模块级常量** | **已用** | 换引用会让 dockview 重建全部格 |
| 订 `onDidLayoutChange` | **已用**（状态栏的「已开」靠它） | 布局落盘订的是同一个事件 |
| 首帧门 | **不需要** | 数据在 `createRoot` 之前就取齐了，压根没有「还没到手」的那一帧 |
| 导航定宽 `constraints` **必须去重** | 待用 | 不去重的话 `setConstraints` 自己触发 `onDidLayoutChange` 无限递归、占死主线程 |
| 默认布局里 `setSize` 等第二格落位 | 待用 | 眼下不摆多列 |
| 布局落盘 400ms 防抖（`ctx.setTimeout`） | 待用 | 还不落盘 |

**布局落盘落地之后**，状态栏还能补两格（母仓有、我们暂时给不了的）：「重置布局」与
「布局没存上」的告警。

**`liveness` 的输入将来要换**。它现在按「条目表」判一格背后的件是 live / idle / gone，
而第三刀根本没接它——运行时注册已经隐含了「件活着」，注册表里没有的格本来就开不出来。
但**热卸一个件**时：件卸载 → effect 收尾 → 注册表摘掉那格 → **dockview 里那格还开着**。
那时要关掉它，判据的来源是**注册表变了**而不是条目表变了。第四刀真接它时按这个形状改。

**渲染层还不感知任何变化**：`bootShell` 取一次注册表就完了，件后来挂上/卸掉界面都不知道。
第四刀要么加事件推送，要么在导航上给一颗刷新。

**明确不抄**：老布局兼容（约 60 行 + 5 个双分支）、母仓插件名硬编码（`console` 特判、
六个图标名的花名册）、CDP 探针驱动面、状态栏里的母仓品牌、`void host` 那个半吊子契约
（参数里给了 host bridge 却改吃 `window.gwb`）。

**落盘那条已经解决了**：`gwb-data` 件先做出来了，shell 写 `inject: ['gwbData']` 就能
`ctx.gwbData.writeDoc('layout', …)`，不用自己拼路径、也不用碰 `fs`。原子落盘在那边兜着——
布局写到一半崩了不会毁掉上一份。

## 之后

**mcp × skills 那道接口**：这一版两件**各自独立**——skills 收着说明书，mcp 开着口，
中间没有线。接起来是 mcp 那侧的事，MCP 协议里没有 skill 这个原语，只有两格可用：
`instructions`（initialize 时白送进 agent 上下文的那段，**唯一的发现面**——旧线实测
客户端不会自己去 `resources/list`）与 `resources`（正文的载体，`skill://gwb/<名>/SKILL.md`）。
接的时候走**局部注入**，不进 `export const inject`：没装 skills 件的 home 里这道桥照常开，
只是没有说明书那一格。

**等什么**：等真有 agent 连上来干活、而且撞上「一张命令名清单不够用」。眼下那份
`gwb-basics` 经 `skill.read` 读得到，验链路够了；接进 MCP 是为了让 agent **自己发现**它，
没有真实压力之前不做。

**`gwb-settings` 的第二版**：node 半的设置读写[已经做完了](/docs/settings)，还欠两块。

**界面那半**——设置面板。`settings.all` 已经按界面要的形状交出去了（每行带
`scope`/`section`/`key` 与 title/type，外加一个 `live` 标着「此刻还有件声明它吗」），
窗格件照着排就行。

**插件启停/卸载**。母仓那 981 行里这半建立在 config 件的 `host.config.*` 之上，而**新内核
有 loader**，直接用 `ctx.loader` 的 `create`/`remove`/`update`，**热挂卸是白得的、不用重启**。
定过不用官方的 `plugin-loader-webui`（它硬 peer 一个 webui，而 webui 要 server），判据见
内核仓 decisions。

**动手前先看内核仓 walls 里那几条**：`update` 改 config 是**整个重挂**、而且 `inject` 它的
件跟着抖；写回 yml 会把用户手写的注释与空行全丢掉；没有文件监听；`remove` 疑似只认短 id；
`create` 不传 `parent` 落不了盘。**后三条是读源码得出的、没实机撞过**，真用之前各验一次。

**明确不抄**：`platform` 分区 + `window.confirm` 拦截（那个布尔不带任何特权，弹窗文案里的
「兜底页」是母仓概念）、`settings.data.list` 那个目录统计器（跟「设置」没必然关系）。

**要修的名不副实**：母仓那颗「卸载」按钮只摘 yml 条目、不碰 `node_modules`。要么接上真的
卸包，要么改叫「移出插件树」。
