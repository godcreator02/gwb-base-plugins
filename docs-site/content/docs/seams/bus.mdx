**本页回答**：插件怎么把能力登记成命令、调用方怎么按名字执行；命令插件对登记方和调用方各保证什么；命令行运行插件与内核怎么用这张命令表。

## 连接的模块

- [命令插件](/docs/commands) `@godcreator/gwb-commands`：提供服务 `ctx.gwbCommands`，一张只在内存里的「命令名 → 处理函数」表
- 登记命令的插件：本仓的 settings、skills、mcp、logger、node-cli、py-cli，以及别的仓里的插件（插件管理在 devkit 仓，外壳在界面插件仓）
- 调用命令的一方：别的插件直接调 `run`；[MCP 入口](/docs/mcp)把 agent 的 `run` 交给它（见[命令表开给 agent](/docs/seams/agent-surface)）；内核把页面经 `window.gwb.command` 发来的命令名和参数原样交给 `gwbCommands.run`（内核那边见内核仓文档站的「IPC 通道」）
- [gwb-node-cli](/docs/node-cli) 与 [gwb-py-cli](/docs/py-cli)：把登记给它们的命令行工具同时登记成总线命令（见[命令行工具](/docs/seams/cli)）

回执类型 `GwbResult` 在内核的词汇表包 `@godcreator/gwb-plugin-api` 里：`{ ok: boolean, data?, error?: string }`。

<Diagram name="command-run" title="一条命令从调用方到处理函数、回执原路返回（分步）">
- 三类调用方：页面调 `window.gwb.command`，内核收下后原样交给 `run`；agent 调 MCP 入口的 `run` 工具，MCP 入口交给 `run`；别的插件直接调 `ctx.gwbCommands.run`
- 命令总线按命令名查内存里的命令表，找不到回 `{ ok: false, error: '没有这条命令：<命令名>' }`
- 找到就把参数原样交给登记方的处理函数：返回带 `ok` 的对象原样返回，返回别的值包成 `{ ok: true, data }`，抛错收成 `{ ok: false, error }`
- 回执沿原路回到调用方；成功写 info，失败写 warn
</Diagram>

- 第 2 步：B 登记同名命令，后登记的生效，写 warn「后登记的生效：@scope/a → @scope/b」
- 第 3 步：A 卸载，A 的 effect 执行注销函数；表里已经是 B 的记录，什么也不删
- 第 4 步：B 卸载，B 的注销函数删掉这条命令
</Diagram>

## 约定

命令插件保证：
- `run` 从不抛错：命令不存在回 `{ ok: false, error: '没有这条命令：<命令名>' }`，处理函数抛错回 `{ ok: false, error: '<异常文本>' }`
- 处理函数返回带 `ok` 键的对象时原样返回，一个字段都不改；其余返回值包进 `data`
- 同名命令后登记的生效，同时写一条 warn，写明原来是哪个包、现在是哪个包
- 注销函数只删自己登记的那条：同名命令被别人接手后，先登记的一方注销不影响接手的那条
- 登记方卸载时，它登记的命令自动注销，登记方不用包 `ctx.effect`；包了也不出错，卸载时只注销一次。注销函数重复调用无副作用
- `plugin` 不以 `@` 开头时写一条 warn，照常登记
- 每次登记、执行都写日志：成功写 info，失败与找不到命令写 warn

登记方保证：
- `def.plugin` 写自己的包名（`@godcreator/gwb-xxx`），自己填，不从 `ctx.name` 读。MCP 入口按它给命令分组和筛选，与说明书的 `plugin` 对得上（见[命令表开给 agent](/docs/seams/agent-surface)）
- `description` 写一句话，`usage` 写参数形状与注意事项，无参数的写「无参数」
- 处理函数自己校验参数，校验不过就抛错或返回 `{ ok: false, error }`
- 需要总线才能工作的插件把 `gwbCommands` 写进 `export const inject`；命令对它可有可无时用 `ctx.inject(['gwbCommands'], …)` 局部注入（设置插件就是这样）

调用方保证：
- 只看回执的 `ok` 判断成败，失败原因读 `error`
- 处理函数自己返回的带 `ok` 的对象会原样到达，调用方按那条命令的 `usage` 读它的字段

## 不负责的事

- 命令插件不登记任何业务命令，不校验参数，不给命令分权限，也不区分调用方是页面、agent 还是插件
- 命令插件不保存命令表：表只在内存里，登记方卸载时它登记的命令自动注销
- 命令插件不接收页面的 IPC 消息：内核收下页面发来的命令、交给 `run`；内核不认识任何命令名
- 命令插件不运行命令行程序：启动子进程的是 gwb-node-cli 与 gwb-py-cli
- 命令插件不决定命令怎么展示给 agent：`index` / `search` 的格式由 MCP 入口决定
