**本页回答**：提供服务的插件怎么知道是哪个插件在调用它；条目 id 怎么变成数据目录名与设置分区名；哪些插件依赖这一点、各取哪一样；两份相同的算法怎么保持一致。

## 连接的模块

- 用调用方身份的插件：
  - [数据插件](/docs/data)与[设置插件](/docs/settings)：取条目 id 定目录与分区，取包名记归属
  - [说明书插件](/docs/skills)、[命令插件](/docs/commands)、[gwb-node-cli](/docs/node-cli)、[gwb-py-cli](/docs/py-cli)：只取包名，写进说明书与命令的 `plugin`
- cordis 的 loader（版本由内核定）：加载 `cordis.yml` 里的条目时，在每个插件的 fiber 上放一个 `entry`；内核把承载 `cordis.yml` 的那条 include 条目（id 是 `home`）放在 loader 根层

## 接口

<Diagram name="entry-identity" title="条目 id 与包名从 cordis.yml 经 loader 到用调用方身份的插件">
- `cordis.yml` 里一条条目写着 `id: hello` 与包名 `@scope/gwb-hello`；loader 加载它时，在这个插件的 `ctx.fiber.entry` 上放 `id: 'home:hello'` 与 `options.name: '@scope/gwb-hello'`
- 数据插件用 `entryDirName` 把条目 id 算成目录 `<home>/data/hello/`，设置插件用 `entrySection` 算成分区 `hello`：只取末段，超过两段或有段不是 kebab-case 就抛错，两份算法靠约定一致
- 说明书插件、命令插件与 node、python 命令行工具插件只取包名，写进说明书与命令的 `plugin`；数据插件与设置插件也取包名记归属
- 身份一律从调用方的 fiber 上取，取不到就抛错
</Diagram>

**条目 id 是两段**：`entry.id` 由 loader 用 `:` 把父条目的 id 和自己的 id 拼起来。条目都在 id 为 `home` 的那条 include 下面，所以是 `home:<cordis.yml 里写的 id>`。

**条目 id → 目录名 / 分区名**：只取末段；超过两段抛错（嵌套分组之后不同分组下的同名末段会算成同一个名字）；每一段都要 kebab-case，字符集里没有点号，`.` 与 `..` 进不来。冒号不进名字——它在 Windows 上是保留字符，`home` 那段又是内核的常量。数据插件的版本：

这两份**靠约定**保持一致：算法在 `plugins/data/src/paths.ts` 的 `entryDirName` 与 `plugins/settings/src/paths.ts` 的 `entrySection` 各写一份，字符集、段数上限、取末段的规则相同，两处注释互相指着对方。十几行纯逻辑不值得为它开一个共享包；代价是改一处要同时改另一处，否则同一条条目的数据目录和设置分区会对不上，两边的归属记录也记在不同的名字下（见[数据归属](/docs/seams/owners)）。没有测试把两份放在一起比。

**随机 id**：条目没在 `cordis.yml` 里写 `id` 时，loader 给一个 8 位十六进制的随机 id，每次启动都变。两个插件各有一份相同的 `looksRandom`，认出来只写 warn——条目本来能正常运行，不抛错；手写一个正好 8 位十六进制的 id 会多一条 warn：

## 约定

**loader 与内核**保证（内核仓的约定）：

- 经 `cordis.yml` 加载的插件，fiber 上都有 `entry`，`entry.id` 是 `home:<id>` 两段，`entry.options.name` 是条目里写的包名
- loader 的版本由内核定；它改了 `entry` 的形状，就是内核改了对外承诺

**用调用方身份的插件**保证：

- 身份一律从调用方的 fiber 上取，不接受调用方传进来的名字（命令插件与 node 命令行运行插件收登记方写的 `plugin`，只用来核对，与取到的包名不同就被命令总线拒收）
- 取不到身份（不是经 `cordis.yml` 加载的插件在调用）就抛错，写明服务只能在经 `cordis.yml` 加载的插件里用
- 数据插件与设置插件对同一个条目 id 算出同一个名字

**在 `cordis.yml` 里加条目的人或插件管理**保证：

- 每条条目手写 `id`，用 kebab-case
- 不嵌套分组：条目都在 `home` 这一层下面
- 不给条目起名叫 `*`（那是设置插件的公共区）

## 不负责的事

- loader 与内核不知道数据目录和设置分区怎么命名，也不保证 id 在删掉条目之后不被别的包复用（复用由[数据归属](/docs/seams/owners)挡住）
- 用调用方身份的插件不给没写 id 的条目补一个稳定的 id；数据插件与设置插件只写 warn
- 说明书插件、命令插件与两个命令行运行插件不用条目 id：同一个包加了两条条目，它们认的是同一个包名
