**本页回答**：日志插件从哪收日志、怎么判断一条日志的来源；页面上的日志窗格怎么拿到历史与实时日志；一条日志的形状；哪些地方靠约定。日志怎么写进 `gwb.log` 由内核负责，见内核仓文档站的「日志 gwb.log」。

## 连接的模块

- [日志插件](/docs/logger) `@godcreator/gwb-logger`：`inject` 里有 `gwbCommands`；提供空服务 `gwbLogger`，登记命令 `logger.backlog`、`logger.where`
- 内核的日志流：内核、插件、页面 console 三个来源都经 cordis 的 `ctx.logger` 汇成一条流；内核给它注册了第一个 exporter 写 stderr 与 `gwb.log`，页面 console 被内核转成名字为 `renderer` 的日志
- 日志窗格：界面插件仓里 baseui 插件的一个窗格，经 `window.gwb.on` 收实时日志、经 `logger.backlog` 取历史

## 接口

<Diagram name="log-flow" title="日志从三个来源到日志插件、页面与日志窗格（分步）">
- 插件（`ctx.logger('<名字>')`）、内核（`kernel`、`loader`）、页面 console（内核转成 `renderer`）的日志都经 cordis 的 `ctx.logger` 汇成一条流
- 流上有三个接收方：内核的 exporter 写 stderr 与 `<home>/gwb.log`；cordis 自带的缓冲 `ctx.logger.buffer` 留 info 及以上；日志插件的 exporter 收全部（debug 也收）
- 日志插件加载时先从 `ctx.logger.buffer` 补历史，再注册自己的 exporter
- 每条新日志编 `seq`、分来源，存进 2000 条的缓冲，经 `gwbKernel.emit` 推 `{ t: 'gwb-logger', line }` 给页面
- 界面插件仓的日志窗格先用 `window.gwb.on` 订阅，再调 `logger.backlog` 取历史，两段按 `seq` 合并
</Diagram>

**窗格那边另写的一份**：日志窗格在浏览器里运行，不 import 日志插件的类型；`LogEntry`、`LogSource`、`LogLevel` 的形状，以及 `'gwb-logger'`、`'logger.backlog'`、`'logger.where'` 这几个字符串，都在界面插件仓的窗格代码里另写一份。这一份**靠约定**：写在本插件 `src/index.ts` 与界面插件仓 baseui 的日志窗格代码两处。窗格收到认不出的条目会丢掉、不崩溃，所以这边改了形状，症状是窗格里少了日志、不报错。

## 约定

日志插件保证：
- 缓冲里是工作台启动以来的日志，最多 2000 条，超出时从最早的开始丢
- 每条日志都经 `gwbKernel.emit` 推一次 `{ t: 'gwb-logger', line: LogEntry }`，`line` 的形状如上
- `seq` 单调递增、不重复
- 先提供 `gwbLogger` 再做别的：窗格等的就是它
- `gwbLogger` 上不加方法：取数据走命令、实时推送走内核的事件
- 格式化失败时退回把参数逐个转成文本，不让 exporter 抛错（抛错会打断别人写日志的那次调用）
- 两条命令在插件卸载时注销

内核保证（内核仓的约定）：
- 内核、插件、页面 console 三个来源都经 cordis 的 `ctx.logger`，页面 console 的名字是 `renderer`，内核自己的名字是 `kernel`
- `gwbKernel.emit` 把 payload 原样推给页面；窗口不在时丢掉，不补发

日志窗格保证：
- 先订阅实时事件，再调 `logger.backlog` 取历史，两段按 `seq` 合并去重
- 只处理 `t === 'gwb-logger'` 的事件，认不出形状的条目丢掉
- 在收日志的路径上不写 `console`：页面 console 会被内核转回日志流，再推回窗格，形成循环

写日志的插件保证：
- 用 `ctx.logger('<自己的名字>')`，名字不用 `kernel`、`loader`、`renderer`，否则会被算成内核或页面

## 不负责的事

- 日志插件不写日志文件、不写 stderr：那是内核的 exporter
- 日志插件不保存 2000 条以前的日志：更早的看 `logger.where` 报的 `gwb.log`
- 日志插件不过滤、不按级别丢弃：`debug` 也进缓冲，筛选在窗格里做
- 日志插件不画窗格：窗格在界面插件仓
- 内核不按插件区分日志：来源分类只在日志插件里做
