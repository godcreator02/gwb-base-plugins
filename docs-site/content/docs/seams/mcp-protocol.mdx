**本页回答**：外部 MCP 客户端怎么连上一个 home 的 MCP 入口；请求要满足哪几项检查；端口、token 从哪来、写在哪；MCP 插件和客户端各保证什么。工具返回的内容怎么由命令表和说明书生成，见[命令表开给 agent](/docs/seams/agent-surface)。

## 连接的模块

- [MCP 插件](/docs/mcp) `@godcreator/gwb-mcp`：在 `apply` 里自己启动一个 `node:http` 服务，绑 127.0.0.1
- MCP 客户端：Claude Code、zcode 等 agent 客户端，照 `mcp.info` / `mcp.token` 给的配置片段连
- 随包的命令行客户端 `plugins/mcp/bin/client.mjs`：零依赖的单文件脚本，按协议完成握手后调一个工具；装了 gwb-node-cli 时还登记成命令 `mcp.client`

MCP 插件的端口来自设置插件（`inject` 里有 `gwbSettings`，见[设置](/docs/seams/settings)）；`runtime.json` 的其余字段由内核写（内核那边见内核仓文档站的「runtime.json」）。

## 接口

<Diagram name="mcp-request" title="MCP 客户端连 MCP 入口的一次请求（分步）">
- 加载时：从设置插件读 `port`（default 是 2870，被占就不开入口）；读或生成 `<home>/mcp/secret.json` 里的 token；只绑 127.0.0.1，绑定成功后把 `{ port, url }` 写进 `runtime.json` 的 `mcp` 项
- 客户端（agent，或随包的 `bin/client.mjs`）向 `http://127.0.0.1:<端口>/mcp` 发 POST，带 `Authorization: Bearer <token>`
- token、Host、Origin 三项检查在处理请求之前做，任何一项不过回 401，工具一次都不会被调用
- 通过的请求新建一个 McpServer 和一条 transport，登记 `index`、`search`、`run` 三个工具；路径不对回 404，不是 POST 回 405
- `index`、`search` 每次都重新读取命令总线的 `list()` 与说明书插件的 `list()`，`run` 交给命令总线的 `run()`；响应结束时 server 与 transport 一起关闭
</Diagram>

- token：请求头 `Authorization: Bearer <token>`，也认只写 token 本身

这一段**靠约定**：home 目录的位置（`%APPDATA%\gwb-kernel\homes\<home>`）由内核决定，写在内核仓 `main.ts` 选定 home 的那一行与这个脚本两处；`mcp/secret.json` 这段相对路径写在 `auth.ts` 的 `SECRET_DIR` / `SECRET_FILE` 与这个脚本两处。脚本不 import 插件代码（它要能单独复制出去用），任何一处改了，脚本读不到 token，请求会收到 401。

## 约定

MCP 插件保证：
- 工具恰好是 `index`、`search`、`run` 三个；加一个工具是 major 级协议变更，给现有工具加可选参数是 minor，改返回形状是 major
- 每个请求都先过 token、Host、Origin 三项检查，任何一项不过回 401 并在日志里写一条 warn，处理函数一次都不会被调用
- 凭据文件取不出来（磁盘满、目录不可写）时照样开端口，但所有请求一律 401，不退回成不检查
- token 每个 home 一份、重启不换；`mcp.token {"rotate":true}` 之后旧 token 立刻失效、新 token 立刻可用
- default home 只用设置里的端口（缺省 2870），被占就不开 MCP 入口、写一条 error，不改用别的端口
- 只在绑定成功之后写 `runtime.json` 的 `mcp` 项，写失败只写一条 warn、MCP 入口照常服务；进程退出时不删
- 不发清单变更通知：连接是无状态的，工具清单也不会变
- 命令执行失败（命令不存在、参数不对）在 `run` 的结果里带 `isError`，不是协议错误，连接不断

MCP 客户端保证：
- 每个请求带 `Authorization: Bearer <token>`，发到 `127.0.0.1` 或 `localhost` 加实际端口
- 非 default home 的端口从 `runtime.json` 的 `mcp` 项或 `mcp.info` 取，读 `runtime.json` 时自己核对记录是否还有效（pid 是否还在）
- 工作台重启、MCP 插件升级之后重连一次：MCP 连接不会自动连上中途才启动的服务
- `run` 结果带 `isError` 时照常读正文里的原因

命令行客户端保证：
- 先发 `initialize`、再发 `notifications/initialized`、最后 `tools/call`，所以对任何 MCP 服务都适用
- 工具结果带 `isError` 时照常打印正文、退出码 1；传输或协议出错时写 stderr、退出码 1

## 不负责的事

- MCP 插件不做命令级的权限控制：token 对的请求能调命令表里的每一条命令，包括往 home 里装插件
- MCP 插件不保持会话、不推送通知；工具清单在连接时拿到后不会变
- MCP 插件不监听 127.0.0.1 以外的地址，不提供 HTTPS
- MCP 插件不替客户端写配置：`mcp.info` / `mcp.token` 只给片段，写进客户端配置是客户端或用户的事
- 客户端不校验参数形状：`run` 的 `args` 在协议层是任意值，由命令自己校验
- 命令行客户端不负责找非 default home 的端口与 token：要用 `--url`、`--token` 显式给
