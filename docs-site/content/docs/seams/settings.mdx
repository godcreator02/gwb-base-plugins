**本页回答**：插件怎么声明、读写自己的设置；插件之间怎么共享凭据；界面和 agent 怎么看到、改到全部设置；值存在哪；设置插件、声明设置的插件、按位置读写的界面与插件各保证什么。设置插件的功能见 [gwb-settings](/docs/settings)，分区归属见[数据归属](/docs/seams/owners)。

## 连接的模块

- [设置插件](/docs/settings) `@godcreator/gwb-settings`：提供服务 `ctx.gwbSettings`；有命令总线时登记四条 `settings.*` 命令（局部注入，没有命令总线时服务照样完整）
- 声明设置项的插件：写 `inject: ['gwbSettings']`。本仓的 MCP 插件用它声明端口，别的仓里的插件用它存地址、凭据等配置
- 按位置读写的一方：编辑设置的界面、经 MCP 入口的 agent、要读另一个插件分区里凭据的插件
- 插件管理（devkit 仓）：用 `owners()` / `transferOwner()`，见[数据归属](/docs/seams/owners)

## 约定

**设置插件**保证：

- 服务的每个方法都绑定到调用方的条目：插件报不出别人的身份，读写不到别人分区里的项（公共区除外）
- `get` 是同步的：构造时同步读完 `settings.json`，插件一拿到服务就能读
- 声明过的项没设过值时 `get` 回声明里的 `default`；没声明过的 key 读公共区，公共区也没有就回 `undefined` 并写 warn
- 插件加载着时，代码里声明的 `title`、`type`、`description` 覆盖文件里那份，值不动；插件停了文件里的项还在，`settings.all` 里 `live` 为 `false`
- `settings.all` 不交出 secret 项的明文和默认值；`settings.get` 与服务的 `get` 照旧回明文
- 日志里永远不写设置的值
- 写文件是原子的；同一个文件的多次写入按发起顺序写进文件；写失败写一条 warn 并把异常抛给调用方
- 同一条目重复声明同一项，后声明的生效并写 warn；注销只删自己那份，注销函数登记到调用方的 `effect` 上

**声明设置的插件**保证：

- 先 `define` 再 `set` / `delete`：没声明过就调 `set` / `delete` 会抛错
- 设置名用 kebab-case，`title` 不为空
- 条目在 `cordis.yml` 里手写 `id`：随机 id 每次启动都变，设置会对不上
- 插件的配置一律经 `define` 声明，不用 `cordis.yml` 条目里的 `config`
- 读到的值自己校验类型：`type` 只用来给界面挑控件，设置插件不做运行时校验
- 要给别的插件共享的凭据才写 `shared: true`

**按位置读写的界面、插件与经 MCP 入口的 agent**保证：

- 知道自己要的 `section` 与 `key`：`section` 是声明方条目 id 的末段，或者公共区 `*`
- 判断 secret 项有没有设过值时看 `isSet`，不看 `value`；只要判断配没配就不调 `settings.get`，它回的明文会进调用方的记录
- 写的值照那一行的 `type` 给

## 不负责的事

- 设置插件不校验值的类型，也不检查 `settings.set` 写的位置有没有插件声明过
- 设置插件不加密：`settings.json` 里 secret 项也是明文
- 设置插件不是安全边界：名字校验只防误写，插件本来就能直接改这个文件
- 设置插件不提供跨 home 的设置：要共享就复制文件
- 设置插件不画界面
- 声明方不负责别的插件读不读它公共区里的项
