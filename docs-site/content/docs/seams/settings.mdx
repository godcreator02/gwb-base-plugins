**本页回答**：插件怎样读写、页面和 AI 怎样管理凭据，以及两份文件写入中断后怎样恢复。分区归属见[数据归属](/docs/seams/owners)。

## 连接的模块

- 设置插件提供 `ctx.gwbSettings`；命令总线是局部注入，服务不依赖命令入口。
- 声明设置的插件通过服务操作自身分区，MCP 插件也用它保存端口、主 token 和临时 token 表。
- 页面与 agent 按分区、键管理；需要跨插件取用凭据的受信插件可内部调用 credentials.reveal。

## 接口

<Diagram name="settings-layout" title="每个 home 的普通设置与凭据，分别经过哪些入口">
- settings.json 保存普通值、设置声明和 $owners；credentials.json 保存同一分区与键的明文 secret
- 插件服务从调用方条目确定分区，未声明的 key 读当前 home 公共区
- settings.* 只操作普通设置；credentials.* 管凭据，list/status 不回值；插件服务 get 仍可取凭据原文
- credentials.copy/import/generate 直接在本机完成操作，不把旧值或新值交给 AI
</Diagram>

**服务**保持 `define/get/set/delete` 的用法。同步 get 先找自己声明的项，没有保存值回 default；自己没声明的 key 读公共区 `*`。set/delete 只能操作自己声明的项：

`shared:true` 只表示本 home 内公共设置；不表示与别的 home 共用文件或同步值。条目要用固定 id，分区取 id 末段，名称规则见 `plugins/settings/src/paths.ts`。

**命令**按位置定位，使用当前 home 的服务；普通设置与凭据分开编排：

| 对象 | 查询入口 | 写入与清除 |
| --- | --- | --- |
| 普通设置 | settings.all/get | settings.set/delete |
| 凭据 | credentials.list/status；本地查看用 credentials.reveal | credentials.copy/import/generate/delete；本地输入用 credentials.set |

`settings.all {section?}` 只列普通设置，`settings.get` 回保存值，未保存回 undefined，经 MCP 翻译为 null，不回默认值。`settings.get/set/delete` 对任何来源的 secret 目标都报错并指向 `credentials.*`，插件内部按位置调用也遵守这一条。

`credentials.list {section?}` 只列凭据，沿用 SettingView 的分区、声明和 live 字段；不带 value/default，只有 secret、isSet 与已保存时的定长掩码。`credentials.status {section,key}` 返回 `{section,key,type,secret:true,isSet,live}`；目标不存在回 null，普通设置目标报错。isSet 是存储状态，不是账号认证结果。

{/* ref file="../plugins/settings/src/index.ts" lines="152-244" hash="03cfd62d61cd" blob="0dcb9862f136" */}

**不回显的写操作**：

| 命令 | 来源与目标 | 结果 |
| --- | --- | --- |
| credentials.copy | from 为 section/key 与可选同级 home 名；to 是当前 home 的 section/key；两端都必须是 secret | 目标配置状态；来源不改，复制后独立 |
| credentials.import | from 为绝对 file、text/json 格式、JSON 字段 path；to 是当前 home 的 section/key | 目标配置状态；来源只读 |
| credentials.generate | to 是当前 home 的 section/key，可给随机字节数 | 目标配置状态；只生成随机值 |
| credentials.delete | section/key 指向凭据；可清理已停用插件的遗留值 | 目标配置状态，保留定义、不回值 |

copy/import/generate 的目标必须仍由已启用插件声明，已有值需 `overwrite:true`。导入文件上限 1 MiB，最终值必须是非空字符串；text 只去掉一个末尾换行。随机字节数为 16—128，默认 32，编码是 base64url。参数与校验的正本：

## 存储与恢复

每个 home 自己保管两份文件，没有自动继承。settings.json 保留 `$owners`、分区与元信息，secret 的 value 单独放进 credentials.json。凭据文件顶层为 version 与 sections，槽按 section/key 对齐。旧 settings.json 里的 secret.value 在下一次成功持久化时迁出。

读取时凭据槽优先于旧 settings 值；槽存在但没有 value 是删除记录。即使中断时普通设置文件还留着旧值，也不会把已删除凭据恢复出来；缺少元信息的凭据槽强制按 secret 对待，不能被普通列表回显：

{/* ref file="../plugins/settings/src/store.ts" lines="91-113" hash="08c21668a79e" blob="69d6fedc9da6" */}

每次持久化先写 credentials.json，再写 settings.json。每个文件都以同目录临时文件加 rename 原子替换，**两份文件不是一个事务**。同一进程内的写入排队，不承诺多个进程同时写同一个 home 的文件锁：

{/* ref file="../plugins/settings/src/store.ts" lines="172-192" hash="fd838273448a" blob="69d6fedc9da6" */}

凭据文件损坏或无法读取会报错；旧 settings 文件解析失败时可暂时按空设置读取，但后续写入会重新严格检查、拒绝覆盖。错误不附文件内容或解析片段。操作失败后服务按可读取的磁盘事实恢复该项，调用方应重新查状态，不把失败等同于完全没有落盘。

## 约定

**设置插件**同时提供 settings 与 credentials 两组命令，负责分区、文件存储、状态回执与不回显的本机转交。`credentials.set {section,key,value}` 只接受字符串，`credentials.reveal {section,key}` 返回保存值；两条标记 hiddenFromAgents，处理函数只允许明确的 ui/plugin 来源。综合设置页合并普通设置与凭据列表展示。插件服务的分区限制防止误用，不是进程隔离。

**声明方**先 define 再 set/delete，固定条目 id，普通值自行校验；secret 写入只接受字符串。不要把内部取到的值拼进业务回执、日志或异常。认证、签发、过期与撤销由业务插件负责。

**管理方**明确目标 home、section、key 与用途，使用复制或导入完成已有凭据的转交，不先读取明文。跨 home 复制相同第三方 token 后，本地修改独立，但服务端撤销仍可能影响全部副本。

## 不负责的事

- 不加密文件，不保证凭据对同用户本机程序不可见。
- 不自动选择其他 home 的凭据，也不持续同步复制结果。
- 不提供第三方 token 签发或认证成功保证；credentials.generate 只是随机值生成。
- 不画界面、不保存插件业务数据。
