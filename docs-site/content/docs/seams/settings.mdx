**本页回答**：插件怎么声明、读写自己的设置；插件之间怎么共享凭据；界面和 agent 怎么看到、改到全部设置；值存在哪；设置插件和各方各保证什么。

## 连接的模块

- [设置插件](/docs/settings) `@godcreator/gwb-settings`：提供服务 `ctx.gwbSettings`；有命令总线时登记四条 `settings.*` 命令（局部注入，没有命令总线时服务照样完整）
- 声明设置项的插件：写 `inject: ['gwbSettings']`。本仓的 MCP 插件用它声明端口，别的仓里的插件（如 gitea 插件仓的 gitea 插件）用它存地址与凭据
- 按位置读写的一方：界面插件仓里插件管理窗格的设置部分、经 MCP 入口的 agent、要读别的插件设置的插件（插件管理配包源时经 `settings.get` 读 `gitea` 分区的 `base-url` 与 `token`）
- 插件管理（devkit 仓）：用 `owners()` / `transferOwner()`，见[数据归属](/docs/seams/owners)

- 右边是 `<home>/settings.json` 的顶层：`$owners`（分区名 → 包名）、每条条目一个分区（条目 `home:mcp` 的分区叫 `mcp`）、公共区 `*`

| 命令 | 参数 | 回执 |

| `settings.all` | 无 | 全部设置项，每行带位置、`title`、`type`、`value`、`live`（此刻有没有插件声明它）；`live` 的项再带声明时给的 `default` |

| `settings.delete` | `{ section, key }` | `{ ok: true }`；只抹值，定义还在 |

## 约定

设置插件保证：
- 服务的每个方法都绑定到调用方的条目：插件报不出别人的名字，读写不到别人分区里的项（公共区除外）
- `get` 是同步的：构造时同步读完 `settings.json`，插件一拿到服务就能读
- 声明过的项没设过值时 `get` 回声明里的 `default`；没声明过的 key 读公共区，公共区也没有就回 `undefined` 并写 warn
- 插件加载期间，代码里声明的 `title`、`type`、`description` 覆盖磁盘上那份，值不动；插件停了磁盘上的项还在，`settings.all` 里 `live` 为 `false`
- `settings.all` 不交出 secret 项的明文和默认值；`settings.get` 与服务的 `get` 照旧回明文
- 日志里永远不写设置的值
- 写盘是原子的；同一个文件的多次写入按发起顺序落盘，后发起的那次留在文件里；写失败写一条 warn 并把异常抛给调用方
- 同一条目重复声明同一项，后声明的生效并写 warn；注销只删自己那份，注销函数登记到调用方的 effect 里

声明设置的插件保证：
- 先 `define` 再 `set` / `delete`：没声明过就调 `set` / `delete` 会抛错
- 设置名用 kebab-case（小写字母、数字、单连字符），`title` 不为空
- 条目在 `cordis.yml` 里手写 `id`：随机 id 每次启动都变，设置会对不上（设置插件认出随机 id 时写 warn）
- 插件的配置一律经 `define` 声明，不用 `cordis.yml` 条目里的 `config`
- 读到的值自己校验类型：`type` 只用来给界面挑控件，设置插件不做运行时校验
- 要给别的插件共享的凭据才写 `shared: true`

按位置读写的一方保证：
- 知道自己要的 `section` 与 `key`：`section` 是声明方条目 id 的末段，或者公共区 `*`
- 用 `settings.all` 判断 secret 项有没有设过值时看 `isSet`，不看 `value`

## 不负责的事

- 设置插件不校验值的类型，也不检查 `settings.set` 写的位置有没有插件声明过
- 设置插件不加密：`settings.json` 里 secret 项也是明文
- 设置插件不是安全边界：名字校验只防误写（名字里带斜杠、条目占用公共区），插件本来就能直接改这个文件
- 设置插件不提供机器级设置：每个 home 一份，要跨 home 共享就复制文件
- 设置插件不画界面：编辑设置的界面在界面插件仓的插件管理窗格里，经 `settings.*` 命令读写
- 声明方不负责别的插件读不读它公共区里的项
