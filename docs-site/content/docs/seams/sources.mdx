**本页回答**：plugin-sources 插件读写哪两份 npmrc、认哪几种行；怎么决定一个 scope 去哪条源检索、怎么判断一个包是不是插件；它读 gitea 插件的哪两项设置；它和 pnpm、插件管理之间靠什么对上。

## 连接的模块

- [plugin-sources 插件](/docs/plugin-sources) `@godcreator/gwb-plugin-sources`：登记 `plugin-sources.search`、`.add`、`.list`、`.remove` 四条命令；`inject` 里有 `gwbCommands`
- 两份 npmrc：机器级 `~/.npmrc`（`add` / `remove` 改它）与 home 级 `<home>/.npmrc`（只读）；pnpm 安装时读的是同一批配置行
- npm registry：npmjs、Verdaccio、gitea 都实现的标准检索接口
- gitea 插件（gitea 插件仓 gwb-gitea）的设置：`gitea` 分区的 `base-url` 与 `token`
- 插件管理（devkit 仓）：真正安装查到的包，命令 `plugin-manager.install`

## 约定

plugin-sources 保证：
- `add` / `remove` 只改机器级 `~/.npmrc`，home 级只读；`@godcreator` 的路由与凭据不改不删
- 写 npmrc 先写同目录的临时文件再改名；`add` 写完重读一遍，读不到写进去的行就回 `ok: false`
- `add` 同一个 scope 已有就原地替换，不多写一行；换源、删源时，旧源的凭据行只在没有别的 scope 还指向它时才删
- 回执与日志里不带 token：写进去的行里 token 换成 `***`，`list` 只报有没有 token
- home 级有同名 scope 指向别的地址时，`add` 的回执 `note` 里提醒 pnpm 用的是 home 级那条
- `search` 不带参数时查全部配好的 scope（`@godcreator` 在前、其余按名字排），各条源并发查，一条失败不影响别的，全都失败才 `ok: false`
- 检索结果只留 keywords 里有 `gwb-plugin` 的包；gitea 把 scope 与名字分开放时拼回完整包名

插件包保证：
- `package.json` 的 `keywords` 里写 `gwb-plugin`；库、共享包不写

gitea 插件保证（gitea 插件仓的约定）：
- 条目 id 是 `gitea`，设置名是 `base-url` 与 `token`

插件管理保证（devkit 仓的约定）：
- `plugin-manager.install` 用 pnpm 安装，pnpm 读的是同样两份 npmrc

## 不负责的事

- plugin-sources 不安装、不卸载、不升级包，不改 `cordis.yml`：那是插件管理
- plugin-sources 不看环境变量或 pnpm 全局配置里指定的源，只看这两份 npmrc
- plugin-sources 不写 home 级 `.npmrc`：那里的行要手工改
- plugin-sources 不判断包的版本兼容：`gwb.testedKernel` 的比对在插件管理里
- gitea 插件不知道 plugin-sources 在读它的设置
