# gwb-skills

skill 是**给 agent 看的说明书**（`SKILL.md` 加可选的附件，形状照 Anthropic Agent Skills
那套）。工作台把命令开放给外部 agent 之后，agent 手上只有一张命令名清单——多步流程、
调用顺序、遇到过的问题都没地方讲，这个插件就是写这些话的地方。

包名 `@godcreator/gwb-skills`，服务 `ctx.gwbSkills`。没有界面，不依赖任何第三方包
（frontmatter 是手写的逐行解析，没有引入 YAML 库）。

## 三条规矩

每一条都防一种**看起来正常、其实在误导人**的情况——这个插件的设计重点全在这里。

### 由插件主动登记

插件在自己的 `apply` 里登记一个目录，经 `ctx.effect` 在卸载时撤销。**不扫 `node_modules`、
不看条目的启用停用**。

所以列表里每一份说明书都对应一个此刻正在运行的插件，不会出现「说明书在、它讲的那条命令不在」
——agent 照着一份讲着不存在的功能的说明书干活，结果是它做错了而没人知道为什么。

### 正文每次都从磁盘读

{/* ref file="../plugins/skills/src/index.ts" lines="151-162" */}

改了 `SKILL.md` 的正文立刻生效，不用重新加载插件；内存里只存元信息。

**登记时扫描的那部分不会自动更新**：加删文件、改 frontmatter 仍要重新加载插件——文件清单在
`register` 那一刻就定了。

### `read` 只查登记表，不拼路径

上面那段代码的第二个 `if` 就是这道防线。按名字查表，文件名必须在扫描出的清单里——
**一旦改成拼路径，一个带 `../` 的参数就能读出插件目录以外的任何文件**。

实机验证过四种写法（`../package.json`、`../../cordis.yml`、`SKILL.md/../../../` …）全被拒绝，
而且拒绝的文字和「没有这份说明书」一字不差——分开报错就等于告诉外面哪些名字存在。

## 怎么登记

在你的插件里，**用局部注入**：

```ts
// 不写进 export const inject——写进去的话，这个插件在没装 skills 插件的 home 里就整个加载不了，
// 而说明书不是它能不能工作的前提
ctx.inject(['gwbSkills'], (scoped) => {
  scoped.effect(() => scoped.gwbSkills.register(new URL('../skills/', import.meta.url)))
})
```

写 `'../skills/'` 是因为构建产物在 `dist/` 下，而说明书目录在包根。

**然后把这个目录加进 `package.json` 的 `files`**：

{/* has file="../plugins/node-cli/package.json" text="skills" */}

漏了这一条，包照样发布、照样装得上，直到那个插件加载时去扫目录才报「读不到」。

## 身份不用自己报

`register` 没有「你是谁」这个参数——服务从 `this.ctx.fiber.entry` 上认出调用方：

{/* ref file="../plugins/skills/src/index.ts" lines="105-116" */}

和 `gwb-data` 认数据目录、`gwb-shell` 认窗格归属是同一个做法。**插件不报自己的名字，
也就没法报别人的名字**去登记一份冒名的说明书。身份也不从路径推——推出来的目录名
是一个可以随便改的参数。

## 四条上限

扫描有上限：单个文件 512KB、往下三层目录、一份说明书最多 64 个文件、只收
`.md/.txt/.json/.yml/.yaml`。超出的不会悄悄丢掉——`collectSkills` 把问题记进 `problems`，
由调用方逐条写 warn 日志。

**frontmatter 取不到 `description` 也要报一句**：只认单行的 `key: value`，折叠写法（`>-`、`|`）
取不到值。悄悄当成空的话，作者要等到 agent 怎么都不读这份说明书时才发现描述丢了。

## 它不认识 MCP，agent 经 MCP 读它

对接 MCP 的是 [gwb-mcp](/docs/mcp)：skills 插件不认识 MCP，mcp 插件局部注入 `gwbSkills`，把说明书清单
（每份的名字与描述）放进 `index` 的返回里；正文由 agent 经 `run` 调用 `skill.read` 读取，附件的目录由
`SKILL.md` 正文自己说明，不单独列出。清单每次调用 `index` 时现取，新加载的插件立刻出现。

skills 插件停用或卸载时，MCP 入口照常工作，只是 `index` 里不再有说明书清单。
