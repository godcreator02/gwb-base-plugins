**本页回答**：说明书插件有哪些功能；插件和 agent 经哪些接口用它，各属于哪条接缝；它依赖什么、缺了会怎样；哪些事常被以为归它、其实归 MCP 入口或登记说明书的插件。包名 `@godcreator/gwb-skills`，源码目录 `plugins/skills/src`，入口文件 `index.ts`。

说明书是给 agent 读的文档：一个目录，里面必有 `SKILL.md`，可以带 `references/` 之类的附件，形状照 Anthropic Agent Skills。agent 经 MCP 入口只拿得到命令名与用法，多步流程、调用顺序、遇到过的问题写在说明书里。

<Diagram name="skills-flow" title="插件登记说明书、agent 读正文、插件卸载时撤掉（分步）">
- 带说明书的插件在包根放 `skills/` 目录，每个带 `SKILL.md` 的子目录一份；`apply` 里局部注入 `gwbSkills`，调 `register(new URL('../skills/', import.meta.url))`
- 说明书插件扫描目录，登记表里每份记名字、描述、包名（取自调用方条目）、文件清单
- 另一个插件带来同名说明书时，先登记的保留，后来的不登记、写 warn
- agent 经 MCP 入口的 `run` 调 `skill.list`、`skill.read { name, file? }`；`skill.read` 只读清单里的文件，每次从磁盘读
- 插件卸载时，它登记的说明书从表里撤掉
</Diagram>

## 功能

- **插件自己登记说明书**：插件在 `apply` 里把一个目录交给说明书插件，目录下每个带 `SKILL.md` 的子目录是一份说明书；插件卸载时它的说明书跟着撤掉，撤的时候只删表里仍是它登记的那条，别的插件后来登记的同名说明书不受影响
- **列表里只有正在运行的插件的说明书**：不扫 `node_modules`、不看条目启用停用，不会出现「说明书在、它讲的命令不在」
- **说明书名全局唯一**：同名的第二份不登记，写一条 warn 说明名字被哪个插件占着
- **正文每次都从磁盘读**：改了 `SKILL.md` 的正文立刻生效；加删文件、改 frontmatter 要重新加载那个插件，文件清单在登记那一刻就定了
- **只读登记过的文件**：`skill.read` 按名字查表，文件名必须在登记时扫出的清单里，带 `../` 的参数读不到插件目录以外的文件；「没有这份说明书」与「没有这个文件」回同一句话
- **扫描有上限、超出就报**：只收 `.md`、`.txt`、`.json`、`.yml`、`.yaml`，单个文件 512KB，往下三层目录，一份说明书最多 64 个文件；超出的、读不了的逐条写 warn，不悄悄丢掉
- **frontmatter 取不到 `description` 也报**：只认单行的 `key: value`，折叠写法（`>-`、`|`）取不到值；没有描述照样登记，同时写一条 warn

## 接口

每条接缝上交换什么、各方保证什么，写在接缝页；本节只列说明书插件提供了哪些接口、定义在哪里。

| 接口 | 做什么 | 接缝 |
| --- | --- | --- |
| 服务 `ctx.gwbSkills` 的 `register(dir)` | 登记一个装说明书的目录（字符串路径或 `URL`），返回注销函数；注销也自动登记在调用方的 `ctx.effect` 上，不用自己包 | [4 说明书](/docs/seams/skills) |
| 服务 `ctx.gwbSkills` 的 `list()`、`read(name, file?)` | 列出全部说明书；读某份说明书里的一个文件，缺省 `SKILL.md`，读不到回 `undefined`；类型 `GwbSkillsApi`、`GwbSkill` 由本包导出 | [4 说明书](/docs/seams/skills) |
| 命令 `skill.list` | 无参数，返回 `{ count, skills }`，每份带名字、描述、所属插件的包名、文件清单 | [1 命令总线](/docs/seams/bus) |
| 命令 `skill.read` | 参数 `{ name, file? }`，返回 `{ name, file, text }`；agent 经 MCP 入口的 `run` 调它读正文 | [3 命令表开给 agent](/docs/seams/agent-surface) |

插件登记说明书的写法，用局部注入，没装说明书插件的 home 里这个插件照常加载：

```ts
ctx.inject(['gwbSkills'], (scoped) => {
  scoped.effect(() => scoped.gwbSkills.register(new URL('../skills/', import.meta.url)))
})
```

写 `'../skills/'` 是因为构建产物在 `dist/` 下，而说明书目录在包根。**这个目录要列进 `package.json` 的 `files`**，漏了包照样发布、照样装得上，直到插件加载时扫目录才报「说明书目录读不了」。

{/* has file="../plugins/node-cli/package.json" text="skills" */}

**登记方的身份不用自己报**：`register` 没有「你是谁」这个参数，服务从调用方上下文的 `fiber.entry.options.name` 认出包名，插件没法用别人的包名登记说明书。

**说明书名**：frontmatter 写了 `name` 就用它，没写用目录名。

## 依赖

| 依赖 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- |
| 命令插件的服务 `gwbCommands`（服务类上的 `static inject`，[gwb-commands](/docs/commands)） | 登记 `skill.list`、`skill.read` | 服务 `gwbSkills` 不提供，插件一直等待 |
| cordis 的 `Service`（peer，`^4.0.0-rc.9`） | 提供服务；方法里的 `this.ctx` 是调用方的上下文 | 无法加载；必须和内核用同一份 cordis |
| loader 在调用方上下文上加的 `fiber.entry.options.name` | 认出登记方的包名 | 不是经 `cordis.yml` 加载的插件调用 `register` 时抛错「取不到调用方的身份」 |
| 文件系统 | 登记时扫目录，读正文 | 目录读不了时写 warn、这个目录一份都不登记；正文读不了回 `undefined` 并写 warn |
| 词汇表包 `@godcreator/gwb-plugin-api`（peer） | `GwbContext` 的类型 | 只在编译时用 |

`@godcreator/gwb-commands` 写在 devDependencies 里：代码只 `import type {}` 它，为的是让 `ctx.gwbCommands` 有类型。frontmatter 是手写的逐行解析，没有 YAML 库。

## 不做的事

- **不认识 MCP**：说明书清单进 MCP 入口 `index` 的返回、附件清单不给 agent，都是 [MCP 入口](/docs/mcp)的决定；它局部注入 `gwbSkills` 取 `list()`
- **不扫 `node_modules`、不找没登记的说明书**：列表里只有插件主动登记的
- **不检查正文**：正文写什么、附件在正文里提没提到，由写说明书的插件负责
- **不支持多行 frontmatter**：`description` 要写成一行
- **没有别的出口**：服务的 `read` 之外，agent 读正文只经 `skill.read`
