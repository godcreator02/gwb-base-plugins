**本页回答**：说明书插件有哪些功能；插件和 agent 经哪些接口用它，各属于哪条接缝；它依赖什么、缺了会怎样；哪些事常被以为归它、其实归 MCP 入口或登记说明书的插件。包名 `@godcreator/gwb-skills`，源码目录 `plugins/skills/src`，入口文件 `index.ts`。

说明书是给 agent 读的文档：一个目录，里面必有 `SKILL.md`，可以带附件。agent 经 MCP 入口只拿得到命令名与用法，多步流程、调用顺序、遇到过的问题写在说明书里。

## 功能

- **插件自己登记说明书**：插件在 `apply` 里把一个目录交给说明书插件，目录下每个带 `SKILL.md` 的子目录是一份；说明书插件从调用方条目认出包名，插件没法用别人的包名登记。插件卸载时它的说明书跟着撤掉，撤的时候只删表里仍是它登记的那条
- **列表里只有正在运行的插件的说明书**：不扫 `node_modules`、不看条目树，不会出现「说明书在、它讲的命令不在」
- **说明书名全局唯一，先登记的保留**：同名的第二份不登记，写一条 warn 说明名字被哪个包占着。这一点和命令总线的「后登记的生效」相反：说明书被静默换掉的话，agent 照着另一个插件的说明书做，症状只是做错了
- **正文每次都从磁盘读**：改了 `SKILL.md` 正文立刻生效；增删文件、改 frontmatter 要重新加载那个插件，文件清单在登记那一刻就定了
- **只读登记过的文件**：读的时候按名字查表，文件名必须在登记时扫出的清单里，不做路径拼接，带 `../` 的参数读不到目录以外的文件；`skill.read` 读不到时不区分「没这份说明书」与「没这个文件」，分开报等于告诉外面哪些名字存在
- **扫描有上限、超出就报**：只收 `.md`、`.txt`、`.json`、`.yml`、`.yaml`，单个文件 512KB，往下三层，一份最多 64 个文件；超出的、读不了的、缺 `SKILL.md` 的逐条写 warn，不悄悄丢掉
- **frontmatter 取不到 `description` 也报**：只认单行 `key: value`，折叠写法（`>-`、`|`）取不到值；没有描述照样登记，同时写一条 warn——没有描述的说明书 agent 不会去读，比整份不收好查。`name` 没写用目录名

## 接口

每条接缝上交换什么、各方保证什么，写在接缝页；本节只列说明书插件提供了哪些接口。

| 接口 | 做什么 | 接缝 |
| --- | --- | --- |
| 服务 `ctx.gwbSkills` 的 `register(dir)` | 登记一个装说明书的目录（字符串路径或 `URL`），返回注销函数；注销也自动登记在调用方的 `effect` 上 | [4 说明书](/docs/seams/skills) |
| 服务 `ctx.gwbSkills` 的 `list()`、`read(name, file?)` | 列出全部说明书；读某份里的一个文件，缺省 `SKILL.md`，读不到回 `undefined` | [4 说明书](/docs/seams/skills) |
| 命令 `skill.list` | 无参数，返回 `{ count, skills }`，每份带名字、描述、包名、文件清单 | [4 说明书](/docs/seams/skills) |
| 命令 `skill.read` | 参数 `{ name, file? }`，返回 `{ name, file, text }`；agent 经 MCP 入口的 `run` 调它读正文 | [3 命令表开给 agent](/docs/seams/agent-surface) |

插件登记说明书的写法，用局部注入，没装说明书插件的 home 里这个插件照常加载：

```ts
ctx.inject(['gwbSkills'], (scoped) => {
  scoped.effect(() => scoped.gwbSkills.register(new URL('../skills/', import.meta.url)))
})
```

写 `'../skills/'` 是因为构建产物在 `dist/` 下，而说明书目录在包根。**这个目录要列进 `package.json` 的 `files`**，漏了包照样发布、照样装得上，直到插件加载时扫目录才报「说明书目录读不了」。

## 依赖

注入了哪些服务、peer 怎么写、缺了会怎样，以及用了哪些约定通道（loader 放在 fiber 上的条目、登记方包目录下的说明书目录），见[插件之间怎么连](/docs/wiring#godcreatorgwb-skills)。登记时目录读不了写 warn、这个目录一份都不登记；正文读不了回 `undefined` 并写 warn。

## 不做的事

- **不认识 MCP**：说明书清单怎么进 MCP 入口 `index` 的返回、附件清单给不给 agent，都是 [MCP 入口](/docs/mcp)的决定；它局部注入 `gwbSkills` 取 `list()`
- **不扫 `node_modules`、不找没登记的说明书**：列表里只有插件主动登记的
- **不检查正文**：正文写什么、提到的命令存不存在、附件在正文里提没提到，由写说明书的插件负责
- **不支持多行 frontmatter**：`description` 要写成一行
- **自己没有说明书**：包根没有 `skills/`
