# 撞过的墙

代码注释只写现状，**为什么、症状、当时怎么查的，全在这一页**，每条钉在具体代码上。

内核那边的规则与坑在内核仓的站上；这一页只记件自己的。

## 相对 import 必须带 `.js`，而它是个静默失败

产物给 node 直接加载（loader 不打包），ESM 不做扩展名补全。少了 `.js` 的症状是
**件挂不上，而日志一个字都没有**——第一个件就是这么撞的，查了几分钟才定位。

（内核后来补了保底 error 出口，同样的错现在当场是一行 `ERR_MODULE_NOT_FOUND` 带路径。）

本想让 TypeScript 替我们强制这一条，**结果不行**：

{/* ref file="../tsconfig.base.json" lines="4-6" */}

`moduleResolution: nodenext` 会强制相对 import 带扩展名，但 **cordis 自己的 `.d.ts` 不兼容
它**——那边写的是 `export * from './context'`，相对 import 不带扩展名。nodenext 解析不了，
整个 `Context` 类型退化成空，症状是 `ctx.logger` / `effect` / `provide` 全报「不存在」。

所以只能回 `bundler`，那一条改由产物守卫拦：

{/* ref file="../plugins/cli/tests/artifact.test.ts" lines="21-43" */}

顺带钉住第二条：**产物里不许有裸名 import**。件该是自包含的——契约包与 cordis 都只
`import type`、编译期擦除，`gwb-cli` 的产物里除了一条 `./registry.js` 什么都没有。

缺产物时整组跳过，门禁不依赖 `build`。

## 契约包走 peer，不是 dev

判据「运行时真 import 了才写 peer，只 `import type` 写 dev」**漏了中间一档**：

{/* has file="../plugins/cli/package.json" text="peerDependencies" */}

`GwbCli.run` 回的是 `GwbResult`——它出现在**导出的类型**里，消费方装了这个件之后必须
解析得到。写成 `devDependency` 的症状是消费方那边全解析不到，因为**发布出去的包不带
devDependencies**。

同一个坑在内核仓也撞了一次（词汇表包的 `GwbContext extends Context` 把 cordis 写成 dev）。
三档判据的正本在内核仓的 `CLAUDE.md`。

**白得的一条**：peer 声明之后，pnpm 把契约包自动装进了 home，消费方不用手动装。

`cordis` 仍然是 dev——它只在 `apply` 的参数类型里用，不出现在导出面。

## 撞名是后来者赢，但不许静默地赢

{/* ref file="../plugins/cli/src/registry.ts" lines="23-36" */}

件一律平等，换掉一条命令是应有之义。但静默改派的话，调用方从此打到另一个件的处理器上，
**两边谁都不会报错**——所以撞名要出一条告警，说清谁换了谁。

## 注销只收自己那份

同一段里那个 `if (table.get(def.name) === record)`：撞名之后**先卸载的那个件，不该把接手的
那份一起带走**。少了这个判等，卸一个件会让另一个件注册的命令跟着消失。

## 一条命令抛出来不该炸到调用方

{/* ref file="../plugins/cli/src/registry.ts" lines="42-54" */}

它可能是界面上的一次点击。handler 自己判过成败就原样透传，没判的一律算成了。

## 共享包

### react 至今没有 ESM 出口，中间包躲不掉

实测 react 19.2.8 的包清单：`exports` 里只有 `react-server` 与 `default`，`default` 指
`index.js`，**没有 `module` 字段、没有 `"type": "module"`**——它是纯 CJS。

所以「把 home 里的 react 按裸名直接交给浏览器」这条路根本不通，必须有人先把它打成 ESM
再发一个包出来。这不是绕远，是唯一的走法。

### 打 ESM 只能用 esbuild，rolldown 会留 `require`

{/* ref file="../packages/shared-react/build.ts" lines="6-9" */}

rolldown 在 browser 平台对「CJS require 外置包」**刻意保留 `require`**，而浏览器里没有
这个东西——产物一加载就炸。esbuild 会把它提升成顶层 `import`。

### react-dom 在工厂函数内部 require，esbuild 也提不出来

{/* ref file="../packages/shared-react/build.ts" lines="22-30" */}

它那句 `require('react')` 不在顶层，而在工厂函数**内部**。esbuild 提不动，于是产物里留下
一个 `__require` 探针，跑到那一句才炸。修补是 banner 提一句 `import * as __gwb_react`，
再把探针换成只认 react 的同步解析器（回 `default`——react-dom 要摸 React 的内部件）。

那条正则认的是 **esbuild 生成代码的形状**，是个明摆着的脆弱点。所以这里跟母仓的处理不同：
**匹配不上直接抛**，而不是打一句「无探针，原样保留」就放过——带探针的产物发出去，要到
页面上打开窗格才看得见。产物守卫再兜一道：四份束里不许出现 `typeof require` 或裸 `require(`。

## 令牌

### preflight 必须包进 `@layer base`，否则它盖掉所有件的工具类

{/* ref file="../packages/tokens/build.ts" lines="16-21" */}

CSS 里**未分层的规则优先级高于所有分层规则**。件的表只写 `@layer utilities { … }`、自己
不声明层顺序，所以顺序得由先加载的令牌表来声明；而 Tailwind 的 `preflight.css` 是一份
**裸规则**（零 `@layer`），原样拼进去就是未分层的，会压过每一个件的工具类。

### 声明面与映射面必须拆成两个文件

{/* ref file="../packages/tokens/src/theme.reference.css" lines="1-14" */}

`theme(reference)` 只拦得住 `@theme` 块的输出，**拦不住普通规则**。把带 `:root { --background: … }`
的声明面一起引进件的构建里，每个件的表都会多出一整份 `:root`，跟页面上那张叠成两份真相。

拆开之后：映射让类名解析得出来（`bg-primary` → `var(--primary)`），值仍在运行时取页面那张
表的变量。实测验收件的产物里 `:root` 出现 **0 次**。

## 验收方法

### 量颜色要等过渡结束，否则读到的是中间值

shadcn 的 button 基础类里有 `transition-all`。切换 `.dark` 之后立刻 `getComputedStyle`，
读到的是过渡动画的中间色——第一次验收就这么被骗了一回：暗色 `--primary` 应该是
`oklch(0.92 …)`，读出来却是 `oklab(0.223 …)`，看着像「切换没生效」。

而 body 没有 transition，它当场就变对了——**两个元素的读数不一致正是这个坑的指纹**。
等 600ms 再读，四项颜色全部精确等于令牌表里声明的值。
