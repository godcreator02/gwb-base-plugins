## 2026-09-11 `plugins.install` 对已经装过的包也新建一条条目

来源：总控台（单元 `26090520ntn/console`，做块笔记那轮界面扩展点时撞上的）

`plugins.install { pkg, spec }` 眼下不看这个包在 home 里有没有条目，装完包就加一条。实跑里
拿它装一个件的开发版，结果 home 里出现了 `home:bn-comment` 与 `home:bn-comment-2` 两条，
同一个件挂了两遍，同名命令登记了两次。只能再调 `plugins.remove-entry` 收拾。

**好的那一半**：`spec` 给了准确版本时它装对了，装进来的就是那个版本。

**投来的建议**（最终怎么改是这个仓的事）：`install` 认一下「这个包已经有条目了」。有条目
就只升版本、不再建条目；或者不替调用方决定，回一句让调用方选。

**为什么现在提**：devkit 正在长一条「改一版看一版」的循环命令，链子是发开发版、装进隔离
home、停用再启用重挂、取证。那条链**有意绕开了 `plugins.install`**，走的是 `pnpm add` 加一条
已有条目，绕的正是这个重复建条目的行为。也就是说这个行为已经在实跑里逼出了一条绕路：装件
本来只该有一条路，现在开发循环那头得自己再走一条。

一手记录原在总控台周转区（2026-09-12 收件箱退役时随处理清掉）
主体投给了 devkit，这一条是抄送。

## 2026-09-14 带路径的 JSON 经 curl 必炸；稳法（body 落文件）没进 command-http 说明书

来源：总控台（第三轮 fresh-eyes 自举验收，功能题 gwb-timer）。

经门 `POST /run` 传含 Windows 路径的 JSON，bash 里 curl 的引号与反斜杠转义来回都不对：
双反斜杠被折一层、`printf` 落文件也折，回执只回 `bad json`，不指根因（正斜杠绕法
09-12 在 devkit 那边提过，本轮复验还在咬人，且对 devkit 的 scaffold 行不通——那条投给了
devkit）。本轮代理最后落定的稳法：**用写文件工具把 body 落成 JSON 文件（转义交给它），
再 `curl --data-binary @file`**，此后全程零踩坑。

**投来的建议**：command-http 说明书补一段「带路径/复杂参数的调用走 body 文件」，把这个
模式写成推荐姿势；`bad json` 的回执顺带点一句根因（反斜杠进 JSON 的坏转义），省得下一个
代理再猜。
