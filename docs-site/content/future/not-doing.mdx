# 刻意不做什么

下面每一条废弃的旧插件仓（`26090623hyz/gwb-plugins`）都有。这里没有，不是排期没排到，
是决定不做。写下来防一件事：一年之后有人看到某处「缺了个自动化」，顺手补上，然后同样的事再来十九次。

## 旧插件仓那几样，明确不要

旧插件仓只作参考，不是模板——查它遇到过的问题有用，结构、分层、包划分一概不照搬（为什么，见
[关键设计](/docs/design#刻意不做的事)）。明确不要的是这几样：

- **`gwb.minAppVersion` 与精确 peer 版本号的两处准入检查**——准入是安装时人判断的事，不是运行时核对
- **`platform` 分区与 `window.confirm` 拦截**——那个布尔值不带任何特权，弹窗文案里的「兜底页」
  是旧插件仓的概念
- **为某个具体插件写特殊分支**（`console` 特判、图标名列表这一类）——插件一律平等

## 做了又撤的

- **多桌面**（shell 0.0.14）：保活切换时出现过「无响应 / 疑似覆盖」，受控复测又复现不出，
  决定撤回，先做布局保存。重做的前提：先把切换语义与 `pane.instance` 的唯一性范围定下来。
  经过见[关键设计](/docs/design)；外壳插件现在在界面插件仓 gwb-ui-plugins，它的说明在那边的文档站
- **状态项机制**（gwb-status）：聚合的需求从没真正出现过，要给人看的插件各自画自己的窗格。哪天真要
  「一屏看全」，做一个聚合窗格的插件也不迟——加回来永远比拿掉容易

## 不属于「不做」的

阶段性或局部的小取舍不列在这里，免得两处都记：搬外壳与设置时的「明确不照搬」清单在
[路线](/future/roadmap)对应的那几节，插件自己的小取舍（日志搜索不做正则这类）在
[现状区](/docs)各插件自己的页里。
