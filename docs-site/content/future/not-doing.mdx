# 刻意不做什么

下面每一条母仓（`26090623hyz/gwb-plugins`，已退役）都有。这里没有，不是排期没排到，
是决定不做。写下来防一件事：一年之后有人看到某处「缺了个自动化」，顺手补上，再来十九次。

## 母仓那几样，明确不要

母仓那批是参考，不是模板——查坑值得，结构、分层、包划分一概不抄（为什么，见
[总览](/docs/overview#母仓那批是参考不是模板)）。明确不要的是这几样：

- **`gwb.minAppVersion` 与精确 peer 号的双份准入**——准入是装的时候人判的事，不是运行时核对
- **`platform` 分区与 `window.confirm` 拦截**——那个布尔不带任何特权，弹窗文案里的「兜底页」
  是母仓概念
- **为具体某个件写硬编码分支**（`console` 特判、图标花名册这一族）——件一律平等

## 做了又撤的

- **多桌面**（shell 0.0.14）：保活切换撞出「无响应 / 疑似覆盖」的现场，受控复测又复现不出，
  拍板撤回，先做布局落盘。重做的门槛：先把切换语义与 `pane.instance` 的唯一性范围钉死。
  现场见[定过的事](/docs/decisions)与[外壳](/docs/shell)那页
- **状态格机制**（gwb-status）：聚合的需求从没真到过，要给人看的件各画各的窗格。哪天真要
  「一屏看全」，做一个聚合窗格的件也不迟——加回来永远比拿掉容易

## 不属于「不做」的

阶段性或局部的小取舍不列在这儿，免得两处记账：搬外壳与设置时的「明确不抄」清单住在
[路线](/future/roadmap)对应的那几节，件自己的小不做（日志搜索不做正则这类）住在
[现状区](/docs)各件自己的页里。
