# 这条线去哪

**本页回答**：这个仓为什么存在、做到什么算成、现在处在哪个阶段。

工作台的机制面全部住件：内核只给一个小面（`ctx.gwbKernel` 三样、loader、`window.gwb`），
其余一切——命令总线、外壳、日志、设置、数据、说明书、主题、插件管理、MCP 桥、两条 CLI——
都是这个仓里的件。所以这个仓的加法判据跟内核的准入判据同源：**真遇到需求才加**，加一个件
是默认形态，加回来永远比拿掉容易。

## 件该长什么样

- **件是能单独拎出去建仓的东西**：构建线住在件里（自己的 esbuild 与 `@tailwindcss/cli`），
  仓根不共享构建脚本
- **界面各画各的窗格**，统一风格由令牌与围栏保证，不由组件源码一致保证
- **说明书随件走**：件自己挂 `SKILL.md` 目录，agent 经 mcp 读

## 当前阶段

十二件与两个共享包都已发上本机 registry、实机验通；样式围栏全仓一套（Tailwind 前缀方案）。
每个件到哪了、第二波做什么（settings 的界面半、shell 的导航），见[路线](/future/roadmap)；
已经明确不做的那些，连同各自的理由，见[刻意不做什么](/future/not-doing)。
