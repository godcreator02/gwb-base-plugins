## 组件：各拉各的

**这个仓里没有组件库，也没有 registry。** 每个件自己放一份 `components.json`，要什么组件就
`pnpm dlx shadcn@latest add <名>` 从 shadcn 官方拉。件之间的组件不需要一致——统一风格由令牌
保证，不由组件源码一致保证。

`plugins/hello` 是样板，**新件照它 0.2 那版抄**：`components.json`（`tailwind.css` 指自己那份
样式入口、`tailwind.prefix` 填件的**短名**）+ 两份 tsconfig 的 `paths` + `build.ts` 的 esbuild
`alias`，三处的 `@/` 都指 `src/client`；件自己的 devDependencies 里带上 `esbuild` 与
`@tailwindcss/cli`。**别去翻 0.1 那版**——那版没有样式入口、没有 `prefix`，构建走的是
2026-09-09 已经删掉的 `tools/build-styles.ts`，照着抄一行都跑不起来。

**`prefix` 那一条是新件最省事的一处**：填了它，CLI 拉下来的组件类名**自带前缀**，不用回头
逐个手改；`cn`（tailwind-merge）对带前缀的类合并本来就对，不用为它配任何东西。拉下来的
组件也**一个补丁都不用打**——前缀围栏不依赖 DOM 位置，portal 到 `body` 的弹层照样有样式。

**标记类也要带前缀。** `group` / `peer` 这一族是「一个类当锚、另一个类的变体去找它」，
而 `logger:group-hover:*` 编出来的选择器认的是**带前缀的** `.logger\:group`——锚那头写成
裸的 `group`，规则永远不命中，还不报错。手写这类搭配时两头一起带前缀，细节见
[撞过的墙](/docs/walls)。

## 剩下那部分要用的东西

**母仓那几条 dockview 工程细节，用掉三条，剩两条**：

| 细节 | 状态 | 为什么 |
| --- | --- | --- |
| 面板组件表必须是**模块级常量** | **已用** | 换引用会让 dockview 重建全部格 |
| 订 `onDidLayoutChange` | **已用**（「已开」与布局落盘都靠它） | 落盘订的就是这个事件 |
| 布局落盘 400ms 防抖 | **已用** | 一阵拖拽合并成一次写；整档重拼，迟到的定时器写不坏账 |
| 首帧门 | **不需要** | 数据在 `createRoot` 之前就取齐了（布局档也是），压根没有「还没到手」的那一帧 |
| 导航定宽 `constraints` **必须去重** | 待用 | 不去重的话 `setConstraints` 自己触发 `onDidLayoutChange` 无限递归、占死主线程 |
| 默认布局里 `setSize` 等第二格落位 | 待用 | 眼下不摆多列 |

状态栏欠的那两格（「重置布局」「布局没存上」）随布局落盘一起补上了——前者进了桌面
pill 的右键菜单（按桌面算），后者只在落盘失败时亮。

**`liveness` 的输入将来要换**。它现在按「条目表」判一格背后的件是 live / idle / gone，
而第三刀根本没接它——运行时注册已经隐含了「件活着」，注册表里没有的格本来就开不出来。
但**热卸一个件**时：件卸载 → effect 收尾 → 注册表摘掉那格 → **dockview 里那格还开着**。
那时要关掉它，判据的来源是**注册表变了**而不是条目表变了。第四刀真接它时按这个形状改。

**渲染层感知变化的现状**：boot 取一次注册表就完了，件后来挂上/卸掉界面不知道——
**手动出路已给**：状态栏「刷新」整页重跑，重取注册表。事件推送（件一变界面自己跟着变）
仍是将来的事，真需要再说。

**明确不抄**：老布局兼容（约 60 行 + 5 个双分支）、母仓插件名硬编码（`console` 特判、
六个图标名的花名册）、CDP 探针驱动面、状态栏里的母仓品牌、`void host` 那个半吊子契约
（参数里给了 host bridge 却改吃 `window.gwb`）。

**落盘那条已经解决了**：`gwb-data` 件先做出来了，shell 写 `inject: ['gwbData']` 就能
`ctx.gwbData.writeDoc('layout', …)`，不用自己拼路径、也不用碰 `fs`。原子落盘在那边兜着——
布局写到一半崩了不会毁掉上一份。

## 已接：mcp × skills 那道接口

旧账记的是「等真有 agent 连上来撞上一张命令名清单不够用再做」——**用户点名「把 skill
功能用起来」就是那个真实压力**，提前做的理由记在这里。接法照当初推的形状：

- `instructions` 点名此刻挂着的 skill（**唯一的发现面**——客户端不会自己去
  `resources/list`），每份一行名字 + 描述 + URI，正文一个字不放
- 正文挂成 `skill://gwb/<名>/<文件>` resources，读回调走 `ctx.gwbSkills.read`，
  读不到 throw（回 JSON-RPC 错误好过骗对面「说明书是空的」）
- mcp 那侧**局部注入** `gwbSkills`：没装 skills 件的 home 里桥照开，只是没有说明书那格
- 翻译层抽在 `plugins/mcp/src/skills.ts`（纯函数、有单测）；**没有加 skill 专用工具**——
  元工具还是 `gwb_cli_list` / `gwb_cli_run` 两件

照 hello 样板挂上说明书的一批：`commands` / `settings` / `plugins` / `node-cli` /
`py-cli` 各一份，讲的全是 agent 经命令总线真用得着的东西（信封、参数形状、两层结构、
回执字段）。

## 之后

**`gwb-settings` 的第二版**：node 半的设置读写[已经做完了](/docs/settings)，还欠两块。

**界面那半**——设置面板。`settings.all` 已经按界面要的形状交出去了（每行带
`scope`/`section`/`key` 与 title/type，外加一个 `live` 标着「此刻还有件声明它吗」），
窗格件照着排就行。

**插件启停/卸载**。母仓那 981 行里这半建立在 config 件的 `host.config.*` 之上，而**新内核
有 loader**，直接用 `ctx.loader` 的 `create`/`remove`/`update`，**热挂卸是白得的、不用重启**。
定过不用官方的 `plugin-loader-webui`（它硬 peer 一个 webui，而 webui 要 server），判据见
内核仓 decisions。

**动手前先看内核仓 walls 里那几条**：`update` 改 config 是**整个重挂**、而且 `inject` 它的
件跟着抖；写回 yml 会把用户手写的注释与空行全丢掉；没有文件监听；`remove` 疑似只认短 id；
`create` 不传 `parent` 落不了盘。**后三条是读源码得出的、没实机撞过**，真用之前各验一次。

**明确不抄**：`platform` 分区 + `window.confirm` 拦截（那个布尔不带任何特权，弹窗文案里的
「兜底页」是母仓概念）、`settings.data.list` 那个目录统计器（跟「设置」没必然关系）。

**要修的名不副实**：母仓那颗「卸载」按钮只摘 yml 条目、不碰 `node_modules`。要么接上真的
卸包，要么改叫「移出插件树」。
