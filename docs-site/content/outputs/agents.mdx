# gwb-base-plugins

**gwb 的无界面基础插件仓**：八个插件 commands、mcp、skills、settings、data、logger、node-cli、py-cli，
全部只依赖词汇表包（`@godcreator/gwb-plugin-api`）的类型。插件管理（plugin-manager，含找插件、配包源）在生命周期插件仓 gwb-lifecycle-plugins，
界面插件（shell、theme、baseui）在 gwb-ui-plugins，内核与词汇表包在 gwb-kernel，改它们去那些仓。
**这个仓的插件不依赖任何界面包**：构建产物里的包名 import 只能是 node 内置模块与 `cordis`。
仓根 `packages/shared-react`、`packages/tokens` 如果还在，是旧构建留下的未跟踪文件（没有 `package.json`），不是在用的包。

peer 里是内核包 `@godcreator/gwb-kernel-desktop`（八个插件都写）与 `cordis`（继承 cordis `Service` 的七个插件在构建产物里按值 import 它，MCP 插件不写）。
MCP SDK 与 zod 写 dev，由 MCP 插件的 `build.ts` 打包进构建产物。

## 动手之前

写插件、在隔离 home 里验证读 skill「gwb-devkit」，升版本号、发版读 skill「gwb-release」，写文档读 skill「docfirst-docs」。

## 检查

提交前 `pnpm check`（类型检查 + oxlint + vitest）。各插件的 `tests/artifact.test.ts` 检查构建产物：相对 import 带 `.js`、
包名 import 只有 node 内置模块与 `cordis`；没构建时整组跳过，改了代码先 `pnpm build` 再 `pnpm check`。
文档检查 `pnpm doc` 与 `pnpm doc:confirm <页…>` 的脚本在仓根。

## 旧插件仓只作参考，不是模板

旧插件仓 gwb-plugins 已删除，它的结构、分层、包划分一概不照搬。它遇到过、现在仍会出现的一个问题要避开：接口包声明成 `peerDependencies` 时 tsdown 会把它外置成包名 import——接口包要么声明进
importmap、要么强制打包进来，并配上构建产物检查。

## 文档地图

文档站在 `docs-site/`，端口 4315（`pnpm --filter gwb-base-plugins-docs-site dev`）。现状区：

- **入口页** `/docs`：接缝图，插件之间的十条接缝各有一页（`/docs/seams/…`）
- **八个插件页**：每页写功能、接口（各属于哪条接缝）、依赖、不做的事
- **关键设计** `/docs/design`、**开发** `/docs/develop`（构建、检查、各插件的测试、发版时包的顺序）、**遇到过的问题** `/docs/pitfalls`

这份 AGENTS.md 是生成物，正本是 `docs-site/content/outputs/agents.mdx`，改完在 `docs-site` 运行 `pnpm exec docfirst render`。
