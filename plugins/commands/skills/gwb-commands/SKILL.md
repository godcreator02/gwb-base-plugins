# 命令总线怎么用

这台工作台的能力面是一条**命令总线**：每个件把自己的能力登记成一条命令，你手里的两个
工具（`gwb_cli_list` / `gwb_cli_run`）就是这条总线的两个口。命令本身没有协议——handler
就是普通函数，参数和返回值由各命令自己定。

## 回执信封

每条命令的回执统一是这两种形状之一：

- 成了：`{ "ok": true, "data": … }`
- 没成：`{ "ok": false, "error": "原因" }`

**取值往 `data` 里再走一层。** 直接读顶层字段拿到的永远是 undefined。

## 失败的三种长相

1. **没有这条命令**——`ok: false`，error 说「没有这条命令：xxx」。多半是名字拼错了，
   或者那个件根本没装/没启用。回到 `gwb_cli_list` 对一遍
2. **参数不对**——命令自己校验参数，抛出来也被收成 `ok: false`。error 里写着它要什么形状
3. **业务上没成**——handler 干了活但结果失败（比如要装的包名不合规），一样 `ok: false`。
   这不是坏事：它把原因说清楚了，照着改参数重试就是

三种**都不是协议错误**，连接不断，把 error 读出来接着往下走。

## 两条查账的命令

- `gwb_cli_list` 回的每条命令带 `plugin` 字段——它是登记这条命令的件的名字。
  「这条命令是干嘛的」看 description，「这条命令归谁管」看 plugin
- `kernel.info` 是内核的自省口，不经过总线也调得到：回 home 目录、日志目录、
  每条条目的挂载状态（`ok` 字段）、谁是外壳。**件挂没挂上看它**，别猜

## 装了新件之后

命令注册表随装了哪些件而变：装一个新件、启用一条停用的条目，都可能多出一批命令。
**动过 `plugins.*` 之后重新 `gwb_cli_list` 一遍**，别凭上一次的清单干活。
