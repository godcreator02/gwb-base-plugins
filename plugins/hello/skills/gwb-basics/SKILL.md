# 在这台工作台上干活

god 工作台（gwb）是一台**本机**桌面工作台。它的本体（内核）只做四件事：起进程挂 cordis、
开一扇窗、把包装进 home、架一道桥。**一切功能皆插件**——你能调到的每一条命令，都来自某个
装在这个 home 里、并且此刻真挂着的件。

## 一个 home 就是一套独立的世界

home 是这台工作台的一套完整实例：装了哪些件、数据落在哪、开在哪个端口，各自分家。
你连上的是**其中一个**，不是全部。所以：

- 别假设别处看到的命令在这里也有
- 也别把这里的结论当成「这台机器上的工作台都这样」

## 怎么问

**先 `gwb_cli_list`，再 `gwb_cli_run`。** 顺序不能反——命令注册表随装了哪些件而变，
没有一张固定清单，凭记忆猜命令名的结果通常是「没有这条命令」。

`gwb_cli_run` 是万能口：拿到名字就能调，参数由命令自己校验。

## 三件要先知道的事

1. **命令失败不是协议错误**。命令不存在、参数不对，回的是 `isError` 的结果文本，
   连接不断——把原因读出来接着往下走，别当成连接挂了
2. **回执统一是 `{ ok, data }` 或 `{ ok, error }`** 这个信封。取值记得往 `data` 里再走一层，
   直接读顶层字段会拿到一片 undefined
3. **这道口是写口**。持 token 就能调完整的命令面，包括往 home 里装件。
   这台工作台的信任模型是「token 给谁 = 授权给谁」，别把它当只读接口

常见命令与它们回什么，见 `references/commands.md`——**要动手调之前再读那一份**，
不必上来就看。
